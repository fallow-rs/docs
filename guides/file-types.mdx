Your project has an HTML page, a Vue component or a stylesheet next to its TypeScript, and you want to know what fallow reports for these files. At the end of this guide, you can predict the findings for each file type, and you can correct a result that surprises you.

The question matters, because a tool that reads only `.ts` files sees no use of a file that only a stylesheet or a template uses. Fallow picks the parser for a file from its extension, with no plugin and no config. So a file that only an HTML page, a Vue template or a stylesheet uses is not unused.

## Before you start

- Read [Entry points and reachability](/concepts/entry-points): a file is used when an entry point reaches it.
- Install the dependencies. The plugins that make files such as `index.html` entry points turn on from `package.json`.

## Steps

### 1. Find the row of your file type

| File type | Extensions | What fallow reads | What fallow reports |
|:--|:--|:--|:--|
| JavaScript and TypeScript | `.js` `.jsx` `.mjs` `.cjs` `.ts` `.tsx` `.mts` `.cts` | Imports, exports, `require()`, dynamic imports, and JSDoc `import()` types | Each [dead code](/analysis/dead-code) issue type |
| Vue | `.vue` | Each `<script>` block, and the names that the `<template>` uses | Unused files and unused exports |
| Svelte | `.svelte` | Each `<script>` block, and the names that the markup uses | Unused files. No unused exports. |
| Astro | `.astro` | The frontmatter, and the client scripts in the body | Unused files and unused exports |
| MDX | `.mdx` | The `import` and `export` lines, and the names that the content uses | Unused files and unused exports |
| HTML | `.html` | `<script src>`, `<link rel="stylesheet">` and `<link rel="modulepreload">` | Unused files |
| CSS, Sass, Less | `.css` `.scss` `.sass` `.less` | `@import`, `@use`, `@forward`, Tailwind directives | Unused files. In a CSS module, unused classes. |
| GraphQL | `.graphql` `.gql` | Relative `#import` lines | Unused files |
| Glimmer | `.gjs` `.gts` | The script, and the names that each `<template>` uses | Unused files and unused exports |

Fallow does not analyze other files, for example `.json` and `.md` files. It never reports them as unused. An import of a `.json` file resolves like any other import.

### 2. Run fallow and read the findings

The table is easier to trust when you see it on real files. This example adds a Vite and Vue front end to the [demo project](/quickstart): `vite` and `vue` in `package.json`, a `dev` script that runs `vite`, an `index.html`, and these files under `src/web/`:

```text
index.html                          loads /src/web/main.ts and /src/web/styles/global.css
src/web/main.ts                     imports OrderCard.vue and graphql/orders.graphql
src/web/components/OrderCard.vue    uses formatDate and styles.root in its template
src/web/dates.ts                    exports formatDate and formatTime
src/web/styles/card.module.css      defines .root and .shadow
src/web/graphql/orders.graphql      #import "./order-fields"
src/web/graphql/order-fields.graphql
src/web/graphql/old-orders.graphql
src/web/OldBanner.svelte
```

```bash
npx fallow dead-code --unused-files --unused-exports
```

```text
  4 entry points detected (2 package.json, 2 plugin)

── Unused Code ─────────────────────────────────────

● Unused files (3)
  src/utils/legacy-currency.ts
  src/web/OldBanner.svelte
  src/web/graphql/old-orders.graphql
  Files not reachable from any entry point
  https://fallow.tools/docs/explanations/dead-code/#unused-files
  To suppress: // fallow-ignore-file unused-file

● Unused exports (5)
  src/lib/format.ts
    :3 formatPercent
  src/lib/index.ts
    :1 formatPercent (re-export)
  src/services/orders.ts
    :18 cancelOrder
  src/web/dates.ts
    :3 formatTime
  src/web/styles/card.module.css
    :3 shadow
  Exported symbols with no known consumers
  https://fallow.tools/docs/explanations/dead-code/#unused-exports
  To auto-fix: fallow fix --dry-run
  To suppress: // fallow-ignore-next-line unused-export

✗ 3 files · 5 exports (0.04s)
```

The findings in `src/utils/`, `src/lib/` and `src/services/` are the findings of the demo. The new findings come from the front end. Read them together with the files that are not in the list:

- `global.css` is used, because `index.html` loads it. The Vite plugin makes `index.html` an [entry point](/concepts/entry-points), so the entry point count goes from 3 to 4.
- `formatDate` is used, because the template of `OrderCard.vue` calls it. The script block alone does not use it.
- `.shadow` is an unused export of the CSS module. Fallow treats each class of a `.module.css` file as an export.
- `order-fields.graphql` is used through `#import "./order-fields"`. Fallow tries `.graphql` and `.gql` for a path without an extension.
- `OldBanner.svelte` and `old-orders.graphql` are unused files, because no file loads them.

### 3. Read the notes for your file type

The run above shows the common case of each file type. Each type also has rules that decide the edge cases, for example a Svelte prop or a path that starts with `/`.

#### Vue and Svelte {#vue-and-svelte}

Fallow parses `<script>` and `<script setup>`, also with `lang="ts"`. In the template, it counts component tags, directives and expressions as uses of the imported names. A name that only the template uses is therefore used, and that is why `formatDate` in the run above is not in the list. `<script setup>` can use an import of the plain `<script>` block, but not the reverse: [Vue and Svelte files](/frameworks/built-in#vue-and-svelte-files) has each rule.

A Svelte component declares its props as exports. Fallow cannot tell a prop from a helper export, so it does not report unused exports of a `.svelte` file. Put helpers in a `.ts` file, where fallow checks them.

#### Astro

Fallow parses the frontmatter between the two `---` lines as TypeScript. It also follows `<script src>` and the imports of inline `<script>` blocks, because Astro bundles them into the page. [Health](/analysis/health) scores the functions of inline scripts.

#### HTML

An HTML file is reachable only when an entry point or a plugin names it. The Vite and Parcel plugins make `index.html` an entry point. Fallow resolves a path that starts with `/` against the directory of the HTML file, then the nearest package directory, then the project root, then `public/`. In the demo, `index.html` is in the project root, so `/src/web/main.ts` resolves at the first step.

`fallow health` also reports the complexity of Angular templates: external `.html` templates and inline `template` strings. [Angular](/frameworks/built-in#angular) lists the constructs and the suppression comments.

Fallow reads the same tags in an `` html`...` `` tagged template in JavaScript and TypeScript, for example in a Hono layout. In JSX, `<script src>` is a string, so fallow does not follow it. [HTML in tagged templates](/frameworks/built-in#html-tagged-templates) has the limits.

#### CSS {#css}

Fallow reads the import rules and treats a CSS module class as an export. A class inside `:global(...)` is not an export, because the CSS module does not rename it. An `@apply` or `@tailwind` directive counts as a use of `tailwindcss`. A Tailwind `@plugin` directive counts as a use of its package or file. `composes: x from "./a.module.css"` is an import of the class `x`, and [CSS and Sass files](/frameworks/built-in#css-and-sass-files) gives the Sass rules. [Styling](/analysis/styling) covers the analysis of the classes themselves.

#### MDX and Markdown

Fallow adds the `import` and `export` lines of an `.mdx` file to the module graph. It does not read `.md` files, so it does not see the `<script setup>` of a VitePress page. A module that only a `.md` page imports is reported as unused. Add it to [`entry`](/reference/config-files#entry).

#### JSDoc in JavaScript

In a JavaScript file, fallow reads the `import()` types of `/** */` comments, for example `@param {import('./types').Config} cfg`. The type then counts as used. Fallow ignores `/* */` comments.

#### React Native {#react-native-platform-files}

The suffixes `.ios`, `.android`, `.native` and `.web` have a meaning only when the `react-native` or `expo` plugin is active:

| Import in the code | With the plugin | Without the plugin |
|:--|:--|:--|
| `./Button` | Each file of the set is reachable: `Button.tsx`, `Button.ios.tsx`, `Button.android.tsx`, `Button.native.tsx` and `Button.web.tsx`. | Only `Button.tsx` is reachable. The platform files are unused files. Without `Button.tsx`, the import is an unresolved import. |
| `./Button.ios` | Only `Button.ios.tsx` is reachable. | Only `Button.ios.tsx` is reachable. |

The `expo-router` plugin does not turn on platform files. An Expo Router app gets them through its `react-native` dependency.

## Check the result

Run `npx fallow dead-code` again after each change. A file that an HTML page, a template or a stylesheet uses is not in the list of unused files. To see which file keeps it in use, trace it:

```bash
npx fallow dead-code --trace-file src/web/styles/global.css
```

```text
  REACHABLE src/web/styles/global.css

  Imported by (1):
    -> index.html
```

## If it fails

When a result still surprises you, the cause is usually a file that no entry point names, or a use that fallow cannot read:

| Problem | Cause | Fix |
|:--|:--|:--|
| A file that an HTML page loads is unused. | No entry point or plugin names the HTML file. | Add the HTML file to [`entry`](/reference/config-files#entry). |
| An import that a template uses is unused. | The template uses the name in a way that fallow does not read, for example a computed component name. | [Trace the export](/guides/trace-a-finding), and [suppress it](/guides/suppress) when the use is real. |
| An unused helper in a `.svelte` file is not reported. | Fallow does not check the exports of Svelte files. | Move the helper to a `.ts` file. |
