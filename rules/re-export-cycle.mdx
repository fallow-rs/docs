## What it reports

Two or more barrel files re-export from each other in a loop.

[Architecture](/analysis/architecture) explains how fallow finds it.

## Why it matters

A barrel file re-exports from another barrel that ultimately re-exports back. When this happens, imports from any file in the loop may silently come up empty, because the re-export chain has no terminating module to resolve names against. To fix this: open any one file in the loop and remove the `export * from` (or `export { ... } from`) statement that points back into the cycle. Any single removal will break the cycle and restore working re-exports. A self-loop (a single barrel re-exporting from itself, often a rename leftover) is reported under the same rule with kind `self-loop`.

## When to keep the code

- An old project with hand-written barrel files can have loops that no code uses. Keep the rule at `warn` until you remove them, then set it to `error`.

## Notes

The finding belongs to a group of files, not to one line. Suppress it with `// fallow-ignore-file re-export-cycle` in one file of the loop. A rule in `overrides` has no effect on this issue type.
