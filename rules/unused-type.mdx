## What it reports

Type export is never imported.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

Type-only exports (interfaces, type aliases, enums used only as types) that are never imported. These do not generate runtime code but add maintenance burden.

## Example

`export interface LegacyProps` is exported, but no module imports the type.

```ts title="src/button.ts"
export interface ButtonProps {
  label: string;
}

export interface LegacyProps {
  text: string;
  color: string;
}

export const renderButton = (props: ButtonProps): string => `<button>${props.label}</button>`;
```

```ts title="src/index.ts"
import { renderButton } from "./button";

console.log(renderButton({ label: "Pay" }));
```

## Fix

Remove the type export, inline it, or keep it behind an explicit API entry point when consumers rely on it. With effect.schemaExportsAsTypes, this rule also reports unused Effect schema exports.

## When to keep the code

- A type that a package publishes for its users: put a `/** @public */` JSDoc tag on it, or add the entry file of the package to [`entry`](/reference/config-files#entry).

## Effect schemas

With [`effect.schemaExportsAsTypes`](/reference/config-dead-code#effect-schemaexportsastypes), this rule also reports an unused export of an Effect schema. fallow reads the syntax of the export and uses no type information. These exports are schemas:

- a class that extends a `Schema` class factory, such as `Schema.Class`;
- a const whose value is a `Schema` constructor, member or `pipe` chain;
- a re-export, an alias or a chain of a schema that the module imports;
- a const whose value is a call of a function that returns a schema;
- a conditional expression whose two branches are schemas (`flag ? Schema.String : Schema.Number`);
- a member of a namespace import, or a call of a function through one (`Helpers.User`, `Helpers.makeUser()`);
- a call of a function that returns one of its parameters, when the argument at that position is a schema (`identity(Schema.String)`);
- a member or a method call of a local `const` object or array literal (`schemas[0]`, `schemas.User`, `factories.make()`);
- a destructured export of such a member (`export const { User } = { User: Schema.String }`).

A `Schema` member counts when its declared return type is a schema in effect 3 or in effect 4. So a call of a lowercase member such as `Schema.optional(Schema.String)`, `Schema.optionalKey(...)` or `Schema.mutable(...)` is a schema. A read of a lowercase member without a call (`Schema.optional`) is a function, so it is not a schema. Decoders, encoders, guards, filters and annotation ids (`Schema.decodeUnknownSync(...)`, `Schema.is(...)`, `Schema.BrandSchemaId`) are not schemas.

```ts
import { Schema } from "effect";

const makeNamed = () => Schema.Struct({ name: Schema.String });

// A schema: fallow reports it as an unused type.
export const Named = makeNamed();

// A function: fallow reports it as an unused export.
export const makeRule = () => Schema.String;
```

The function can be in the same module or in a module that the export imports it from. It must be a function declaration, or a `const` with an arrow function or a function expression. These rules apply to the function:

- Each `return` must be a schema. A function with one `return` that is not a schema does not count.
- Each path of a block body must end in a `return` or a `throw`.
- A `return` can use a `const` schema from the top of the function body, and can go through `.pipe(...)` with `Schema` transforms.
- A `return` can call a second such function. fallow follows 4 functions at most.
- An `async` function and a generator do not count.
- A function that returns one of its parameters gives a schema only when each `return` is that same parameter, the function does not assign the parameter again, and no spread argument comes before it.

The export of the function itself stays an unused export when no module uses it.

A local object or array literal counts only when no code can change its members. The module must not export the literal. It must only read members that the literal has, or destructure it. A read of a key that the literal does not have (`schemas.shift()`, `schemas[5]`) also stops the check, because an array method can change the members. The module must not assign, update or delete a member, and it must not pass the literal itself to other code. The literal must have no spread, no computed key that is not a literal, and no `this`. A key must be a literal: `schemas[0]` and `schemas["User"]` count, `schemas[index]` does not.

Some forms need type information. An unused export of such a form stays an `unused-export` finding. [Effect schemas that the syntax does not prove](/guides/limits#effect-schemas-that-the-syntax-does-not-prove) lists them, with the fix.
