## What it reports

CSS or CSS-in-JS hardcoded styling value bypasses the design token system.

[Styling](/analysis/styling) explains how fallow finds it.

## Why it matters

A hardcoded value does not follow a change of the design token. A theme or brand update misses this place, and the interface becomes inconsistent.

## Example

Markup uses `class="w-[13px] bg-[#1a2b3c]"`, Tailwind arbitrary values, or a stylesheet sets `color: #1a2b3c` where the project has color tokens.

```css title="src/button.css"
.button {
  color: #1a2b3c;
}
```

```css title="src/theme.css"
:root {
  --color-brand: #1a2b3c;
}
```

## Fix

Replace the value with the nearest token of the scale. Keep the value when the one-off value is deliberate.

## When to keep the code

- A value that must differ from the scale on purpose. To leave out some Tailwind arbitrary values, set [`health.tailwindIgnorePatterns`](/reference/config-health#health-tailwindignorepatterns).
