## What it reports

An Angular @Output() / signal output() output is emitted nowhere in its own component.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

A parent can bind to an output that the component never emits. The handler of the parent never runs, and no error tells anyone.

## Example

user-card.component.ts declares @Output() close = new EventEmitter`<void>`() (or close = output`<void>`()) but `this.close.emit(...)` is called nowhere in the class.

```ts title="src/app.component.ts"
import { Component } from "@angular/core";
import { UserCardComponent } from "./user-card.component";

@Component({
  selector: "app-root",
  imports: [UserCardComponent],
  template: `<app-user-card (save)="onSave()" />`,
})
export class AppComponent {
  onSave(): void {
    console.log("user saved");
  }
}
```

```ts title="src/user-card.component.ts"
import { Component, EventEmitter, Output } from "@angular/core";

@Component({
  selector: "app-user-card",
  template: `<button (click)="save.emit()">Save</button>`,
})
export class UserCardComponent {
  @Output() save = new EventEmitter<void>();
  @Output() close = new EventEmitter<void>();
}
```

## Fix

Remove the unused output, or emit it from the class. If the output is part of a deliberately-stable public component API, suppress the line with // fallow-ignore-next-line unused-component-output.
