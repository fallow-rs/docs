## What it reports

Suppression comment or tag no longer matches any issue.

[Suppress a finding](/guides/suppress) explains how fallow finds it.

## Why it matters

The comment tells readers that a problem exists where none does. When a new issue of the same kind appears on that line, the old comment hides it from review.

## Example

`// fallow-ignore-next-line unused-export` stays above an export that another module imports, so no unused-export finding remains for the comment to suppress.

```ts title="src/index.ts"
import { formatPrice } from "./money";

console.log(formatPrice(1999));
```

```ts title="src/money.ts"
// Money helpers for the checkout.

// fallow-ignore-next-line unused-export
export const formatPrice = (cents: number): string => `${(cents / 100).toFixed(2)} EUR`;
```

## Fix

Remove the suppression. If a different issue is still intentional, replace it with a current, specific suppression.

## When to keep the code

- None. Remove the stale comment. A stale comment can hide a new finding at the same place later.

## Notes

- `/** @expected-unused */` marks an export that is unused on purpose. The tag becomes stale when code starts to use the export.
- When a comment names an unknown issue type, fallow still applies the known names of that comment, and reports the unknown name as stale. Correct the name.
