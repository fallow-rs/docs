## What it reports

The change adds a suppression comment.

[Changed code](/analysis/changed-code) explains how fallow finds it.

## Why it matters

`fallow audit` reports a comment line that the change adds with a lint, type-check, coverage or Fallow suppression: `eslint-disable`, `oxlint-disable`, `biome-ignore`, `deno-lint-ignore`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `istanbul ignore`, `c8 ignore`, `v8 ignore`, `fallow-override-threshold-next-line` or `fallow-ignore`. A moved comment is not added. A `fallow-ignore` comment that names only diff-risk rules does not count.

Files below a fixture or generated directory (`fixture`, `fixtures`, `__fixtures__`, `__snapshots__`, `generated`, `__generated__`) do not report, because a tool writes them or a test reads them as data. Defaults to `warn`.

## Example

A change adds `// @ts-expect-error` above a call instead of a correct type.

**Before the change**

```ts title="src/cart.ts"
const addItem = (cart: string[], sku: string): string[] => [...cart, sku];

export const cart = addItem([], "shirt");
```

**After the change**

```ts title="src/cart.ts"
const addItem = (cart: string[], sku: string): string[] => [...cart, sku];

// @ts-expect-error
export const cart = addItem([], 42);
```

## Fix

Decide if the suppression is necessary. If it is, keep it and suppress the finding with `// fallow-ignore-next-line added-suppression`, or turn the rule off for the path.
