## What it reports

The change adds a test-environment branch to source code.

[Changed code](/analysis/changed-code) explains how fallow finds it.

## Why it matters

The tests run a path that production never runs. A passing test then does not prove that the production path works.

## Example

A change adds `if (process.env.NODE_ENV === 'test') return cached;` to `src/pricing.ts`.

**Before the change**

```ts title="src/pricing.ts"
const loadPrices = (): Record<string, number> => ({ shirt: 20, socks: 5 });

export const priceOf = (sku: string): number => {
  const prices = loadPrices();
  return prices[sku] ?? 0;
};
```

**After the change**

```ts title="src/pricing.ts"
const cached: Record<string, number> = { shirt: 1, socks: 1 };

const loadPrices = (): Record<string, number> => {
  if (process.env.NODE_ENV === "test") return cached;
  return { shirt: 20, socks: 5 };
};

export const priceOf = (sku: string): number => {
  const prices = loadPrices();
  return prices[sku] ?? 0;
};
```

## Fix

Prefer a seam that tests can inject, such as a parameter or a module mock. If the branch is intended, suppress it with `// fallow-ignore-next-line test-only-branch`.
