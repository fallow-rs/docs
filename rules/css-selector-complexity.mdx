## What it reports

CSS selector, nesting, or important usage is structurally complex.

[Styling](/analysis/styling) explains how fallow finds it.

## Why it matters

A selector with high specificity or `!important` wins over later rules, so the next style change needs a stronger selector. A long descendant chain also breaks when the markup changes.

## Example

`.sidebar nav ul li a.active` sits four levels deep in nested SCSS, and its block uses `!important` on most declarations.

```scss title="src/sidebar.scss"
.sidebar {
  nav {
    ul {
      li {
        a.active {
          color: red !important;
          font-weight: bold !important;
          text-decoration: none !important;
        }
      }
    }
  }
}
```

## Fix

Flatten the nesting, put a class on the element instead of a long descendant chain, and remove `!important` where the order of the rules can do the work.

## When to keep the code

- A reset rule, an accessibility rule, or a rule that overrides markup of another library can need a strong selector.
