## What it reports

Catalog entry not referenced by any workspace package

[Dependencies](/analysis/dependencies) explains how fallow finds it.

## Why it matters

An entry in a package manager catalog (`pnpm-workspace.yaml` `catalog:` / `catalogs:` or Bun root `package.json` `workspaces.catalog` / `workspaces.catalogs`) that no workspace package.json dependency and no pnpm override (`pnpm-workspace.yaml` `overrides`, skipped when `packageManager` names a pnpm version that ignores it: pnpm before 10.5.1, or pnpm 10 or earlier when the root `package.json` declares non-empty `pnpm.overrides` or `resolutions`; root `package.json` `pnpm.overrides`, skipped when `packageManager` names pnpm 11 or later; root `package.json` `resolutions`, read only when `packageManager` names pnpm 10 or earlier) references via the `catalog:` protocol. Catalog entries are leftover dependency metadata once a package is removed from every consumer; delete the entry to keep the catalog truthful. See also: fallow/unresolved-catalog-reference (the inverse: consumer references a catalog that does not declare the package).

## Example

The catalog source declares `catalog: { is-even: ^1.0.0 }`, but no workspace package.json declares `"is-even": "catalog:"`.

## Fix

Delete the entry from the catalog source file. If any consumer uses a hardcoded version (surfaced in `hardcoded_consumers`), switch that consumer to `catalog:` first to keep versions aligned.

## When to keep the code

- When a workspace pattern names a directory that does not exist yet, for example a repository that CI clones there, fallow does not report catalog entries. Packages in that directory can use them.
