## What it reports

Class member is never referenced.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

Public class methods and properties that are never referenced, checked project-wide. Members marked `private` and `#private` members are not checked. Protected members have their own rule, `unused-protected-class-member`.

## Example

class Parser has a public parseLegacy method that is never called in the project.

## Fix

Remove or privatize the member. For reflection/framework lifecycle hooks, configure or suppress the intentional entry point.

## When to keep the code

- A framework calls the member at run time. Add its name to [`usedClassMembers`](/reference/config-dead-code#usedclassmembers).

## Notes

- The rule checks public members. A `private` member is not checked, and [Unused protected class members](/rules/unused-protected-class-member) checks `protected` members.
- A use through `this` inside the class counts as a use.
- Fallow does not report a member with a decorator, because a framework uses it at run time. A Lit `@state()` property is checked. To check members with some decorators, list those decorators in [`ignoreDecorators`](/reference/config-dead-code#ignoredecorators).
- Fallow does not report the lifecycle methods of React, Angular and custom elements. A [plugin](/concepts/plugins) can declare the lifecycle methods that its framework calls, and fallow counts them as used while the plugin is on. For example, the Ionic plugin (`@ionic/angular`) counts `ionViewWillEnter`, `ionViewDidEnter`, `ionViewWillLeave` and `ionViewDidLeave` as used. The [plugin source](https://github.com/fallow-rs/fallow/tree/main/crates/core/src/plugins) lists the names that each plugin knows.
- When the class extends another class, a call of the member in the parent class counts as a use of the override.
- When code gives an instance in a variable to `Object.keys`, `Object.values`, a rest pattern or `for...in`, fallow counts each member as used.
- A Playwright test that `test.extend<T>()` or `mergeTests(...).extend<T>()` makes from `@playwright/test` uses the members of each fixture class that the test reads.
