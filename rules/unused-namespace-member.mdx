## What it reports

Namespace member is never referenced.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

No code reads the member, but its export makes it look like an API that other code depends on. People keep it in step during refactors and do not dare to remove it.

## Example

`src/lib/legacy.ts` exports namespace Legacy with a member unusedInner that no file reads as Legacy.unusedInner.

```ts title="src/index.ts"
import { Legacy } from "./lib/legacy";

console.log(Legacy.formatOrderId(42));
```

```ts title="src/lib/legacy.ts"
export namespace Legacy {
  export function formatOrderId(id: number): string {
    return `ORD-${id}`;
  }

  export const unusedInner = "v1";
}
```

## Fix

Remove the unused member, or remove its export keyword when only the namespace body uses it. For generated code, turn the rule off for those files in overrides. Suppress an intentional member with // fallow-ignore-next-line unused-namespace-member.
