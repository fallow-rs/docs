## What it reports

A catchTag handler names a project error tag that no code produces.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

A `catchTag("X", ...)` or `catchTags({ X: ... })` handler where every project class with tag `X` is never constructed or failed with, and no object literal `_tag: "X"` or tagged constructor produces the tag. A tag that no project class declares can come from a package, so the rule abstains.

Effect built-in tags such as `TimeoutException` are never reported. The rule reports a handler only when no `unused-tagged-error` finding covers its classes: the error rule is off, or its finding is suppressed. Default warn.

The check runs only when the project declares `effect`.

## Example

main.ts calls Effect.catchTag("Expired", ...), the only class with tag Expired is never constructed, and the unused-tagged-error finding for it is suppressed.

```ts title="src/errors.ts"
import { Data } from "effect";

export class NotFound extends Data.TaggedError("NotFound")<{ readonly id: string }> {}

// fallow-ignore-next-line unused-tagged-error
export class Expired extends Data.TaggedError("Expired")<{}> {}
```

```ts title="src/main.ts"
import { Effect } from "effect";
import { NotFound, type Expired } from "./errors";

const loadCart = (id: string): Effect.Effect<number, NotFound | Expired> =>
  id === "" ? Effect.fail(new NotFound({ id })) : Effect.succeed(3);

const program = loadCart("cart-1").pipe(
  Effect.catchTag("NotFound", () => Effect.succeed(0)),
  Effect.catchTag("Expired", () => Effect.succeed(-1)),
);

Effect.runPromise(program);
```

## Fix

Remove the handler, or fail with the error where the condition occurs. If a package or code outside the project produces the tag, suppress the line with // fallow-ignore-next-line unproduced-catch-tag.
