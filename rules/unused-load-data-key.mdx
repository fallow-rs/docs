## What it reports

A SvelteKit load() or React Router / Remix loader return-object key is read by no consumer.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

The rule checks route data producers in SvelteKit, React Router and Remix. A SvelteKit route `load()` (in `+page.ts` / `+page.server.ts` and the `.js` variants) returns an object whose keys become the route's `data` prop. A React Router or Remix route module exports a `loader` (or `clientLoader`) whose returned keys reach the route component through `useLoaderData()`.

A returned key that no consumer reads is dead: it runs a real server-side fetch or database cost on every request for data that nothing renders. For SvelteKit, fallow credits the sibling `+page.svelte`'s `data.<key>` reads and project-wide `page.data.<key>` (Svelte 5 `$app/state`) or `$page.data.<key>` (Svelte 4 `$app/stores`) reads.

For React Router and Remix, fallow credits `useLoaderData()` reads and `loaderData.<key>` prop reads in the same route module.

The detector abstains on a spread, non-literal, multi-return, computed-key or wrapped producer, on a consumer that passes the whole `data` or loader data object on, on a `+page.server.ts` whose universal `+page.ts` sibling forwards its `data`, and project-wide for SvelteKit when any whole-object use of `page.data` / `$page.data` is seen.

It also skips a resource route (a route module with a `loader` and no default export component) and a `Response.json(...)` return, because an HTTP client reads that body, not a component. Default warn; delete the key or wire a consumer. A load fetch can have side effects, so there is no safe auto-fix.

The check runs only when the project declares `@sveltejs/kit`, `react-router`, `react-router-dom`, `@react-router/dev` or a `@remix-run/*` runtime package.

## Example

src/routes/blog/+page.ts returns \{ posts, draftCount \} but +page.svelte only reads data.posts and no component reads page.data.draftCount. In React Router, `app/routes/home.tsx` has a loader that returns \{ posts, draftCount \} but the route component only reads posts from useLoaderData().

```svelte title="src/routes/blog/+page.svelte"
<script lang="ts">
  let { data } = $props();
</script>

<ul>
  {#each data.posts as post}
    <li>{post.title}</li>
  {/each}
</ul>
```

```ts title="src/routes/blog/+page.ts"
import type { PageLoad } from "./$types";

export const load: PageLoad = async ({ fetch }) => {
  const posts: { title: string }[] = await (await fetch("/api/posts")).json();
  return {
    posts,
    draftCount: posts.length,
  };
};
```

## Fix

Delete the unused key from the load() or loader return (and skip its fetch), or wire a consumer (read data.`<key>` in +page.svelte, page.data.`<key>` in a shared component, or the key from useLoaderData() in the route component). If the fetch has a side effect you must keep, suppress the line with // fallow-ignore-next-line unused-load-data-key.
