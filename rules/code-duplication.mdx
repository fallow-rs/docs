## What it reports

Duplicated code block.

[Duplication](/analysis/duplication) explains how fallow finds it.

## Why it matters

A block of code that appears in multiple locations with identical or near-identical token sequences. Clone detection uses normalized token comparison, abstracting identifiers and literals in non-strict modes. Duplicated line counts and percentages include every instance, including the first. Overlapping line ranges in the same file count once. Redundant token counts exclude one retained copy per clone group. In `fallow audit`, the `introduced-clone-group` rule sets how a clone group takes part in the verdict: `warn` (the default) gives `warn`, `error` fails the audit, and `off` removes the group from the verdict. Under `--gate new-only`, only a group that the change introduced counts. Under `--gate all`, every clone group in the changed files counts. With `overrides`, the most severe result over the instance files applies. The `duplicates.threshold` gate is independent of the rule.

## Example

Two files contain the same normalized token sequence across a multi-line block.

## Fix

Extract the shared logic when the duplicated behavior should evolve together. Leave it duplicated when the similarity is accidental and likely to diverge. To keep one intended copy out of the report, suppress it with `// fallow-ignore-next-line code-duplication`. To make a new copy fail `fallow audit`, set the `introduced-clone-group` rule to `error`.
