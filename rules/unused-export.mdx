## What it reports

Export is never imported.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

Named exports that are never imported by any other module in the project. Includes both direct exports and re-exports through barrel files. The export may still be used locally within the same file.

## Example

`export const formatPrice = ...` exists in src/money.ts, but no module imports formatPrice.

## Fix

Remove the export or make it file-local. If it is public API, import it from an entry point or add an intentional suppression with context. To treat exported Effect schemas as type contracts, set effect.schemaExportsAsTypes: fallow then reports them as unused types.

## When to keep the code

- Public API of a library: code outside the project imports the export. Put a `/** @public */` JSDoc tag on the export (`@internal`, `@alpha` and `@beta` work too). Fallow does not report the exports of an entry file unless [`includeEntryExports`](/reference/config-files#includeentryexports) is on (a framework file that a [plugin](/concepts/plugins) knows, such as a Next.js page, is the exception: fallow checks its other exports always), so you can also add the entry file of the package to [`entry`](/reference/config-files#entry). For a library workspace in a monorepo, add its name to [`publicPackages`](/reference/config-files#publicpackages).
- A name that a framework reads by convention, such as `getStaticProps` of Next.js: the [plugin](/concepts/plugins) of the framework marks it as used. When no plugin covers it, add a rule to [`ignoreExports`](/reference/config-dead-code#ignoreexports).
- Dead code that you keep on purpose: mark it with `/** @expected-unused */`. Fallow then reports a [stale suppression](/rules/stale-suppression) when code starts to use it.
