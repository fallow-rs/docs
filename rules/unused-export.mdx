## What it reports

Export is never imported.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

An export that nothing imports looks like an API that other code depends on, so nobody dares to change or remove it. Code that only this export uses stays in the project with it.

## Example

`export const formatPrice = ...` exists in `src/money.ts`, but no module imports formatPrice.

```ts title="src/index.ts"
import { formatTotal } from "./money";

console.log(formatTotal(1999));
```

```ts title="src/money.ts"
export const formatTotal = (cents: number): string => `${(cents / 100).toFixed(2)} EUR`;

export const formatPrice = (cents: number): string => `EUR ${cents / 100}`;
```

## Fix

Remove the export or make it file-local. If it is public API, import it from an entry point or add an intentional suppression with context. To treat exported Effect schemas as type contracts, set effect.schemaExportsAsTypes: fallow then reports them as unused types.

## When to keep the code

- Public API of a library: code outside the project imports the export. Put a `/** @public */` JSDoc tag on the export (by default `@internal`, `@alpha` and `@beta` work too; the [`keepExportTags`](/configuration/suppression#jsdoc-visibility-tags) config key selects the tags). Fallow does not report the exports of an entry file unless [`includeEntryExports`](/reference/config-files#includeentryexports) is on (a framework file that a [plugin](/concepts/plugins) knows, such as a Next.js page, is the exception: fallow checks its other exports always), so you can also add the entry file of the package to [`entry`](/reference/config-files#entry). With `includeEntryExports` on, a name that an entry file re-exports with `export * from "./module"` needs an importer too: fallow reports an unused name at its declaration, and an [`ignoreExports`](/reference/config-dead-code#ignoreexports) rule for the entry file also covers the names behind its `export *` lines. A module that an entry file re-exports with `export * as Name from "./module"` is checked the same way: fallow reports each export that no consumer reads through `Name`, and a rule for the entry file that covers `Name` covers each export behind it. For a library workspace in a monorepo, add its name to [`publicPackages`](/reference/config-files#publicpackages).
- Shared test data in a fixture file, such as `test/fixtures/users.ts`: the Vitest, Jest and Playwright plugins make each file below `fixtures/` or `__fixtures__/` an entry point. When a file outside those directories imports a name from the fixture file, fallow checks the exports of the fixture file, and of each fixture file that it imports by name. The default export stays used, because a tool can load the file by its path. A fixture file keeps all its exports when no file imports a name from it (a test reads it as data), when a dynamic import, an import pattern or `require()` loads it, when only a side-effect import loads it, when its fixture directory has its own `package.json`, or when an `entry` pattern or another plugin rule also matches it. `fallow fix` does not remove an export below `fixtures/`, so remove it by hand or keep it with a suppression comment.
- A name that a framework reads by convention, such as `getStaticProps` of Next.js: the [plugin](/concepts/plugins) of the framework marks it as used. When no plugin covers it, add a rule to [`ignoreExports`](/reference/config-dead-code#ignoreexports).
- Dead code that you keep on purpose: mark it with `/** @expected-unused */`. Fallow then reports a [stale suppression](/rules/stale-suppression) when code starts to use it.
