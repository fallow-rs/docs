## What it reports

An Effect tagged error class is referenced only as a type or a catchTag string, and no code constructs or fails with it.

[Dead code](/analysis/dead-code) explains how fallow finds it.

## Why it matters

A class that extends `Data.TaggedError("X")` or `Schema.TaggedError<Self>()("X", ...)` that type positions or `catchTag("X")` handlers reference, but that no code reads as a value. Any value reference counts as a producer: `new X()`, `X.make`, `Schema.Union(X)`, an API or RPC error declaration that decodes the error at a boundary, or passing the class to a function. Only type positions and catch-tag strings do not count. A class with zero references is left to `unused-export`. The finding lists the `catchTag` handlers of the tag. Default warn. The check runs only when the project declares `effect`.

## Example

errors.ts declares class Expired extends Data.TaggedError("Expired"), signatures list it in the error channel and a handler calls catchTag("Expired"), but no code constructs Expired or fails with it.

## Fix

Fail with the error where the condition occurs, or remove the class, its type references and its catchTag handlers. If consumers outside the project construct or decode it, suppress the line with // fallow-ignore-next-line unused-tagged-error.
