The beacon records how often each function runs in production and sends those counts to Fallow Cloud. You use the counts to find hot paths and code that never runs.

In HTTP mode, the beacon sends nothing until you give it three values: an API key, a project id, and the Fallow Cloud endpoint.

## Browser setup

Install the beacon and a build instrumenter that is compatible with Istanbul:

```bash
npm install @fallow-cli/beacon
npm install --save-dev oxc-coverage-instrument
```

Add `oxc-coverage-instrument` to the production build so that it fills `window.__coverage__`. Then start the browser beacon from the application entrypoint:

```ts
import { createBrowserBeacon } from "@fallow-cli/beacon/browser";

const beacon = createBrowserBeacon({
  apiKey: import.meta.env.VITE_BEACON_API_KEY,
  endpoint: "https://api.fallow.cloud",
  projectId: "your-org/your-repo",
  commitSha: import.meta.env.VITE_GIT_SHA,
  coverageOrigin: "production",
});

beacon.start();
```

In browser code, use an ingest-only key with the prefix `fallow_pub_k1_`. This key can only call `POST /v1/ingest`. Never put a full `fallow_live_k1_` key in a browser bundle.

The first browser snapshot can contain only startup code, so the beacon skips it on purpose. To send data, do one of these:

- Go through at least one real workflow in the app.
- Wait for the 30-second flush.
- Hide the page, which starts a flush.

## Node setup

Node can read V8 coverage only when `NODE_V8_COVERAGE` is set before the process starts. The beacon cannot turn on V8 coverage after the process has started.

```bash
NODE_V8_COVERAGE=./coverage node dist/index.js
```

Start the beacon from server code after boot:

```ts
import { createNodeBeacon } from "@fallow-cli/beacon";

const beacon = createNodeBeacon({
  apiKey: process.env.BEACON_API_KEY,
  endpoint: "https://api.fallow.cloud",
  projectId: "your-org/your-repo",
  commitSha: process.env.GIT_SHA,
  coverageOrigin: "production",
});

beacon.start();
```

Use a full `fallow_live_k1_` key and keep it on the server. Bun and Deno need Istanbul instrumentation at build time, because their V8 capture is unavailable or incomplete.

## Verify the first ingest

The beacon logs nothing when an upload succeeds. To confirm that data arrives, check one of these signals:

1. `POST https://api.fallow.cloud/v1/ingest` returns `202 Accepted` in the browser network panel or server proxy logs.
2. The onboarding card at [fallow.cloud](https://fallow.cloud) changes to a repository row after aggregation.
3. The key's `last used` value updates under Settings, API keys.

Fallow Cloud processes an accepted ingest asynchronously. Expect a short delay between the `202` response and the repository row.

## If the dashboard stays empty

Check these in order:

1. `endpoint` is exactly `https://api.fallow.cloud`.
2. Browser code uses an ingest-only key. Server code uses a full key.
3. The configured environment variable exists in the production build or process.
4. `projectId` is stable and different for each repository or service.
5. Browser builds contain Istanbul counters, or Node started with `NODE_V8_COVERAGE`.
6. The app exercised real routes or jobs after the beacon started.
7. The first `/v1/ingest` response is `202`, not `401`, `403`, `402`, `413`, or `429`.

When no coverage source is available, the beacon emits one `onRuntimeMismatch` error that tells you what to fix, and then stops. Fix that error before you wait for another batch.

## Add static inventory

Runtime capture tells Fallow Cloud only what V8 or Istanbul observed. To see the functions that were never tracked, upload the static inventory in CI. Fallow Cloud then shows them as `untracked`:

```bash
fallow coverage upload-inventory --api-key "$FALLOW_KEY"
```

For bundled or minified code, also upload source maps from CI. [`fallow coverage`](/cli/coverage) documents the inventory and source-map commands.

## Privacy

The beacon sends function paths, names, positions, hit counts, project metadata, and delivery reports. It does not send arguments, request bodies, environment variables, or source code. The [network activity disclosure](https://fallow.cloud/coverage/network-activity) lists everything the beacon sends.
