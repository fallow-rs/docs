Fallow telemetry is off by default. When you turn it on, fallow sends one small event for each analysis run. The events help the maintainers improve the agent, CI, JSON, MCP and editor workflows. [`fallow telemetry`](/cli/telemetry) has the commands and the environment variables.

To keep telemetry off on each machine and in CI, set `FALLOW_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1`.

## You do not have to trust the list {#inspect-what-is-sent}

To print the exact payload of a real command without a send, run:

```bash
FALLOW_TELEMETRY=inspect npx fallow dead-code --format json --quiet
```

Fallow prints the payload to stderr. The normal output of the command does not change. To print an example event that shows each field, run `fallow telemetry inspect --example`.

## What fallow never sends {#what-is-never-collected}

- Names of repositories, organizations, projects, branches or git remotes.
- File paths, import specifiers, source code or stack traces.
- Names of packages, dependencies, workspaces or frameworks.
- Command-line arguments.
- Config contents or config values.
- Names or values of environment variables.
- Error text, logs or exceptions.
- Exact counts of results, files or functions.
- Identifiers of a machine, a user, a project or a repository.

Fallow does not send a hash of these values either.

The one exception is an anonymous install token. With it, the dashboards count workflows for each install, not for each run:

- It is a random value. Fallow does not make it from your machine, account, repository, files or environment.
- Fallow creates it only when you turn telemetry on, with `fallow telemetry enable` or the first send after `FALLOW_TELEMETRY=on`.
- `fallow telemetry disable` deletes it.
- Fallow sends it only in the HTTP header `X-Fallow-Install`, never in the event.
- `fallow telemetry status` tells only if the token exists. It never shows the token.

## What fallow sends {#what-is-collected}

A successful run gives a `workflow_completed` event. A failed run gives a `workflow_failed` event. This is the output of `fallow telemetry inspect --example`:

```json
{
  "schema_version": 2,
  "event": "workflow_completed",
  "fallow_version": "3.44.0",
  "workflow": "audit",
  "integration_surface": "mcp",
  "invocation_context": "agent",
  "agent_source": "codex",
  "output_format": "json",
  "quiet": true,
  "ci": false,
  "tty": false,
  "os": "macos",
  "arch": "aarch64",
  "duration_bucket_ms": "500-2000",
  "outcome": "issues_found",
  "exit_code_bucket": "1",
  "run_scope": "changed_only",
  "config_shape": "custom_rules",
  "output_destination": "stdout",
  "analysis_mode": "static",
  "file_count_bucket": "500-1999",
  "function_count_bucket": "1000-9999",
  "avg_fan_out_bucket": "1-2",
  "findings_present": true,
  "result_count_bucket": "1-9",
  "report_truncated": true,
  "truncation_reason": "comment_limit",
  "cache_state": "warm",
  "mcp_tool": "find_dupes",
  "has_parent_run": true,
  "run_role": "followup",
  "followup_kind": "audit"
}
```

Fallow leaves out a field that does not apply to the run. For example, `agent_source` is only in an event of a run that an agent started, and `failure_reason` is only in a `workflow_failed` event.

| Field | Values and purpose |
|:--|:--|
| `workflow` | The command family, such as `audit`, `dead_code` or `health`. Shows which workflows to improve first. |
| `integration_surface` | CLI, CLI JSON, MCP, CI, editor or library. |
| `invocation_context` | A person, CI, an editor or an agent. |
| `agent_source` | One value of the agent list below. |
| `output_format`, `quiet` | The output format and the quiet flag, to protect the most used output contracts. |
| `ci`, `tty`, `os`, `arch` | The environment class. |
| `duration_bucket_ms` | A range of time, never the exact time. |
| `outcome`, `exit_code_bucket` | Clean, findings or failure. |
| `failure_reason` | One of `validation`, `unsupported_format`, `config`, `analysis`, `diff`, `network`, `auth`, `gate`, `signal` or `unknown`. Fallow does not read the error text for it. |
| `run_scope` | `full_project`, `changed_only`, `workspace_scoped`, `file_scoped` or `unknown`. |
| `config_shape` | `default`, `custom_config`, `custom_rules`, `plugins_enabled` or `unknown`. |
| `output_destination` | `stdout`, `file`, `ci_comment` or `unknown`. |
| `analysis_mode` | `static`, `runtime_coverage`, `production_coverage`, `security`, `similar_code`, `fix` or `unknown`. |
| `file_count_bucket`, `function_count_bucket`, `avg_fan_out_bucket` | A range for the size of the project, from counts that the run already has. |
| `findings_present`, `result_count_bucket` | If the run found something, and a range: `0`, `1-9`, `10-99`, `100+` or `unknown`. |
| `report_truncated`, `truncation_reason` | If fallow cut a report or a comment, and why: `comment_limit`, `max_items`, `size_limit` or `unknown`. |
| `cache_state` | `cold`, `warm`, `partial` or `unknown`. |
| `mcp_tool` | The MCP tool, from a fixed list of tool names. |
| `has_parent_run`, `run_role`, `followup_kind` | If a run follows an earlier run of an agent, and of which kind. The event never holds the link token. |

A follow-up run can also send a cleaned link token in the HTTP header `X-Fallow-Parent-Run`, never in the event. When fallow changes the fields, `schema_version` changes.

Telemetry comes only from the CLI. The language server, the editor extension and the Node.js bindings send no telemetry. When the MCP server starts the CLI, the event of that run counts for the MCP tool.

## Agent source {#agent-source}

When an agent starts a run, fallow can send one `agent_source` value from this list:

```text
none codex claude_code cursor copilot opencode aider roo
windsurf gemini cline continue zed goose other_known unknown
```

Fallow never sends `none`: it is the value before fallow classifies a run. An agent that is not on the list is `other_known`. Fallow changes aliases to the listed value, for example `claude-code` to `claude_code`, and `gemini_cli` and `antigravity` to `gemini`.

Fallow does not send the MCP client info, process names, editor or extension names, model names, account IDs, prompts or version strings of an agent.

A wrapper around an agent can set `FALLOW_AGENT_SOURCE` to one value of the list. Fallow ignores a value that is not on the list. `FALLOW_AGENT_SOURCE` does not turn telemetry on.

## Transport {#transport-and-server-privacy}

- Fallow sends an HTTPS POST with a JSON body to `https://api.fallow.cloud/v1/telemetry/events`. `FALLOW_API_URL` changes the host.
- The request has no cookies and no authentication token.
- At the end of a run, fallow writes the event to the local file `telemetry-spool.jsonl`, next to the telemetry config. The next run with telemetry on sends the saved events in the background. Your command does not wait for it.
- The file keeps the 64 newest events. A machine that stays offline loses its oldest events, so the counts are a rough sample.
- A network error never changes the output or the exit code. Fallow never writes telemetry to stdout.
- The server does not add customer, repository, organization, git, registry or license data to the events. It removes or shortens IP addresses as early as possible, and deletes raw events after a short time.

## Turn telemetry off everywhere {#disabling-everywhere}

`DO_NOT_TRACK` and `FALLOW_TELEMETRY_DISABLED` have the highest precedence. When one of them is set, telemetry stays off, and `fallow telemetry enable` refuses to turn it on. In CI, telemetry is off unless `FALLOW_TELEMETRY` is set in that CI environment. A local `fallow telemetry enable` does not turn it on in CI.
