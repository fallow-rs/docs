Fallow telemetry is **opt-in** and **off by default**. This page lists what fallow sends when you turn it on, and what it never sends. The data helps improve agent, CI, JSON, MCP, and editor workflows. Fallow does not use it to track individuals or codebases. For the commands and environment controls, see [`fallow telemetry`](/cli/telemetry).

To keep telemetry off everywhere, set `FALLOW_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1`. See [Disabling everywhere](#disabling-everywhere).

## What is never collected

Fallow telemetry never includes:

- repository, organization, project, branch, or git remote names
- file paths, import specifiers, source snippets, or stack traces
- package, dependency, workspace, or framework package names
- raw command-line arguments
- config contents or config values
- environment variable names or values
- raw errors, logs, or serialized exceptions
- machine, user, project, or repository identifiers

Fallow does not send hashed versions of these values either.

The one exception is an anonymous install grouping token. With this token, aggregate dashboards can count distinct workflows per install instead of per run. The token has these properties:

- It is a new random value. Fallow never derives it from your machine, user account, repository, project, file paths, or environment.
- Fallow creates it only when you explicitly opt in: `fallow telemetry enable`, or the first upload after `FALLOW_TELEMETRY=on`.
- `fallow telemetry disable` deletes it.
- Fallow sends it only as a private transport header (`X-Fallow-Install`) for server-side grouping. It is never a field inside the event.
- `fallow telemetry status` reports only whether the token is present. It never shows the token.

## Inspect what is sent

You do not have to trust the list. To print the exact payload that a real command would send, without sending it, run:

```bash
FALLOW_TELEMETRY=inspect fallow audit --format json --quiet
```

Fallow prints the payload to stderr. The normal output of your command does not change.

## What is collected

When you enable telemetry, fallow sends one small, high-level event per analysis run:

```json
{
  "schema_version": 1,
  "event": "workflow_completed",
  "fallow_version": "3.28.0",
  "workflow": "audit",
  "integration_surface": "mcp",
  "invocation_context": "agent",
  "agent_source": "codex",
  "output_format": "json",
  "quiet": true,
  "ci": false,
  "tty": false,
  "os": "linux",
  "arch": "x86_64",
  "duration_bucket_ms": "500-2000",
  "outcome": "issues_found",
  "exit_code_bucket": "1",
  "findings_present": true,
  "mcp_tool": "find_dupes",
  "parent_run": "tmp_8x7p4k"
}
```

Four fields are optional:

- `agent_source` appears only on agent-driven runs.
- `findings_present` is omitted by commands that run no analysis, and by older binaries.
- `mcp_tool` appears only when a run came through the MCP server.
- `parent_run` appears only when a run is explicitly correlated to a previous one.

In all other cases, fallow omits these fields.

| Field | Purpose |
|:------|:--------|
| `workflow` | Prioritize the audit, dead-code, health, duplication, CI, runtime-coverage setup, impact, security, fix, and explain workflows. |
| `integration_surface` | Show whether you use fallow through human CLI, CLI JSON, MCP, CI, editor, or as a library. |
| `invocation_context` | Separate human, CI, editor, and agent-driven use without uploading detection evidence. |
| `agent_source` | Improve compatibility with specific agent integrations. Values come from a documented allowlist. |
| `output_format` / `quiet` | Protect the output contracts that users and agents rely on most. |
| `duration_bucket_ms` | Find slow workflow classes without collecting exact timings. |
| `outcome` / `exit_code_bucket` | Measure clean runs, findings, and failures without uploading raw error text. |
| `findings_present` | Whether the analysis found any issues, independent of the exit code. This makes informational analyses measurable, such as default-config `dupes`, which never exits non-zero. |
| `mcp_tool` | Attribute MCP usage to a specific tool, from a fixed allowlist of tool names. |
| `parent_run` | Link explicit agent follow-up runs with a short allowlisted token. It is never a path or a free-form string. |

When fallow runs through the MCP server, the server tags the CLI process that it starts. The one event from that run then counts toward the `mcp` surface and the specific tool, instead of a plain `cli_json` run. Code Mode snippets can make several read-only host calls. Fallow attributes the CLI events from those calls to `code_execute`, not to free-form code text or nested helper names. This tagging sends no extra event and does not change what fallow collects.

The LSP server, editor extension, and library embeddings run in-process and currently emit no telemetry.

The `schema_version` field increments if the collected fields change. The fallow team updates this page before any new field ships.

## Agent source

When telemetry is enabled and fallow classifies a run as agent-driven, fallow may send one normalized `agent_source` value from a fixed allowlist:

```text
none codex claude_code cursor copilot opencode aider roo
windsurf gemini cline continue zed goose other_known unknown
```

Fallow never sends `none`. It is the internal default before fallow classifies a run, and fallow sends `agent_source` only for agent-driven runs. Fallow groups agents that are not on the list, for example enterprise IDE assistants, under `other_known`. Fallow also normalizes aliases: hyphen aliases such as `claude-code`, and CLI aliases such as `gemini_cli` and `antigravity` (both map to `gemini`).

Fallow does not upload any of these:

- raw MCP client info
- process names or parent process paths
- editor or extension identifiers
- environment variable names
- model names
- account or organization IDs
- prompts
- versions
- free-form vendor strings

If you write an agent wrapper, set `FALLOW_AGENT_SOURCE=<allowlisted-value>`. An ambiguous source sends `unknown`. **Setting `FALLOW_AGENT_SOURCE` never enables telemetry by itself and uploads no codebase content.** When more than one agent environment is present, attribution is best-effort and can depend on check order. To name the agent yourself, set `FALLOW_AGENT_SOURCE`.

## Transport and server privacy

- Fallow sends each request as an HTTPS POST with a JSON body to `https://api.fallow.cloud/v1/telemetry/events` (override the host with `FALLOW_API_URL`)
- Fallow uses no cookies and sends no authentication token
- The upload runs on a background thread and does not slow down your command
- Fallow does not wait for the upload, so the fastest runs and runs on slow networks often drop their event. The counts are a rough, biased sample, not an exact usage count
- Fallow ignores network errors, and they never affect command output or the exit code
- Fallow never writes telemetry to stdout
- The server does not add customer, repository, organization, git, package-registry, or license data to telemetry
- The server drops or truncates IP addresses as early as practical
- The server keeps raw events for a short window only, then deletes them

Public reporting uses only coarse aggregate trends after privacy review.

## Disabling everywhere

The `DO_NOT_TRACK` and `FALLOW_TELEMETRY_DISABLED` environment variables are kill switches with top precedence. When either is truthy, telemetry stays off and fallow refuses `fallow telemetry enable`. In managed and CI environments, use `FALLOW_TELEMETRY_DISABLED=1` as the fleet-wide switch.
