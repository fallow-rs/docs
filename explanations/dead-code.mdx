This page lists the issue types of `fallow dead-code` and `fallow architecture`. Each section tells in a few sentences what a finding means and what to do. Each section links to the rule page of the issue type, which has an example, the fix and the facts: the default severity, the config key and the suppression comment.

To learn how fallow decides that code is unused, read [Dead code](/analysis/dead-code). Before you remove code, check the finding with [`fallow dead-code --trace`](/guides/trace-a-finding).

## Files and exports {#files-and-exports}

### Unused files {#unused-files}

No [entry point](/concepts/entry-points) reaches the file. No reachable file imports it, and no plugin or `entry` pattern names it. Delete the file. When a tool or a script loads the file without an import, tell fallow about that loader.

Full reference: [Unused files](/rules/unused-file)

### Unused exports {#unused-exports}

A reachable file exports a name, and no other file imports it. Remove the export, or remove the `export` keyword when the file uses the name itself. When code outside the project imports the name, mark it as public API.

Full reference: [Unused exports](/rules/unused-export)

### Unused types {#unused-types}

A type alias or an interface is exported, and no file uses it. Remove the type, or remove its `export` keyword. Keep it when a package publishes it for its users.

Full reference: [Unused types](/rules/unused-type)

### Private type leaks {#private-type-leaks}

An exported function, class or value has a signature that uses a type of the same file, and that type is not exported. Users of the export cannot name the type. Export the type, or change the signature. This check is off by default.

Full reference: [Private type leaks](/rules/private-type-leak)

### Deprecated exports in use {#deprecated-exports-in-use}

An export has a `@deprecated` JSDoc tag, and reachable files still use it. The finding lists these files. Move each one to the replacement API, then remove the export. This check is off by default.

Full reference: [Deprecated exports in use](/rules/deprecated-export-in-use)

### Duplicate exports {#duplicate-exports}

Two or more files export the same name. An auto-import can then pick the wrong file. Keep one export of the name, and import it from that file in all other places.

Full reference: [Duplicate exports](/rules/duplicate-export)

### Duplicate export aliases {#duplicate-export-aliases}

One file exports one value under two or more names, for example `export { a, a as b }`. Keep one name, and change the imports of the other names.

Full reference: [Duplicate export aliases](/rules/duplicate-export-alias)

### Unresolved imports {#unresolved-imports}

Fallow cannot find the file or the package of an import. The code probably fails when it runs. Correct the path, install the package, or add the path alias to `tsconfig.json`.

Full reference: [Unresolved imports](/rules/unresolved-import)

## Members {#members}

### Unused enum members {#unused-enum-members}

No code uses a member of an enum. Remove the member. Keep it when stored data or another system still sends its value.

Full reference: [Unused enum members](/rules/unused-enum-member)

### Unused class members {#unused-class-members}

No code outside the class uses a public method or property of the class. Remove the member, or make it `private`. A member that a framework calls at run time can be a false positive: tell fallow about it.

Full reference: [Unused class members](/rules/unused-class-member)

### Unused protected class members {#unused-protected-class-members}

The class and its subclasses never read a `protected` member. Remove the member, or make it `private`. This check is off by default.

Full reference: [Unused protected class members](/rules/unused-protected-class-member)

### Unused namespace members {#unused-namespace-members}

No code reads a member of an exported TypeScript namespace. Remove the member, or remove its `export` keyword when only the namespace uses it.

Full reference: [Unused namespace members](/rules/unused-namespace-member)

### Unused store members {#unused-store-members}

No code reads a `state` key, a getter or an action of a Pinia store. Remove the member. Suppress the finding when a Pinia plugin or a dynamic call uses the member.

Full reference: [Unused store members](/rules/unused-store-member)

## Dependencies {#dependencies}

[Dependencies](/analysis/dependencies) explains how fallow compares `package.json` with the imports.

### Unused dependencies {#unused-dependencies}

A package in `dependencies` has no import, and no `package.json` script runs it. Remove it from `package.json`. When another workspace imports it, move it to that workspace.

Full reference: [Unused dependencies](/rules/unused-dependency)

### Unused devDependencies {#unused-devdependencies}

A package in `devDependencies` has no import, and no script or tool config uses it. Remove it from `package.json`.

Full reference: [Unused devDependencies](/rules/unused-dev-dependency)

### Unused optionalDependencies {#unused-optionaldependencies}

A package in `optionalDependencies` has no import. Make sure that no supported platform needs it, then remove it.

Full reference: [Unused optionalDependencies](/rules/unused-optional-dependency)

### Type-only dependencies {#type-only-dependencies}

A package in `dependencies` has only `import type` imports, so it never loads at run time. Move it to `devDependencies`. Fallow reports this issue type only in [production mode](/concepts/production-mode).

Full reference: [Type-only dependencies](/rules/type-only-dependency)

### Test-only dependencies {#test-only-dependencies}

Only test files import a package in `dependencies`. Move it to `devDependencies`. Fallow does not report this issue type in production mode, because that mode leaves out the test files.

Full reference: [Test-only dependencies](/rules/test-only-dependency)

### Dev dependencies in production {#dev-dependencies-in-production}

Production code imports a package of `devDependencies` as a value. An install without dev packages, such as `npm install --omit=dev`, then breaks that import. Move the package to `dependencies`, unless your build puts the package into its output.

Full reference: [Dev dependencies used in production](/rules/dev-dependency-in-production)

### Unlisted dependencies {#unlisted-dependencies}

Code imports a package that its `package.json` does not declare. The import can work through a package that another workspace installs, and fail in a clean install. Declare the package in the `package.json` that owns the file.

Full reference: [Unlisted dependencies](/rules/unlisted-dependency)

### Unlisted binaries {#unlisted-binaries}

A `package.json` script or a process call runs a command, and no installed or declared package supplies it. Add the package to `devDependencies`. When the operating system or the CI image supplies the command, add its name to `ignoreBinaries`.

Full reference: [Unlisted binaries](/rules/unlisted-binary)

## Catalogs and overrides {#catalogs-and-overrides}

### Unused catalog entries {#unused-catalog-entries}

A package in a catalog of `pnpm-workspace.yaml` (or of a Bun root `package.json`) has no `catalog:` reference. Remove the entry. When a workspace pins the package with a version, change it to `catalog:` first.

Full reference: [Unused catalog entries](/rules/unused-catalog-entry)

### Empty catalog groups {#empty-catalog-groups}

A named group under `catalogs:` has no packages. Remove the group.

Full reference: [Empty catalog groups](/rules/empty-catalog-group)

### Unresolved catalog references {#unresolved-catalog-references}

A `package.json` uses `catalog:` or `catalog:<name>` for a package, and that catalog does not declare the package. The install fails. Add the package to the catalog, use another catalog, or pin a version.

Full reference: [Unresolved catalog references](/rules/unresolved-catalog-reference)

### Dependency overrides {#pnpm-dependency-overrides}

Fallow checks the override entries of pnpm, npm and Bun. Two issue types report problems with them.

#### Unused dependency overrides {#unused-dependency-overrides}

An override targets a package that no workspace declares and the lockfile does not hold. Remove the override. When it pins a version of a package that the lockfile holds, fallow does not report it.

Full reference: [Unused dependency overrides](/rules/unused-dependency-override)

#### Misconfigured dependency overrides {#misconfigured-dependency-overrides}

The key or the value of an override is not valid for the package manager, for example an empty value. Correct the entry, or remove it.

Full reference: [Misconfigured dependency overrides](/rules/misconfigured-dependency-override)

#### Override sources and the pnpm version {#pnpm-override-sources}

Each pnpm version reads other override sources. Fallow reads the pnpm version from the `packageManager` field of the root `package.json`. Fallow checks only the sources that this version reads. This applies to the override checks and to the catalog checks.

| Source | Fallow skips it for |
|:--|:--|
| `overrides` in `pnpm-workspace.yaml` | pnpm before 10.5.1. Also pnpm 10 or earlier when the root `package.json` declares `pnpm.overrides` or `resolutions`. |
| `pnpm.overrides` in the root `package.json` | pnpm 11 and later. |
| `resolutions` in the root `package.json` (catalog checks) | pnpm 11 and later, and a project without a pnpm version. |

When fallow skips the `overrides` of `pnpm-workspace.yaml`, it records the `pnpm-workspace-overrides-ignored` workspace diagnostic. pnpm itself prints no warning for this case.

## Architecture {#architecture}

[`fallow architecture`](/cli/architecture) reports these issue types. [Architecture](/analysis/architecture) explains them.

### Circular dependencies {#circular-dependencies}

Files import each other in a loop, directly or through other files. A file in the loop can then read a value before the value exists. Move the shared code to a new file, or reverse one import. Fallow does not report a loop of `import type` imports.

Full reference: [Circular dependencies](/rules/circular-dependency)

### Re-export cycles {#re-export-cycles}

Barrel files re-export from each other in a loop, or one barrel file re-exports from itself. No file in the loop declares the names, so an import from the loop gets nothing. Remove one `export ... from` statement of the loop.

Full reference: [Re-export cycles](/rules/re-export-cycle)

### Package cycles {#package-cycles}

The [workspaces](/concepts/workspaces) of a monorepo import each other in a loop. A build tool then cannot build them in order. Move the shared code to a package that both import, or reverse the imports of one step.

Full reference: [Package cycles](/rules/package-cycle)

### Boundary violations {#boundary-violations}

A file imports a file of a zone that your `boundaries` config does not allow. Change the import. When the import is correct, change the boundary rules.

Full reference: [Boundary violations](/rules/boundary-violation)

### Policy violations {#policy-violations}

A call, an import or an export breaks a rule of a rule pack in your `rulePacks` config. The message of the finding names the rule and the allowed alternative. Follow it, or limit the rule to other files.

Full reference: [Policy violations](/rules/policy-violation)

## Framework rules {#framework-rules}

Fallow runs these issue types only when the project declares the framework as a dependency. [Built-in plugins](/frameworks/built-in) lists the frameworks.

### Invalid client exports {#invalid-client-exports}

A `"use client"` file of a Next.js app exports a name that only a server file can export, such as `metadata` or `GET`. The build fails. Move the export to a file without the directive.

Full reference: [Invalid client exports](/rules/invalid-client-export)

### Mixed client/server barrels {#mixed-client-server-barrels}

One barrel file re-exports a `"use client"` file and a server-only file. An import from the barrel can then carry server code into the client, or the reverse. Split the barrel into a client barrel and a server barrel.

Full reference: [Mixed client/server barrels](/rules/mixed-client-server-barrel)

### Misplaced directives {#misplaced-directives}

A `"use client"` or `"use server"` line comes after an import or another statement. The bundler then ignores it without a message. Move the directive to the first line of the file.

Full reference: [Misplaced directives](/rules/misplaced-directive)

### Route collisions {#route-collisions}

Two or more route files of a Next.js App Router resolve to the same URL, for example through two route groups. The build fails. Move or merge files, so that each URL has one route file.

Full reference: [Route collisions](/rules/route-collision)

### Dynamic segment name conflicts {#dynamic-segment-name-conflicts}

Two dynamic route segments at the same position use different names, such as `[id]` and `[slug]`. The build passes, and the route fails on its first request. Give the segments one name.

Full reference: [Dynamic segment conflicts](/rules/dynamic-segment-name-conflict)

### Unused server actions {#unused-server-actions}

No code calls an export of a `"use server"` file. Next.js still accepts requests for the action. Call the action from code, or remove it.

Full reference: [Unused server actions](/rules/unused-server-action)

### Unprovided injects {#unprovided-injects}

A Vue `inject(KEY)` or a Svelte `getContext(KEY)` reads a key that no `provide()` or `setContext()` supplies. The read returns `undefined` at run time. Add the provider, or remove the read.

Full reference: [Unprovided injects](/rules/unprovided-inject)

### Unrendered components {#unrendered-components}

A barrel file keeps a component reachable, and no file renders it. Render the component where it belongs, or delete it and its re-export.

Full reference: [Unrendered components](/rules/unrendered-component)

### Unused component props {#unused-component-props}

A component declares a prop and never reads it. Use the prop, or remove it from the declaration.

Full reference: [Unused component props](/rules/unused-component-prop)

### Absent component props {#absent-component-props}

A component reads an optional prop, and no known caller passes it. The default value then always applies. Decide if the prop still has a purpose. This check is off by default.

Full reference: [Absent optional component props](/rules/absent-component-prop)

### Unused component emits {#unused-component-emits}

A Vue component declares an event with `defineEmits` and never emits it. Emit the event where it must fire, or remove it from the declaration.

Full reference: [Unused component emits](/rules/unused-component-emit)

### Unused Svelte events {#unused-svelte-events}

A Svelte component dispatches an event with `createEventDispatcher`, and no component listens for it. Add the listener, or remove the dispatch.

Full reference: [Unused Svelte events](/rules/unused-svelte-event)

### Unused component inputs {#unused-component-inputs}

An Angular component declares an input and never reads it in its class or its template. Read the input, or remove it.

Full reference: [Unused component inputs](/rules/unused-component-input)

### Unused component outputs {#unused-component-outputs}

An Angular component declares an output and never emits it. Emit the output where it must fire, or remove it.

Full reference: [Unused component outputs](/rules/unused-component-output)

### Unused load data keys {#unused-load-data-keys}

A SvelteKit `load()` function returns a key that no page reads. The server still gets the data on each request. Remove the key and its fetch, or read the key in the page.

Full reference: [Unused load data keys](/rules/unused-load-data-key)

### Prop drilling {#prop-drilling}

A React prop goes through a chain of components that only pass it on. Move the component that uses the prop closer to the data, or give the value through a context. This check is off by default.

Full reference: [Prop drilling](/rules/prop-drilling)

### Thin wrapper {#thin-wrapper}

A React component only renders one other component with all of its props. Render the other component directly, and delete the wrapper. This check is off by default.

Full reference: [Thin wrappers](/rules/thin-wrapper)

### Duplicate prop shape {#duplicate-prop-shape}

Three or more React components in two or more files declare the same set of prop names. Make one shared props type. This check is off by default.

Full reference: [Duplicate prop shapes](/rules/duplicate-prop-shape)

### Unused Effect layers {#unused-effect-layers}

An Effect `Layer` is used only by other layers that nothing uses, so it never runs. Remove the unused layers, or provide the layer to a runtime.

Full reference: [Unused Effect layers](/rules/unused-effect-layer)

### Unused tagged errors {#unused-tagged-errors}

Types and `catchTag` handlers name an Effect tagged error, and no code creates it. The failure never happens. Fail with the error where the problem occurs, or remove the class and its handlers.

Full reference: [Unused tagged errors](/rules/unused-tagged-error)

### Unproduced catch tags {#unproduced-catch-tags}

A `catchTag` handler waits for an error tag of the project that no code produces. The handler never runs. Remove the handler, or fail with the error where the problem occurs.

Full reference: [Unproduced catch tags](/rules/unproduced-catch-tag)

## Functions {#functions}

### Constant parameters {#constant-parameters}

Each call of a function passes the same value for a parameter, or no call passes an optional parameter. A branch that tests the parameter can then never run. Remove the parameter or the dead branch, or keep the parameter when it is a deliberate option. This check is off by default.

Full reference: [Constant parameters](/rules/constant-parameter)

### With type evidence {#with-type-evidence}

With [type-aware analysis](/analysis/type-aware), the constant parameter check also reports a default value that no call needs, and it checks the methods of exported classes. These findings show `(type evidence)` in the output. A type does not prove a value at run time, so check the calls before you remove a default.

Full reference: [Constant parameters](/rules/constant-parameter)

## Suppressions {#suppressions}

### Stale suppressions {#stale-suppressions}

A `fallow-ignore` comment or an `@expected-unused` tag matches no finding. The code changed, and the comment stayed. Remove the comment. When the comment names an unknown issue type, correct the name.

Full reference: [Stale suppressions](/rules/stale-suppression)
