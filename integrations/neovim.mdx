Connect Neovim to `fallow-lsp`, the language server of fallow, so that you see the findings of fallow while you edit. The server runs the same analysis as the CLI and CI.

## Before you start

- Neovim 0.11 or later, for `vim.lsp.config` and `vim.lsp.enable`. On an older version, start the server with `nvim-lspconfig` or `vim.lsp.start`.
- `fallow-lsp` on the `PATH` of Neovim. The `fallow` npm package contains it: `npm install -g fallow`.

## Steps

1. Check that Neovim can find the server:

   ```bash
   fallow-lsp --version
   ```

2. Add the server to your Neovim config:

   ```lua
   -- init.lua
   vim.lsp.config("fallow", {
     cmd = { "fallow-lsp" },
     filetypes = { "javascript", "typescript", "javascriptreact", "typescriptreact" },
     root_markers = { ".fallowrc.json", "package.json", ".git" },
   })

   vim.lsp.enable("fallow")
   ```

3. Open a file of a JavaScript or TypeScript project.

To use the fallow of the project, set `cmd` to the absolute path of `fallow-lsp` in `node_modules/.bin/`. Neovim runs `cmd` exactly as you write it.

## What you get

- Diagnostics for each finding of the [dead code analysis](/analysis/dead-code), circular dependencies and duplicated code.
- A hover on an export with the number of files that import it, and on duplicated code with the other places of the clone group.
- Code actions that remove an unused export or delete an unused file.
- A code lens `imported by N files` above each used export, when your config shows code lenses.

Each dead-code diagnostic has the `finding_id` of the finding in `data.findingId`. It is the same id as in `fallow dead-code --format json`.

The server runs the first analysis when you open the first file, and updates the diagnostics each time that you save a file.

## Options

Pass options in `init_options`. Each option is optional.

```lua
-- init.lua
vim.lsp.config("fallow", {
  cmd = { "fallow-lsp" },
  filetypes = { "javascript", "typescript", "javascriptreact", "typescriptreact" },
  root_markers = { ".fallowrc.json", "package.json", ".git" },
  init_options = {
    issueTypes = { ["circular-dependencies"] = false },
    changedSince = "fallow-baseline",
    prewarm = true,
  },
})
```

| Option | Effect |
|:--|:--|
| `issueTypes` | Hides an issue type in the editor when you set it to `false`. The config file of the project does not change. The keys are the issue types in kebab case. A client can get the list with the custom request `fallow/issueTypes`. |
| `changedSince` | Shows only the findings in files that changed since this git ref, like `--changed-since` on the CLI. |
| `prewarm` | Parses the project when the server starts, so the first analysis is faster. The server publishes no diagnostics before the first analysis. |
| `configPath` | The path of the config file, like `--config` on the CLI. |
| `production` | Runs in [production mode](/concepts/production-mode). |

The server keeps one project session between saves, so a save parses only the changed files. To load a new session on each run, set `cmd_env = { FALLOW_LSP_REUSE_SESSION = "0" }` in the config of the server.

## Check the result

1. Run `:checkhealth vim.lsp`.
2. Check that the `fallow` client is attached:

   ```vim
   :lua vim.print(vim.lsp.get_clients({ name = "fallow" }))
   ```

## If it fails

- **The client does not attach.** Neovim did not find `fallow-lsp`. Set `cmd` to an absolute path.
- **A new buffer shows no findings.** Wait for the first analysis, or save the file.
- **Many unused dependencies.** Install the dependencies of the project.
