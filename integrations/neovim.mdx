Get fallow findings in Neovim while you edit, with the same results as the CLI and CI. Neovim's built-in LSP client starts `fallow-lsp`, the language server that the VS Code extension also uses. The editor does no analysis of its own.

<Info>
The `vim.lsp.config` and `vim.lsp.enable` API below requires Neovim 0.11+. On older versions, attach `fallow-lsp` through `nvim-lspconfig` or a manual `vim.lsp.start`.
</Info>

## What works

- **Real-time diagnostics** for these issues:
  - unused files, exports, types, dependencies, and enum and class members
  - unresolved imports, unlisted dependencies, and duplicate exports
  - circular dependencies and code duplication
- **Opt-in security candidate diagnostics.** These are off by default. To turn them on, raise the `security-sink` or `security-client-server-leak` rule to `warn` or `error` in your fallow config. Each candidate shows as an `information` squiggle. A candidate is unverified, so check it before you act. The hover shows the confidence signals first and points to `fallow security --file` for the full trace. A quick-fix dismisses the candidate.
- **Hover information** with export usage counts, unused status, and duplicate block locations
- **Quick-fix code actions** to remove unused exports or delete unused files
- **Code lens** with export reference counts, where Neovim shows code lens

## Installation

<Steps>
  <Step title="Install Fallow so fallow-lsp is on your PATH">
    ```sh
    npm install -g fallow
    ```

    You can also add it as a project devDependency (`npm install -D fallow`) and point `cmd` at `node_modules/.bin/fallow-lsp`.
  </Step>
  <Step title="Confirm Neovim can see the binary">
    ```sh
    fallow-lsp --version
    ```
  </Step>
  <Step title="Register and enable the server">
    Add the configuration below to your Neovim config, then open a TypeScript or JavaScript project.
  </Step>
</Steps>

## Configuration

```lua
vim.lsp.config("fallow", {
	cmd = { "fallow-lsp" },
	filetypes = { "javascript", "typescript", "javascriptreact", "typescriptreact" },
	root_markers = { ".fallowrc.json", "package.json", ".git" },
	init_options = {
		-- Every issue type is enabled by default. List only the ones you
		-- want to turn off; any key you omit stays enabled.
		issueTypes = {
			["circular-dependencies"] = false,
		},
	},
})

vim.lsp.enable("fallow")
```

`init_options` is optional. `cmd`, `filetypes`, and `root_markers` are enough to attach the server.

### Issue-type toggles

To hide an issue type in the editor, set it to `false` in the LSP initialization options. Your project config does not change. The keys are fallow issue types in kebab-case, such as `unused-exports`, `unresolved-imports`, and `circular-dependencies`. To get the current list, a client can send the custom `fallow/issueTypes` request.

### Scope to changed files

To see diagnostics only for files changed since a git ref, pass the ref as `changedSince`. This works like `fallow dead-code --changed-since` and the VS Code `fallow.changedSince` setting. Use it to adopt fallow on a legacy codebase without a flood of old findings:

```lua
init_options = {
	changedSince = "fallow-baseline",
},
```

<Note>
**When diagnostics appear.** Fallow uses the LSP 3.17 pull model and refreshes diagnostics on save. The first analysis runs when the server attaches. A buffer you just opened shows findings when that first pass completes, or after the next save. Some findings belong to files you have not opened, such as `package.json` for unlisted dependencies. Fallow pushes those findings, so you still see them.
</Note>

## Binary resolution

Neovim runs `cmd` exactly as configured. If `fallow-lsp` is not on Neovim's `PATH`, point `cmd` at an absolute path:

```lua
vim.lsp.config("fallow", {
	cmd = { "/absolute/path/to/fallow-lsp" },
	filetypes = { "javascript", "typescript", "javascriptreact", "typescriptreact" },
	root_markers = { ".fallowrc.json", "package.json", ".git" },
})
```

## Verifying the setup

1. Open a TypeScript or JavaScript project.
2. Run `:checkhealth vim.lsp`.
3. Confirm `fallow` is attached:

   ```vim
   :lua vim.print(vim.lsp.get_clients({ name = "fallow" }))
   ```
