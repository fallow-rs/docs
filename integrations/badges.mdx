## Before you start

- Install the dependencies of the project. The score depends on the findings, and fallow reads the packages in `node_modules`.

## Steps

1. Write the badge:

   ```bash
   mkdir -p .github/badges
   npx fallow health --format badge > .github/badges/health.svg
   ```

2. Add the badge to the README with a relative link:

   ```markdown
   ![fallow health](.github/badges/health.svg)
   ```

3. Commit both files.

`--format badge` computes the score, so you do not need `--score`. The SVG contains everything that it needs and loads nothing from another host. Each badge has its own element ids, so a page can show more than one badge.

The color follows the grade:

| Grade | Color |
|:--|:--|
| A | Bright green |
| B | Green |
| C | Yellow |
| D | Orange |
| F | Red |

[Health score](/analysis/health#health-score) gives the score range of each grade.

## Check the result

The first lines of the file name the grade and the score:

```text
<svg xmlns="http://www.w3.org/2000/svg" width="88" height="20" role="img" aria-label="fallow: C (60)">
<title>fallow: C (60)</title>
```

## Update the badge from CI

A badge that you commit changes only when you write it again. To update it on each push to the default branch, let a CI job write it and commit it:

```yaml
# .github/workflows/badge.yml
name: Health badge

on:
  push:
    branches: [main]

permissions:
  contents: write

jobs:
  badge:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: |
          mkdir -p .github/badges
          npx fallow health --format badge > .github/badges/health.svg
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add .github/badges/health.svg
          git diff --quiet --cached || git commit -m "chore: update health badge [skip ci]"
          git push
```

This works for a private repository too. GitHub shows a relative image link to each reader who can read the repository.

## A badge for each workspace

In a monorepo, scope the score to one [workspace](/concepts/workspaces) with `--workspace`:

```bash
npx fallow health --format badge --workspace @acme/web > .github/badges/web.svg
```

## A badge from shields.io

To show the badge with the style of shields.io, write a JSON endpoint file from the score:

```bash
npx fallow health --format json --score --quiet \
  | jq '{schemaVersion: 1, label: "fallow", message: "\(.health_score.grade) (\(.health_score.score | floor))", color: (if .health_score.score >= 85 then "brightgreen" elif .health_score.score >= 70 then "green" elif .health_score.score >= 55 then "yellow" elif .health_score.score >= 40 then "orange" else "red" end)}' \
  > health-badge.json
```

Publish the file at a public URL, and use the endpoint badge of shields.io:

```markdown
![fallow health](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/your-org/your-repo/main/health-badge.json)
```

shields.io reads the file from a public URL, so this works only for a public repository. Do not put a token in the URL.

## If it fails

- **The badge shows a broken image.** The README links to a file that the branch does not have, or to a private repository from an outside host. Use a relative link to a file in the same branch.
- **The score is lower than expected.** The job did not install the dependencies, so fallow reported used packages as unused. Run the install step before fallow.
