Call the fallow analyses from your own Node.js code with the package `@fallow-cli/fallow-node`. Each function returns the same report as the CLI with `--format json`, without a child process.

Use the bindings in a tool, a server or a script that runs in Node.js. For a shell script or a CI job, use the CLI.

## Before you start

- Node.js 22 or later.
- A JavaScript or TypeScript project with its dependencies installed.

## Steps

1. Install the package:

   ```bash
   npm install @fallow-cli/fallow-node
   ```

   The package is a native addon. npm installs the binary for your platform: macOS, Linux (glibc or musl) or Windows, on x64 or arm64.

2. Write a script that calls the analyses:

   ```js
   // report.mjs
   import fallow from "@fallow-cli/fallow-node";

   const { detectDeadCode, computeHealth } = fallow;
   const root = process.argv[2] ?? process.cwd();

   const deadCode = await detectDeadCode({ root });
   console.log(`${deadCode.kind}: ${deadCode.summary.total_issues} issues`);
   for (const item of deadCode.unused_exports) {
     console.log(`unused export ${item.path}:${item.line} ${item.export_name}`);
   }

   const health = await computeHealth({ root, score: true });
   console.log(`health score ${health.health_score.score} (${health.health_score.grade})`);
   ```

   The package is a CommonJS module. In an ES module, import its default export, as in the example. In CommonJS, use `require("@fallow-cli/fallow-node")`.

3. Run the script in the project root.

## Check the result

```bash
node report.mjs
```

```text
dead-code: 6 issues
unused export src/lib/format.ts:3 formatPercent
unused export src/lib/index.ts:1 formatPercent
unused export src/services/orders.ts:18 cancelOrder
health score 60.8 (C)
```

Each report has a `kind` field that names the analysis, and a `schema_version`. The paths are relative to the root. [JSON output](/reference/json-output) describes each report.

## If it fails

A function rejects with a `FallowNodeError`. It has the fields `message`, `exitCode`, and optionally `code`, `help` and `context`:

```js
try {
  await detectDeadCode({ root: "/does/not/exist" });
} catch (error) {
  console.log(error.code, error.exitCode);
}
```

```text
FALLOW_INVALID_ROOT 2
```

The exit codes are the same as on the CLI. See [Exit codes](/reference/exit-codes).

- **`Named export ... not found`.** You used a named import in an ES module. Import the default export.
- **`Cannot find native binding`.** npm skipped the optional dependencies, or `node_modules` comes from another operating system. Run `npm install` again on the machine that runs the script.

## Reference

### Functions {#functions}

Each function is async and takes an optional options object.

| Function | CLI equivalent | Returns |
|:--|:--|:--|
| `detectDeadCode(options?)` | `fallow dead-code --format json` | `DeadCodeReport` |
| `detectCircularDependencies(options?)` | `fallow dead-code --circular-deps --format json` | `DeadCodeReport` with only circular dependencies |
| `detectBoundaryViolations(options?)` | `fallow dead-code --boundary-violations --format json` | `DeadCodeReport` with only boundary violations |
| `detectArchitecture(options?)` | `fallow architecture --format json` | `ArchitectureReport` |
| `detectDuplication(options?)` | `fallow dupes --format json` | `DuplicationReport` |
| `detectSimilarCode(options?)` | `fallow similar-code --format json` | `SimilarCodeReport` |
| `detectFeatureFlags(options?)` | `fallow flags --format json` | `FeatureFlagsReport` |
| `computeComplexity(options?)` | `fallow health --format json` | `HealthReport` |
| `computeHealth(options?)` | `fallow health --format json` | The same as `computeComplexity` |

`detectSimilarCode` needs the local model of [similar-code analysis](/analysis/similar-code). It never downloads the model. Run `fallow similar-code setup --local` once with the CLI.

### Shared options {#options}

Each options object accepts these fields. An enum value uses the lowercase value of the CLI, for example `"mild"`.

| Field | Type | CLI equivalent |
|:--|:--|:--|
| `root` | `string` | `--root`. The default is `process.cwd()`. |
| `configPath` | `string` | `--config` |
| `allowRemoteExtends` | `boolean` | `--allow-remote-extends` |
| `noCache` | `boolean` | `--no-cache` |
| `threads` | `number` | `--threads` |
| `diffFile` | `string` | `--diff-file`. A path only: the bindings do not read a diff from stdin. |
| `production` | `boolean` | `--production` |
| `changedSince` | `string` | `--changed-since` |
| `workspace` | `string[]` | `--workspace` |
| `changedWorkspaces` | `string` | `--changed-workspaces` |
| `explain` | `boolean` | `--explain` |

Each function also takes the options of its command, with the CLI option in camel case: for example `unusedExports` for `--unused-exports`, `minTokens` for `--min-tokens`, or `score` for `--score`. The package types in [`types/index.d.ts`](https://github.com/fallow-rs/fallow/blob/main/crates/napi/types/index.d.ts) list each option of each function.

The bindings run the analyses only. They have no function that writes files, for example `fix`, `init` or `--save-baseline`, and no watch mode.
