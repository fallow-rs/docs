Production mode limits the analysis to code that ships to users. Fallow ignores test and development files, so the report shows only the unused code and dependencies in your production build.

```bash
fallow dead-code --production
```

You can also set it in your config:

```jsonc
// .fallowrc.json
{
  "production": true
}
```

## What changes in production mode

| Behavior | Default | Production |
|:---------|:--------|:-----------|
| Test files (`*.test.*`, `*.spec.*`, `*.e2e.*`, `__tests__/`, `test/`, `tests/`) | Included | Excluded |
| Story files (`*.stories.*`) | Included | Excluded |
| Mock files (`__mocks__/`) | Included | Excluded |
| Package.json scripts analyzed | All | Only `start`, `build`, `serve`, `preview`, `prepare`, `prepublishOnly`, `postinstall`, and `pre`/`post` lifecycle hooks for `start`, `build`, `serve`, `install` |
| Unused devDependencies | Reported | Skipped |
| Unused optionalDependencies | Reported | Skipped |
| Test-only dependencies | Flagged (move to devDependencies) | Skipped |
| Type-only dependencies | Not flagged | Flagged (move to devDependencies) |

## Type-only dependency detection

In production mode, fallow finds dependencies that your code imports only with `import type`:

```ts
import type { Config } from 'some-package';  // Type-only, erased at runtime
```

Move these packages to `devDependencies`. The compiler erases types, so production installs do not need them.

<Tip>
In a monorepo, production mode finds the dependencies in each package that belong in devDependencies. This keeps each package install small.
</Tip>

## Per-analysis production mode

In combined mode (bare `fallow`) and in `fallow audit`, you can enable production mode for each analysis separately:

```jsonc
// .fallowrc.json
{
  "production": {
    "health": true,
    "deadCode": false,
    "dupes": false
  }
}
```

For one run, pass `--production-health`, `--production-dead-code`, or `--production-dupes`. In CI, set `FALLOW_PRODUCTION_HEALTH=true` or one of the related env vars. The global `--production` flag still enables production mode for every analysis.

Fallow applies these sources in order of precedence, highest first:

1. CLI flags
2. Per-analysis env var
3. Global `FALLOW_PRODUCTION`
4. Config

`--production` and the per-analysis flags can only enable production mode. `--no-production` turns it off for every analysis, and it overrides env vars and config. It conflicts with `--production`. Env vars and config can enable or disable production mode. Examples:

```bash
# Run health in production mode, dead-code and dupes on the full tree
fallow --production-health

# Same, via env var (useful in CI templates that pass env-only)
FALLOW_PRODUCTION_HEALTH=true fallow

# Per-analysis env wins over the global env, so this runs health in production
# mode even though the global env says off (the typical CI-template case)
FALLOW_PRODUCTION=false FALLOW_PRODUCTION_HEALTH=true fallow

# CLI flags beat env vars; this enables all three regardless of FALLOW_PRODUCTION_* env
fallow --production

# Turn production mode off for every analysis, even when config sets production: true
fallow --no-production
```
