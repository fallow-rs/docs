Production mode limits the analysis to code that ships to users. Fallow ignores test and development files, so the report shows only the unused code and dependencies in your production build.

```bash
fallow dead-code --production
```

You can also set it in your config:

```jsonc
// .fallowrc.json
{
  "production": true
}
```

## What changes in production mode

| Behavior | Default | Production |
|:---------|:--------|:-----------|
| Test files (`*.test.*`, `*.spec.*`, `*.e2e.*`, `*.e2e-spec.*`, `*.bench.*`, `__tests__/`, `__snapshots__/`, `test/`, `tests/`, `test-d/`) | Included | Excluded |
| Story files (`*.stories.*`, `*.story.*`) | Included | Excluded |
| Mock and fixture files (`__mocks__/`, `__fixtures__/`, `*.fixture.*`) | Included | Excluded |
| Config files in the project root (`*.config.*`) and hidden script files (`.*.js`, `.*.ts`, `.*.mjs`, `.*.cjs`) | Included | Excluded |
| Files that only an explicit `"entryPointRole": "support"` entry of a [custom plugin](/frameworks/custom-plugins) matches | Entry points | Excluded |
| `package.json` scripts that fallow reads for dependency use | All | Only `start`, `build`, `serve`, `preview`, `prepare`, `prepublishOnly`, `postinstall`, the `pre`/`post` lifecycle hooks for `start`, `build`, `serve`, `install`, and namespaced forms such as `build:prod` |
| Files that a `package.json` script runs, for example `node scripts/seed.js` | Entry points | Entry points |
| Unused devDependencies | Reported | Skipped |
| Unused optionalDependencies | Reported | Skipped |
| Test-only dependencies | Flagged (move to devDependencies) | Skipped |
| Type-only dependencies | Not flagged | Flagged (move to devDependencies) |

## Type-only dependency detection

In production mode, fallow finds dependencies that your code imports only with `import type`:

```ts
import type { Config } from 'some-package';  // Type-only, erased at runtime
```

Move these packages to `devDependencies`. The compiler erases types, so production installs do not need them.

<Tip>
In a monorepo, production mode finds the dependencies in each package that belong in devDependencies. This keeps each package install small.
</Tip>

## Per-analysis production mode

In combined mode (bare `fallow`) and in `fallow audit`, you can enable production mode for each analysis separately:

```jsonc
// .fallowrc.json
{
  "production": {
    "health": true,
    "deadCode": false,
    "dupes": false
  }
}
```

For one run, pass `--production-health`, `--production-dead-code`, or `--production-dupes`. In CI, set `FALLOW_PRODUCTION_HEALTH=true` or one of the related env vars. The global `--production` flag still enables production mode for every analysis.

Fallow applies these sources in order of precedence, highest first:

1. CLI flags
2. Per-analysis env var
3. Global `FALLOW_PRODUCTION`
4. Config

`--production` and the per-analysis flags can only enable production mode. `--no-production` turns it off for every analysis, and it overrides env vars and config. It conflicts with `--production`. Env vars and config can enable or disable production mode. Examples:

```bash
# Run health in production mode, dead-code and dupes on the full tree
fallow --production-health

# Same, via env var (useful in CI templates that pass env-only)
FALLOW_PRODUCTION_HEALTH=true fallow

# Per-analysis env wins over the global env, so this runs health in production
# mode even though the global env says off (the typical CI-template case)
FALLOW_PRODUCTION=false FALLOW_PRODUCTION_HEALTH=true fallow

# CLI flags beat env vars; this enables all three regardless of FALLOW_PRODUCTION_* env
fallow --production

# Turn production mode off for every analysis, even when config sets production: true
fallow --no-production
```

## Exclude more paths in production mode only

Some files do not ship, but they are not tests: build scripts, seed data, or local tools. Use the object form of `production` and list these paths in `ignore`:

```jsonc
// .fallowrc.json
{
  "production": {
    "deadCode": true,
    "ignore": ["scripts/**", "src/dev-tools/**"]
  }
}
```

Each entry is a glob, relative to the project root. The default is an empty list.

- A run in production mode does not analyze these paths. The built-in test, story and dev patterns still apply.
- A run without production mode analyzes these paths as usual.
- The globs apply to each analysis that runs in production mode, not only to dead-code analysis.
- The globs also apply when `--production` or a `FALLOW_PRODUCTION*` env var turns on production mode.

The boolean form, `"production": true`, has no `ignore` list. To hide files in every mode, use `ignorePatterns` instead.

[`fallow migrate`](/cli/migrate) converts each production exclusion of a knip `project` setting (`!pattern!`) to a `production.ignore` glob.

## Production code that a test pattern excludes

The built-in directory patterns, such as `**/test/**` and `**/tests/**`, can also match production source. An example is `src/components/runner/test/Runner.vue`. Production mode does not analyze that file. An export or a parameter that only this file uses can then appear in a finding.

When an analyzed production file imports such a file, fallow reports it. This also applies to an import of a workspace package whose entry file a pattern excludes. The JSON output adds one `production-excluded-file-imported` entry to `workspace_diagnostics[]` for each pattern:

| Field | Value |
|:------|:------|
| `pattern` | The built-in glob that excluded the files |
| `file_count` | The number of excluded files that production code imports |
| `files` | The first five of these files, relative to the project root |

The human output prints the same warning on stderr. The diagnostic does not change the findings or the exit code.

`ignorePatterns` cannot bring back a file that a production pattern excludes. To analyze the file, do one of these steps:

- Move the file out of the matched path, for example rename the `test` directory.
- Run that analysis without production mode: pass `--no-production`, or set `production: { deadCode: false }` in the config.
