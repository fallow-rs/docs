A file that only an HTML page, a Vue template, or a stylesheet references is not unused. Fallow analyzes more than `.js` and `.ts` files: it reads imports and exports from non-JavaScript file types, based on the file extension. You do not need a plugin or config.

<Tabs>
  <Tab title="HTML">
    Fallow finds `.html` files and reads the `<script src>` and `<link>` tags as module graph edges. This covers projects with HTML entry points, such as Parcel or setups with no framework.

    **Fallow reads:**

    - `<script src="./main.js">` script references
    - `<link rel="stylesheet" href="./styles.css">` stylesheet references
    - `<link rel="modulepreload" href="./vendor.js">` module preload references
    - Root-relative paths (for example `<script src="/src/main.tsx">`). Fallow resolves them against the project root, as Vite, Parcel, and similar dev servers do. This also applies when the reference is in a JSX, TSX, JS, or TS source file (see the JSX templates tab).

    ```html index.html
    <!DOCTYPE html>
    <html>
      <head>
        <link rel="stylesheet" href="./styles/main.css" />
        <link rel="modulepreload" href="./vendor/lodash.js" />
      </head>
      <body>
        <div id="app"></div>
        <script src="./src/main.ts"></script>
      </body>
    </html>
    ```

    Fallow reads references to `./styles/main.css`, `./vendor/lodash.js`, and `./src/main.ts` from this file.

    <Tip>
    The Parcel plugin adds `index.html` as an entry pattern, so fallow finds HTML entry files with no extra config.
    </Tip>

    **Angular template complexity.** `fallow health` reports the complexity of Angular templates as synthetic `&lt;template&gt;` findings. This covers standalone `.html` files that `templateUrl` references and inline `@Component({ template: \`...\` })` literals. Fallow counts these template constructs:

    - control-flow blocks (`@if`, `@for`, `@switch`, `@case`, `@defer (when ...)`, `@let`)
    - legacy structural directives (`*ngIf`, `*ngFor`)
    - bound attributes (`[x]`, `(x)`, `bind-x`, `on-x`)
    - `{{ }}` interpolations

    Fallow reports an inline-template finding on the `@Component` decorator line. To suppress it, put `// fallow-ignore-next-line complexity` directly above the decorator. To suppress an external-template finding, put `&lt;!-- fallow-ignore-file complexity --&gt;` at the top of the `.html` file.
  </Tab>
  <Tab title="Vue / Svelte">
    Fallow reads the `<script>` block of Vue and Svelte single-file components and analyzes it like a JS or TS module. It also reads the `<template>` section for component references, directives, and expressions. An import that only the template uses therefore counts as used.

    **Script extraction:**

    - `<script>` and `<script setup>` blocks
    - `lang="ts"` and `lang="tsx"` attributes
    - `<script src="./external.ts">` external script references
    - HTML comments (`<!-- ... -->`), which fallow removes before parsing

    **Vue template tracking:**

    - Component tags: `<MyComponent>` resolves to imported `MyComponent`
    - Custom directives: `v-focus-trap` resolves to imported `vFocusTrap`
    - `v-on` and `v-bind` object syntax (for example `v-on="handlers"`)
    - Template expressions: `{{ formatDate() }}` marks `formatDate` as used
    - Namespace member access: `utils.formatDate` in a template marks the member as used

    **Svelte template tracking:**

    - Component tags: `<Button>` resolves to imported `Button`
    - Directives: `use:tooltip`, `transition:fade`, `animate:flip`, `in:fly`, `out:fade`
    - Attribute expressions: `{expression}` and shorthand attributes `{variable}`
    - `$store` subscriptions: `$myStore` marks `myStore` as used

    ```vue Example.vue
    <script setup lang="ts">
    import { ref } from 'vue'
    import { formatDate } from '@/utils/date'
    import FocusTrap from '@/components/FocusTrap.vue'

    const count = ref(0)
    </script>

    <template>
      <FocusTrap>
        <div>{{ formatDate(new Date()) }}</div>
      </FocusTrap>
    </template>
    ```

    Fallow reads imports of `ref` from `vue`, `formatDate` from `@/utils/date`, and `FocusTrap` from `@/components/FocusTrap.vue`. The template uses `<FocusTrap>` and `formatDate`, so fallow does not report them as unused, although the script block does not use them.

    <Warning>
    Svelte components export props implicitly. Fallow cannot tell props from utility exports, so it can miss unused exports in `.svelte` files. For details, see [Limitations](/analysis/limitations).
    </Warning>
  </Tab>
  <Tab title="SSR layouts">
    SSR frameworks such as [Hono](https://hono.dev) render HTML from layout components with JSX or with a tagged template literal (`` html`...` ``). Fallow reads `<script src="...">` and `<link rel="stylesheet|modulepreload" href="...">` in both forms as it does in plain HTML. Each one is an asset reference that keeps the target file reachable.

    **Fallow reads:**

    - `<script src="./app.js">` inside JSX/TSX layouts and `` html`...` `` tagged templates
    - `<link rel="stylesheet" href="./global.css">` inside JSX/TSX layouts and `` html`...` `` tagged templates
    - `<link rel="modulepreload" href="./vendor.js">` inside JSX/TSX layouts and `` html`...` `` tagged templates
    - Root-relative paths (`<link href="/static/style.css">`). Fallow resolves them against the parent directory of the source file first, then against the project root, as Vite, Parcel, and Hono serve static assets

    ```tsx Layout.tsx
    export const Layout = () => (
      <html>
        <head>
          <link rel="stylesheet" href="/static/style.css" />
          <script src="/static/app.js"></script>
        </head>
        <body>
          <h1>Hello from Hono</h1>
        </body>
      </html>
    );
    ```

    ```ts layout.ts
    import { html } from 'hono/html'

    export const Layout = ({ title, body }: { title: string; body: string }) => html`
      <!doctype html>
      <html>
        <head>
          <title>${title}</title>
          <link rel="stylesheet" href="/static/style.css" />
          <script defer src="/static/app.js"></script>
        </head>
        <body>${body}</body>
      </html>
    `
    ```

    Fallow reads references to `/static/style.css` and `/static/app.js` from both files and marks those files in `static/` as reachable.

    <Note>
    In JSX, fallow reads only lowercase intrinsic elements (`<script>`, `<link>`) with plain string literals (`src="foo.css"`). It skips capitalized React-style components (`<Script>`, `<Link>`) and expression containers (`href={someVar}`) on purpose. Their meaning depends on the component, and fallow cannot resolve that statically.

    In tagged templates, fallow matches only the bare identifier tag `html`. It ignores other tags, such as `css`, `sql`, and `gql`. It skips an asset reference that an interpolation splits (`` html`<script src="${base}/app.js">` ``), so it does not produce a broken specifier.
    </Note>
  </Tab>
  <Tab title="JSDoc">
    Plain JavaScript files can reference TypeScript types through JSDoc `import()` expressions. Fallow reads these references and marks the types as used, so untyped JS files do not cause false unused-export reports.

    ```js app.js
    /**
     * @param cfg {import('./types.ts').Config}
     * @returns {import('./types.ts').Result}
     */
    function boot(cfg) {
      return { ok: true };
    }
    ```

    Fallow marks the `Config` and `Result` types from `./types.ts` as used, although no `import` statement binds them. This works in all JSDoc tags (`@param`, `@returns`, `@type`, `@typedef`, `@callback`). Fallow also supports:

    - union annotations with more than one `import()` expression (`{import('./a').A | import('./b').B}`)
    - nested member access
    - bare package specifiers
    - parent-relative paths

    <Note>
    Fallow reads only `/** */` JSDoc blocks. It ignores single-star `/* */` comments, because they are not JSDoc. The TypeScript compiler does the same.
    </Note>
  </Tab>
  <Tab title="Astro">
    Astro components start with a frontmatter block between two `---` lines. Fallow analyzes the content of this block as TypeScript.

    Fallow also follows the client scripts in the template body: `<script src="...">` references and ESM `import` statements in inline `<script>` blocks. Astro bundles both into the page at build time, so their targets stay reachable.

    ```astro Layout.astro
    ---
    import Header from '../components/Header.astro'
    import Footer from '../components/Footer.astro'
    import type { Props } from './types'
    ---

    <html>
      <body>
        <Header />
        <slot />
        <Footer />
        <script src="../scripts/analytics.ts"></script>
        <script>
          import '../scripts/hydrate'
        </script>
      </body>
    </html>
    ```

    Fallow reads imports of `Header`, `Footer`, and the `Props` type from this file. It also reads `../scripts/analytics.ts` (external) and `../scripts/hydrate` (inline ESM).
  </Tab>
  <Tab title="MDX">
    MDX files can contain JavaScript `import` and `export` statements next to Markdown content. Fallow adds these statements to the module graph.

    ```mdx guide.mdx
    import { CodeBlock } from '../components/CodeBlock'
    import { Callout } from '../components/Callout'

    export const meta = { title: 'Getting Started' }

    # Getting Started

    <CodeBlock language="bash">
      npm install fallow
    </CodeBlock>
    ```

    Fallow tracks the imports of `CodeBlock` and `Callout`, and the named export `meta`.
  </Tab>
  <Tab title="GraphQL">
    GraphQL documents can import fragments from other `.graphql` and `.gql` files with `#import` comments. Fallow reads these relative links and keeps the imported fragment files reachable.

    **Fallow reads:**

    - `#import "./fragment.graphql"` relative imports
    - `# import '../shared/fields.gql'` with optional whitespace after `#`
    - Relative imports with no extension, such as `#import "./fragment"`. Fallow tries `.graphql` and `.gql`

    ```graphql query.graphql
    #import "./fragments/user-fields"

    query CurrentUser {
      currentUser {
        ...UserFields
      }
    }
    ```

    ```graphql fragments/user-fields.graphql
    fragment UserFields on User {
      id
      name
    }
    ```

    Fallow reads the reference to `./fragments/user-fields` from `query.graphql`. Because the reference has no extension, fallow tries `.graphql` and `.gql`. It then marks `fragments/user-fields.graphql` as reachable.

    <Note>
    Fallow reads only relative `#import` specifiers that start with `./` or `../`. It ignores package specifiers and schema-loader syntax on purpose, because they do not point to a local document in the module graph.
    </Note>
  </Tab>
  <Tab title="CSS / SCSS Modules">
    Fallow treats the class names in CSS and SCSS module files (`.module.css` and `.module.scss`) as named exports. When a component imports `styles` from a CSS module, fallow knows which classes exist.

    ```css Button.module.css
    .root {
      display: flex;
    }

    .primary {
      background: blue;
    }

    .disabled {
      opacity: 0.5;
    }
    ```

    This file exports `root`, `primary`, and `disabled` as named exports.

    **CSS features fallow tracks:**

    | Feature | Description |
    |:--------|:------------|
    | `@import` | Adds an edge to the module graph |
    | `@use` | Fallow resolves Sass `@use` rules as module imports |
    | `@forward` | Fallow treats Sass `@forward` rules as re-exports |
    | `@apply` / `@tailwind` | Counts as a use of the Tailwind CSS dependency |
    | `@plugin` | Fallow reads Tailwind v4 plugin sources as default imports (package or relative) |

    <Tip>
    When Tailwind is in your `package.json`, `@apply` and `@tailwind` directives mark the `tailwindcss` dependency as used. This prevents a false "unused dependency" report. A Tailwind v4 `@plugin "pkg"` directive marks its package or local plugin file as used.
    </Tip>
  </Tab>
  <Tab title="React Native">
    React Native projects use a file extension per platform for each platform implementation. Fallow treats these files as variants of the same module.

    **Supported platform extensions:**

    | Extension | Platform |
    |:----------|:---------|
    | `.web.ts` / `.web.tsx` | Web (react-native-web) |
    | `.ios.ts` / `.ios.tsx` | iOS |
    | `.android.ts` / `.android.tsx` | Android |
    | `.native.ts` / `.native.tsx` | Native (iOS + Android) |

    ```text
    src/
      Button.tsx          # Default implementation
      Button.web.tsx      # Web override
      Button.native.tsx   # Native override
    ```

    When another file imports `./Button`, fallow resolves the import to all platform variants and marks each one as reachable.
  </Tab>
