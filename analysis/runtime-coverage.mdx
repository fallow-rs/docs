Static analysis tells you which code can run. It cannot tell you which code your users run. **Runtime coverage** is data about the functions that ran in a deployed app with real traffic. Fallow merges it into the [health report](/analysis/health), so that you delete cold code on evidence and review changes to busy code with care.

```bash
npx fallow health --runtime-coverage ./coverage
```

## What fallow finds

A small app ran 200 requests with `NODE_V8_COVERAGE=./coverage`. Then fallow read the capture:

```text
● Runtime coverage: cold code detected
  6 tracked, 3 hit, 3 unhit, 0 untracked (50.0% covered)
  based on 603 traces over 0 days (0 deployments)
  src/format.js:3 formatPercent [0 invocations, safe to delete]
  src/orders.js:5 refundOrder [0 invocations, safe to delete]
  src/orders.js:3 cancelOrder [0 invocations, review required]
  hot paths:
    src/format.js:1 formatPrice (200 invocations, p100, cost 200 at 1.00 iterations/call)
    src/index.js:4 handle (200 invocations, p50, cost 200 at 1.00 iterations/call)
    src/orders.js:1 createOrder (200 invocations, p0, cost 200 at 1.00 iterations/call)


Coverage intelligence
  Verdict: high-confidence-delete
  src/format.js:3 formatPercent high-confidence-delete [static_unused, runtime_cold, no_test_path]
    Confirm ownership, then remove cold unused code in `src/format.js:formatPercent`
  src/orders.js:5 refundOrder high-confidence-delete [static_unused, runtime_cold, no_test_path]
    Confirm ownership, then remove cold unused code in `src/orders.js:refundOrder`
```

| Part | Meaning |
|:--|:--|
| `cold code detected` | The verdict of the report: `clean`, `cold-code-detected`, `hot-path-touched`, `license-expired-grace` or `unknown`. |
| `6 tracked, 3 hit, 3 unhit` | The functions that the capture tracked, and how many of them ran. |
| `based on 603 traces` | The number of calls in the capture. A small number gives a lower confidence. |
| `[0 invocations, safe to delete]` | One function, its call count, and its verdict. |
| `hot paths` | The functions with the most calls. `p100` is the rank. The cost is the calls multiplied by the work per call. |
| `Coverage intelligence` | Findings that combine the runtime data with the static analysis and the tests. |

The rest of the report is the normal health report.

## How fallow decides

Fallow gives each function one verdict. It combines two facts: the static result (does a reachable file use the function?) and the call count in the capture.

| Verdict | Meaning |
|:--|:--|
| `safe_to_delete` | No reachable code uses the function, and it did not run. This is the strongest signal to delete. |
| `review_required` | Reachable code uses the function, but it did not run. It can be an error path, a seasonal feature, or code that is really unused. |
| `low_traffic` | The function ran, but its share of all calls is below the low-traffic threshold: 0.1 percent by default. |
| `coverage_unavailable` | Fallow could not match the function to the capture. This is not a signal to delete. |
| `active` | The function ran above the threshold. The report does not list it. |
| `unknown` | Fallow could not decide. |

In the example, nothing uses `formatPercent` and `refundOrder`, and they did not run. `cancelOrder` has an import in `index.js`, but no request took that path.

The confidence of a verdict depends on the size of the capture. Below 5,000 calls, fallow gives `medium` confidence at most. Change the two limits with `--min-observation-volume` and `--low-traffic-threshold`.

Fallow accepts a V8 coverage directory, one V8 JSON file, or one Istanbul `coverage-final.json`. When the V8 dump holds source maps, fallow maps the bundle positions back to your source files.

## Capture once on your machine

A single local capture is free. Continuous monitoring and more than one capture need a license.

1. Run the setup. It installs the `@fallow-cli/fallow-cov` package and writes a recipe for your framework to `docs/collect-coverage.md`:

   ```bash
   npx fallow coverage setup
   ```

2. Run your app with real traffic and the coverage setting of the recipe, for example `NODE_V8_COVERAGE=./coverage node server.js`.

3. Read the capture:

   ```bash
   npx fallow health --runtime-coverage ./coverage
   ```

The setup is resumable. Run `fallow coverage setup` again after the capture, and it continues with the analysis.

## Collect continuously with Fallow Cloud

One capture shows one moment. A function that runs once a month does not show in a capture of one hour. Fallow Cloud collects runtime coverage from each deployment over days or weeks, with a small beacon in your app. `fallow coverage analyze --cloud` then reads the data of the last 1 to 90 days. To set it up, see [The Fallow beacon](/cloud/beacon).

## Act on a verdict

| Verdict | Action |
|:--|:--|
| `safe_to_delete` with `high` confidence | Delete the function. Ask the owner first when the code is shared. |
| `safe_to_delete` with `medium` confidence | Capture more traffic, or check the function by hand. |
| `review_required` | Ask: is this an error path, a seasonal path or a worker? When it is not, remove the call and the function. |
| `low_traffic` | Find the users of the feature before you remove it. |
| `coverage_unavailable` | Check the source maps and the capture. Do not delete on this verdict. |

On a pull request, add `--changed-since main` or `--diff-file <file>`. When the change touches a hot path, the verdict becomes `hot-path-touched`, and the reviewer knows that the change runs often.

## Set a limit

With `--runtime-coverage`, a finding with the verdict `safe_to_delete`, `review_required` or `low_traffic` makes `fallow health` exit with code 1. Add `--report-only` to show the runtime data without a failure.

## Limits

- A capture holds only the paths that ran during the capture. A short capture misses rare paths, and the report says so with a `short capture` note.
- V8 does not track each function. A function that the engine did not compile, a worker thread or `eval` code gets `coverage_unavailable`.
- A bundled app needs source maps. Without them, fallow cannot connect a call to a line of your source.
- A function that ran in tests only is not a production call. Capture from the deployed app, not from a test run.
