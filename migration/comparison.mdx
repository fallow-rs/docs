Use this page to decide whether fallow or knip fits your project. Both tools detect unused code in TypeScript and JavaScript projects.

knip is a mature tool with broad plugin coverage. Fallow is written in Rust and is one binary. In addition to unused code, fallow covers:

- code duplication
- complexity hotspots
- maintainability scores
- architecture boundaries
- design-system styling

## Performance

Fallow is a compiled Rust binary that uses rayon to run in parallel. knip runs on Node.js. knip v6 uses the Oxc parser through NAPI bindings. This made the gap to fallow much smaller than with v5, but knip still runs on one thread.

The benchmarks use cold runs (no cache), so both tools start from zero. The fastest tool in each row is in bold.

|:--------|------:|-------:|--------:|--------:|

| [preact](https://github.com/preactjs/preact) | 244 | **74ms** | 822ms | 2.01s |
| [fastify](https://github.com/fastify/fastify) | 286 | **64ms** | 903ms | 205ms |
| [vue/core](https://github.com/vuejs/core) | 522 | **138ms** | errors¹ | errors¹ |

<Info>
  The benchmarks ran on open-source projects from 174 to 38,146 files. Versions: fallow 2.100.0, knip 5.87.0, and knip 6.6.1. Machine: Apple M5 (10 cores), 32 GB RAM, macOS 26.4, Node v22.22.1. Each number is the median of 5 cold runs (no cache) after 2 warmups.

  The knip v6 column is the primary comparison. knip v6 is faster than knip v5 on every project that both can load, except preact. Fallow's lead over knip v5 is wider on the small and mid-size projects (for example 13.7x on fastify, 13.0x on zod, 10.3x on preact).

  fallow is fastest on small and mid-size projects (fastify, preact, query, svelte, zod). On the large projects astro and TypeScript, knip v6 with its Oxc parser is faster. There, fallow's advantage is that one tool does more. Fallow's persistent cache makes repeat (warm) runs faster again. The table uses the more conservative cold numbers.

  ¹ Current knip (both v5 and v6) exits without valid output on next.js, vite, and vue/core. To read plugin settings, knip loads and executes the project's own config and JSON files. This works well on apps, but fails on a few framework monorepos. Fallow reads files syntactically and executes no config, so it completes on these projects with no setup.

  - **vite**: a workspace `package.json` starts with a UTF-8 BOM, and knip's `JSON.parse` call rejects it. You can report this gap upstream. Fallow removes BOMs.
  - **vue/core**: a private `sfc-playground/vite.config.ts` fails to load.
  - **next.js**: the Next.js monorepo needs a build for its jest config. Its packages that publish from `dist` need entry config per workspace. This repo is the framework source, not a Next.js app, and the knip Next.js plugin targets apps.

  knip config can fix all three. Fallow needs no config.
</Info>

### Why fallow is faster

| Factor | Fallow | knip |
|:-------|:-------|:-----|
| Language | Compiled Rust binary | Node.js runtime |
| Parser | Oxc (native Rust) | Oxc via NAPI bindings |
| Parallelism | rayon work-stealing across all cores | Single-threaded |
| Startup | Instant (no JIT warmup) | Node.js bootstrap + module loading |
| Memory | Flat contiguous data structures | GC-managed heap |

### Memory and large codebases

Fallow stores graph edges in flat arrays and resolves imports in parallel without locks, so it handles large monorepos well. Memory use grows linearly with the file count, not with the Node.js GC heap.

## Detection capabilities

<Tabs>
  <Tab title="Comparison table">
    | Capability | Fallow | knip |
    |:-----------|:------:|:----:|
    | Unused files | Yes | Yes |
    | Unused exports | Yes | Yes |
    | Unused types | Yes | Yes |
    | Unused dependencies | Yes | Yes |
    | Unused devDependencies | Yes | Yes |
    | Unused enum members | Yes | Yes |
    | Unused class members | Yes | No (dropped in v6) |
    | Unresolved imports | Yes | Yes |
    | Unlisted dependencies | Yes | Yes |
    | Duplicate exports | Yes | Yes |
    | Code duplication | Yes (`fallow dupes`) | No |
    | Circular dependencies | Yes | Yes |
    | Complexity hotspots | Yes (`fallow health`) | No |
    | Architecture boundary violations | Yes | No |
    | Feature flag detection | Yes (`fallow flags`) | No |
    | CRAP score thresholds (`--max-crap`) | Yes | No |
    | Runtime coverage (paid runtime intelligence) | Yes (`--runtime-coverage`) | No |
    | TS namespace declaration members | No | Yes (new in v6) |
  </Tab>
  <Tab title="Details">
    **fallow extras:**
    - **Unused class members**: knip removed class member detection in v6. Fallow keeps it, with heuristics for code that uses the whole object (`Object.values`, `Object.keys`, `for..in`, spread, computed access).
    - **Code duplication**: the built-in `fallow dupes` command has four detection modes (strict, mild, weak, semantic), groups clones into families, and suggests refactorings. You do not need a separate tool such as jscpd.
    - **Circular dependencies**: fallow finds cycles in the module graph. knip also detects circular dependencies.
    - **Namespace import narrowing**: after `import * as ns from './x'`, a use such as `ns.foo` or `const { foo } = ns` marks only the accessed exports as used. Fallow uses `oxc_semantic` to find import bindings that the code never reads, with scope awareness. Such an import does not count as a reference.
    - **Complexity hotspots**: `fallow health` reports, for each function, the cyclomatic and cognitive complexity, the CRAP (Change Risk Anti-Patterns) score with optional Istanbul coverage, and the unit size. It also gives a composite health score. `--max-crap`, `--max-cyclomatic`, and `--max-cognitive` fail CI above a threshold.
    - **Architecture boundary violations**: you declare import rules between packages or layers in config. Fallow reports each import that crosses a defined boundary.
    - **Feature flag detection**: `fallow flags` finds feature flag patterns and correlates them with dead code. It outputs SARIF, markdown, JSON, or MCP.
    - **Runtime coverage (paid runtime intelligence)**: fallow merges V8 runtime samples with the static graph. You see hot and cold paths, and health weighted by runtime use. A single local capture is free. Continuous or multi-capture monitoring needs a license.

    **knip extras:**
    - **TS namespace declaration members**: new in v6. knip detects unused members of TypeScript `namespace` declarations (the `namespace Foo { export const bar }` syntax).
  </Tab>
</Tabs>

## Plugin coverage

| Capability | Fallow | knip |
|:-----------|:-------|:-----|
| Built-in catalogue | Major frameworks and tools | Broader niche and legacy coverage |
| Config parsing | Supported where configuration affects entry points or usage | Supported |
| Custom plugin support | Yes (JSONC, JSON, TOML, or inline) | Yes (JS functions) |

knip has more plugins, mostly for niche and legacy tools. Fallow covers all major frameworks and the most popular tools in each category.

<Tabs>
  <Tab title="Shared coverage">
    Both tools have plugins for: Next.js, Nuxt, Remix, SvelteKit, Gatsby, Astro, Angular, NestJS, Vite, Webpack, Rollup, Vitest, Jest, Playwright, Cypress, Storybook, ESLint, Biome, TypeScript, Babel, Tailwind, PostCSS, Prisma, Turborepo, Nx, semantic-release, and many more.
  </Tab>
  <Tab title="Fallow-only plugins">
    Rspack, Rsbuild, Rolldown, Tsdown, Drizzle, Knex, Kysely, TypeORM, Wrangler (Cloudflare), Expo, React Native, Electron, i18next, Parcel, Oxlint, SWC, WebdriverIO, Cucumber, lefthook, Docusaurus, Capacitor, typedoc, c8/nyc, markdownlint, Remark, and others.
  </Tab>
  <Tab title="Knip-only plugins">
    knip also covers tools such as Wireit, GitHub Actions, Netlify, and other niche integrations. The [knip plugin list](https://knip.dev/reference/plugins) has the full list.
  </Tab>
</Tabs>

<Info>
  If fallow has no plugin for a framework in your project, [create a custom plugin](/frameworks/custom-plugins) in JSONC, JSON, or TOML. You do not write code.
</Info>

## Features fallow has that knip doesn't

<CardGroup cols={2}>
  <Card title="Baseline comparison" icon="code-compare">
    Adopt fallow in CI step by step with `--save-baseline` and `--baseline`. CI fails only on new issues, not on existing ones.
  </Card>
  <Card title="Inline suppression" icon="comment-slash">
    Suppress one line or one file with `// fallow-ignore-next-line` and `// fallow-ignore-file` comments. You do not change the config.
  </Card>
  <Card title="Code duplication" icon="clone">
    The built-in `fallow dupes` has four detection modes, clone family grouping, cross-language matching, and refactoring suggestions.
  </Card>
  <Card title="Complexity and health score" icon="heart-pulse">
    `fallow health` reports cyclomatic and cognitive complexity, CRAP score, risk profiles, and a composite health score. `--max-crap`, `--max-cyclomatic`, and `--max-cognitive` fail CI when a function goes above a threshold.
  </Card>
  <Card title="Architecture boundaries" icon="shield">
    Enforce import rules between packages or layers. Boundary violations fail the build, and you do not need ESLint plugins.
  </Card>
  <Card title="Feature flag detection" icon="flag">
    `fallow flags` finds feature flag patterns in the codebase and cross-references them with dead code. It exports to SARIF, markdown, and MCP.
  </Card>
  <Card title="Combined audit" icon="clipboard-check">
    `fallow audit` runs dead code, health, duplication, and styling analysis and gives one verdict. Each analysis can have its own baseline (`--dead-code-baseline`, `--health-baseline`, `--dupes-baseline`).
  </Card>
  <Card title="Standalone rule explainer" icon="circle-question">
    [`fallow explain <issue-type>`](/cli/explain) prints the reason for a rule, a worked example, fix guidance, and the docs URL. It does not run an analysis. knip has no equivalent. The closest tools are Credo (`mix credo explain`) for Elixir and Biome's build-time diagnostic explainer. Only fallow has a standalone CLI subcommand and an MCP tool (`fallow_explain`) that agents can call before they fix a finding.
  </Card>
  <Card title="Git-aware analysis" icon="code-branch">
    Limit the analysis to changed files with `--changed-since <ref>`, or to changed workspaces in a monorepo with `--changed-workspaces <ref>`. Use this for CI checks on PRs only.
  </Card>
  <Card title="Auto-fix dry run" icon="wand-magic-sparkles">
    Preview all fixes with `fallow fix --dry-run` before you apply them. Use the JSON output to review the fixes in a script.
  </Card>
  <Card title="Trace and debug tooling" icon="magnifying-glass">
    Use `--trace FILE:EXPORT` to follow how an export is used, `--trace-file PATH` for the edges of a file, `--trace-dependency PACKAGE` for the use of a dependency, and `--performance` for pipeline timing.
  </Card>
  <Card title="CSS Modules tracking" icon="paintbrush">
    fallow reads class names in `.module.css` and `.module.scss` files as named exports, and tracks them through `styles.className` member accesses.
  </Card>
  <Card title="MCP server" icon="robot">
    The built-in `fallow-mcp` gives AI agents `analyze`, `find_dupes`, `check_health`, `audit`, `check_runtime_coverage`, and more as typed tools.
  </Card>
  <Card title="Claude Code hooks" icon="hammer">
    `fallow hooks install --target agent` installs a `PreToolUse` gate. The gate blocks `git commit` and `git push` when `fallow audit` fails, and gives the agent structured output that it can act on.
  </Card>
</CardGroup>

Other features:

- **TOML configuration**: in addition to JSONC and JSON, fallow reads `fallow.toml` for teams that prefer TOML.
- **Cross-reference analysis**: `fallow dead-code --include-dupes` finds dead code that is also duplicated. These are high-priority cleanup targets.

## When to choose fallow

<CardGroup cols={2}>
  <Card title="Speed matters" icon="gauge-high">
    In a large codebase, analysis in under a second makes watch mode and fast CI feedback possible.
  </Card>
  <Card title="CI pipelines" icon="circle-check">
    Use SARIF for GitHub Code Scanning, baselines to adopt fallow step by step, and `--changed-since` to check only what a PR changes.
  </Card>
  <Card title="Dead code + duplication" icon="layer-group">
    Replace both knip and jscpd with one tool. Cross-reference dead code with duplication to decide what to clean up first.
  </Card>
  <Card title="Gradual adoption" icon="stairs">
    Severity rules per issue type (`error`, `warn`, `off`) and inline suppression comments let teams adopt fallow step by step.
  </Card>
  <Card title="AI-assisted development" icon="robot">
    Your team uses AI coding agents. Fallow gives them `--format json` on the CLI, an MCP server for typed tool calls, and `--changed-since` to check only what a PR changes.
  </Card>
</CardGroup>

## When to choose knip

<CardGroup cols={2}>
  <Card title="Niche plugins" icon="puzzle-piece">
    Your project depends on a tool that only knip has a plugin for, and a custom plugin is not worth the effort.
  </Card>
  <Card title="Already working well" icon="thumbs-up">
    knip is already set up and its speed is not a problem. Then you have no reason to migrate.
  </Card>
  <Card title="Custom reporters" icon="code">
    You need JavaScript reporter functions to format the output.
  </Card>
</CardGroup>
