Your stylelint config mixes two kinds of rules. Some rules check the form of each stylesheet, such as hex colors and class names. Other rules limit the selectors, such as no id selectors or a maximum nesting depth. You want fallow to check the selectors too, without a second list of limits to keep in step. `fallow migrate` reads the selector rules of your stylelint config and turns on the matching fallow [styling](/analysis/styling) checks.

Fallow does not replace stylelint. Stylelint keeps its formatting, naming, ordering and syntax rules. Fallow adds checks across the project, such as unused styling and broken references.

## Before you start

- A stylelint config in the project root. Fallow uses the first file of this list: `.stylelintrc`, `.stylelintrc.json`, `.stylelintrc.jsonc`, `stylelint.config.js`, `stylelint.config.cjs`, `stylelint.config.mjs`. Without such a file, fallow reads the `stylelint` field of `package.json`.
- No fallow config file in the project. `fallow migrate` does not overwrite one.

Fallow does not run a JavaScript config. It reads the text from the first `{` to the last `}` as one object. A config with `require()`, variables or a spread does not parse, and the command exits with code 2. A `{` before the object, for example in a `@type` comment, also stops the parse. Then give fallow a JSON copy with `--from`.

## What maps to what

Each selector rule maps to one fallow rule. Each other rule stays in stylelint:

| stylelint | fallow |
|:--|:--|
| `max-nesting-depth`, `selector-max-id`, `selector-max-specificity`, `selector-max-class`, `selector-max-attribute`, `selector-max-combinators`, `selector-max-compound-selectors`, `selector-max-type`, `selector-max-universal`, `no-descending-specificity`, `declaration-no-important` | [`css-selector-complexity`](/rules/css-selector-complexity) at `warn`, and `audit.css` and `audit.cssDeep` at `true` |
| Formatting, naming, ordering, vendor prefix and syntax rules, for example `color-hex-length` and `selector-class-pattern` | Nothing. A warning tells you to keep the rule in stylelint. |
| `extends`, `plugins`, `overrides` and other top-level keys | Nothing. Fallow reads only the `rules` object of your own file. |

Fallow maps a rule only when it is on. A rule with the value `null`, `false` or an empty array is off.

## Steps

The steps use the demo project of these docs with the stylesheets of the [Styling](/analysis/styling) page: `src/ui/receipt.css`, `src/ui/ReceiptCard.module.css` and the component that imports them. The project root has this `.stylelintrc.json`:

```json
{ "extends": ["stylelint-config-standard"], "rules": { "selector-max-id": 0, "max-nesting-depth": 2, "color-hex-length": "short", "selector-class-pattern": "^[a-z]+$", "declaration-no-important": null } }
```

1. Preview the config. The command writes no file:

   ```bash
   npx fallow migrate --dry-run
   ```

   ```text
   {
     "$schema": "https://raw.githubusercontent.com/fallow-rs/fallow/main/schema.json",
     // Migrated from .stylelintrc.json
     "audit": {
       "css": true,
       "cssDeep": true
     },
     "rules": {
       "css-selector-complexity": "warn"
     }
   }

   Migrated from: .stylelintrc.json

   Warnings (2):
     [stylelint] `color-hex-length`: color formatting stays in Stylelint (suggestion: leave this rule in Stylelint)
     [stylelint] `selector-class-pattern`: naming conventions stay in Stylelint (suggestion: leave this rule in Stylelint)
   ```

   `selector-max-id` and `max-nesting-depth` turn on `css-selector-complexity`. `declaration-no-important` is `null`, so it is off and adds nothing. The two warnings name the rules that stay in stylelint.

2. Write the config file:

   ```bash
   npx fallow migrate
   ```

   To read one specific file, add `--from config/.stylelintrc.json`.

3. Run the styling analysis:

   ```bash
   npx fallow health --css
   ```

   The `CSS health` section of the report ends with the selector that `css-selector-complexity` reports:

   ```text
   CSS health
     Styling health: ~79 B (CSS quality, scored separately from the code health score)
     2 stylesheets · 5 rules · 20.0% !important · 0 empty · max nesting 0
     src/ui/receipt.css:9  specificity (0,4,5) · complexity 15 · 1 !important · nesting 0
   ```

   Line 9 of `receipt.css` is the long selector with `!important`. The finding has the severity `warn`, so it does not fail the run. The demo run still exits with code 1, because of the complex function `classifyCustomer`.

## What differs

The example shows that fallow turns on its own check, and does not copy your limits:

- Fallow does not copy the limit of a rule. `"selector-max-id": 0` and `"selector-max-id": 2` give the same config. `css-selector-complexity` has its own limits: an id selector, a nesting depth of 3 or more, a `!important`, or a complex selector.
- Rules that `extends` adds, for example from `stylelint-config-standard`, do not count.
- Most plugin rules get no warning, and fallow does not migrate them.
- `css-selector-complexity` is a warning. To fail a run on it, set the rule to `error`.

## Run both tools

Keep stylelint in your lint step. The warnings of the migration list the rules that only stylelint checks. Fallow adds the checks across the project.
