Your dependency-cruiser config holds the import rules of your project: no cycles, no imports across layers, no package that `package.json` does not list. Fallow reports import cycles, imports across [architecture](/analysis/architecture) boundaries, and problems in `package.json` dependencies, so most of these rules have a fallow check. `fallow migrate` does not read a dependency-cruiser config, so you write the fallow config by hand. Most checks need no config at all. Only a `forbidden` rule between directories needs boundary zones.

## Before you start

- A list of the rules in your dependency-cruiser config that you want to keep.
- A fallow [config file](/configuration/overview), or a plan to create one.

## What maps to what

Find each rule of your list in the left column. The right column gives the fallow issue type that reports the same problem:

| dependency-cruiser rule | fallow issue type |
|:--|:--|
| `no-circular` | [`circular-dependency`](/rules/circular-dependency) |
| `no-orphans` | [`unused-file`](/rules/unused-file). See [What differs](#what-differs). |
| `not-to-unresolvable` | [`unresolved-import`](/rules/unresolved-import) |
| `no-non-package-json` | [`unlisted-dependency`](/rules/unlisted-dependency) |
| `not-to-dev-dep` | [`dev-dependency-in-production`](/rules/dev-dependency-in-production) |
| A `forbidden` rule with `from` and `to` paths | [`boundary-violation`](/rules/boundary-violation), with zones in the `boundaries` config |
| `not-to-spec`, `no-deprecated-core`, `not-to-deprecated`, `no-duplicate-dep-types`, `optional-deps-used`, `peer-deps-used` | No built-in issue type. |

## Steps

The steps use the demo project of these docs. It imports `uuid` in `src/services/orders.ts`, and `package.json` does not list it. For the example, `src/lib/format.ts` also gets a `formatSku` function that imports `lookupPrice` from `src/services/catalog.ts`.

1. Run the checks that need no config:

   ```bash
   npx fallow architecture --cycles
   npx fallow dead-code --unresolved-imports --unlisted-deps
   ```

   The demo has no cycle, so the first command prints `✓ No issues found`. The second command reports the package that a `no-non-package-json` rule reports:

   ```text
   ● Unlisted dependencies (1)
     uuid
     Packages imported in code but missing from package.json
     https://fallow.tools/docs/explanations/dead-code/#unlisted-dependencies
   ```

2. Write a zone for each directory of a `forbidden` rule. The two tools state the rule from opposite sides. A dependency-cruiser `forbidden` rule says which imports are not allowed. A fallow boundary rule says which zones a zone can import from, and each other import between zones is a violation. This dependency-cruiser rule forbids imports from `src/lib` and `src/utils` into `src/services`:

   ```json
   {
     "forbidden": [
       { "name": "lib-not-to-services", "severity": "error", "from": { "path": "^src/(lib|utils)" }, "to": { "path": "^src/services" } }
     ]
   }
   ```

   In fallow, the `lib` zone can import no other zone:

   ```jsonc
   // .fallowrc.json
   {
     "boundaries": {
       "zones": [
         { "name": "lib", "patterns": ["src/lib/**", "src/utils/**"] },
         { "name": "services", "patterns": ["src/services/**"] }
       ],
       "rules": [
         { "from": "lib", "allow": [] }
       ]
     }
   }
   ```

3. Run the boundary check:

   ```bash
   npx fallow architecture --boundaries
   ```

## Check the result

The import in `src/lib/format.ts` breaks the rule, so the boundary check reports it and exits with code 1:

```text
● Boundary violations (1)
  src/lib/format.ts:1 → src/services/catalog.ts (lib → services)
  Imports that cross defined architecture zone boundaries
  https://fallow.tools/docs/explanations/dead-code/#boundary-violations

✗ 1 boundary violation (0.03s)
```

Run the same check on a commit where dependency-cruiser reported a violation, and compare the two lists.

## What differs

When the lists do not agree, look for one of these differences:

- Fallow zone patterns are globs, not regular expressions. A file that matches no zone has no restriction. [Boundaries](/configuration/boundaries) shows presets for common layouts and zones for each feature directory.
- A boundary rule matches on the zone of the importing file and the zone of the imported file. The only condition on the kind of import is `allowTypeOnly`, which allows type-only imports from more zones.
- dependency-cruiser reports an orphan when a module has no dependencies in either direction. Fallow reports an unused file when no [entry point](/concepts/entry-points) reaches it. So fallow reports a group of files that only import each other, and does not report an entry point that nothing imports.

## Run both tools for a while

Each tool reads its own config, so you can run both in CI. Fallow does not report `.dependency-cruiser.js`, `.cjs`, `.mjs` or `.json` as an unused file when `dependency-cruiser` is a dependency. When the fallow checks cover your rules, remove dependency-cruiser. To start on a project with existing violations, save a [baseline](/guides/baselines).
