Fallow reports [unused exports](/rules/unused-export) and [unused types](/rules/unused-type), like ts-prune. This guide maps each ts-prune option to a fallow setting. `fallow migrate` does not read a ts-prune config, so you write the fallow config by hand.

## Before you start

- The ts-prune command and options that your scripts and your CI use.

## What maps to what

| ts-prune | fallow |
|:--|:--|
| `npx ts-prune` | `fallow dead-code --unused-exports --unused-types` |
| `-p, --project <path>` | Nothing. Fallow finds the `tsconfig.json` files itself. For type-aware analysis, use `--type-aware-project <path>`. |
| `-i, --ignore <regexp>` | [`ignoreExports`](/reference/config-dead-code#ignoreexports) for export names, or [`ignoreFindings`](/reference/config-dead-code#ignorefindings) for files |
| `-s, --skip <regexp>` | [`ignorePatterns`](/reference/config-files#ignorepatterns) |
| `-e, --error` | Nothing. `unused-export` has the default severity `error`, so the run fails on a finding. |
| `-u, --unusedInModule` | [`ignoreExportsUsedInFile`](/reference/config-dead-code#ignoreexportsusedinfile) set to `true` |
| `// ts-prune-ignore-next` | `// fallow-ignore-next-line unused-export` |
| The `files` of `tsconfig.json` as public API | [`entry`](/reference/config-files#entry). Fallow does not report the exports of an entry file. |

ts-prune options take regular expressions. The fallow settings take globs and export names.

## Steps

1. Run the check:

   ```bash
   npx fallow dead-code --unused-exports --unused-types
   ```

2. Write each ts-prune option of your scripts as the fallow setting of the table.

3. Replace the ts-prune step of your CI with the same command.

## Check the result

Compare the findings with the output of ts-prune. Fallow finds the entry points of frameworks through its [plugins](/concepts/plugins), so an export that a framework loads by convention is not a finding.

## What differs

- Fallow reads the syntax of the code and follows the imports from the entry points. It does not run the TypeScript compiler by default. When a delete depends on exact symbol identity, add `--type-aware`, and fallow confirms each candidate with the TypeScript checker. See [Type-aware analysis](/analysis/type-aware).
- Fallow also reports unused files, unused dependencies, and unused enum and class members. Use filter options, such as `--unused-exports`, to see only the findings that ts-prune reports.
- [`fallow fix`](/cli/fix) can remove unused exports.

## Run both tools for a while

You can run both tools in CI until the lists agree, then remove ts-prune. To start on a project with existing unused exports, save a [baseline](/guides/baselines).
