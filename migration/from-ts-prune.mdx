Your scripts or your CI run ts-prune to list the exports that no file imports, often with options such as `--ignore` or `--skip`. Fallow reports [unused exports](/rules/unused-export) and [unused types](/rules/unused-type) too, so one fallow command replaces the ts-prune step. `fallow migrate` does not read a ts-prune config, so you write each option as a fallow setting by hand. The table below gives the setting for each option.

## Before you start

- The ts-prune command and options that your scripts and your CI use.

## What maps to what

Find each ts-prune option of your scripts in the left column:

| ts-prune | fallow |
|:--|:--|
| `npx ts-prune` | `fallow dead-code --unused-exports --unused-types` |
| `-p, --project <path>` | Nothing. Fallow finds the `tsconfig.json` files itself. For type-aware analysis, use `--type-aware-project <path>`. |
| `-i, --ignore <regexp>` | [`ignoreExports`](/reference/config-dead-code#ignoreexports) for export names, or [`ignoreFindings`](/reference/config-dead-code#ignorefindings) for files |
| `-s, --skip <regexp>` | [`ignorePatterns`](/reference/config-files#ignorepatterns) |
| `-e, --error` | Nothing. `unused-export` has the default severity `error`, so the run fails on a finding. |
| `-u, --unusedInModule` | [`ignoreExportsUsedInFile`](/reference/config-dead-code#ignoreexportsusedinfile) set to `true` |
| `// ts-prune-ignore-next` | `// fallow-ignore-next-line unused-export` |
| The `files` of `tsconfig.json` as public API | [`entry`](/reference/config-files#entry). Fallow does not report the exports of an entry file. |

ts-prune options take regular expressions, and the fallow settings take globs and export names. So write each pattern again: a regular expression such as `\.generated\.ts$` becomes a glob such as `**/*.generated.ts`.

## Steps

1. Run the check:

   ```bash
   npx fallow dead-code --unused-exports --unused-types
   ```

   On the demo project of these docs, the output is:

   ```text
   ● Unused exports (3)
     src/lib/format.ts
       :3 formatPercent
     src/lib/index.ts
       :1 formatPercent (re-export)
     src/services/orders.ts
       :18 cancelOrder
     Exported symbols with no known consumers
     https://fallow.tools/docs/explanations/dead-code/#unused-exports
     To auto-fix: fallow fix --dry-run
     To suppress: // fallow-ignore-next-line unused-export

   ✗ 3 exports (0.29s)
   ```

   `formatPercent` shows two times: once where it is declared, and once in the [barrel file](/concepts/entry-points) `src/lib/index.ts` that exports it again.

2. Write each ts-prune option of your scripts as the fallow setting of the table.

3. Replace the ts-prune step of your CI with the same command. It exits with code 1 on a finding, so the step fails as before.

## Check the result

Compare the findings with the output of ts-prune on the same commit. When ts-prune lists an export and fallow does not, check if a framework loads that export by convention. Fallow finds the entry points of frameworks through its [plugins](/concepts/plugins), so such an export is not a finding.

## What differs

- Fallow reads the syntax of the code and follows the imports from the entry points. It does not run the TypeScript compiler by default. When a delete depends on exact symbol identity, add `--type-aware`, and fallow confirms each candidate with the TypeScript checker. See [Type-aware analysis](/analysis/type-aware).
- Fallow also reports unused files, unused dependencies, and unused enum and class members. Use filter options, such as `--unused-exports`, to see only the findings that ts-prune reports.
- [`fallow fix`](/cli/fix) can remove unused exports.

## Run both tools for a while

You can run both tools in CI until the lists agree, then remove ts-prune. To start on a project with existing unused exports, save a [baseline](/guides/baselines).
