`fallow migrate` reads your knip config and writes a fallow [config file](/configuration/overview) with the same settings. It warns about each setting that it cannot convert.

## Before you start

- A knip config in one of these places: `knip.json`, `knip.jsonc`, `.knip.json`, `.knip.jsonc`, or the `knip` field of `package.json`.
- No fallow config file in the project. `fallow migrate` does not overwrite one.

Fallow finds `knip.ts` and `knip.config.ts`, but it cannot read them. Convert such a file to `knip.json` first.

## What maps to what

| knip | fallow |
|:--|:--|
| `entry` | [`entry`](/reference/config-files#entry). When some patterns have the production marker `!`, the marked patterns go to `entry` and the other patterns go to [`supportEntry`](/reference/config-files#supportentry). |
| `project` | Fallow finds the project files itself. An exclusion with the production marker, such as `!scripts/**!`, becomes a [`production.ignore`](/reference/config-files#production-ignore) pattern. |
| `ignore` | [`ignoreFindings`](/reference/config-dead-code#ignorefindings). The files stay in the analysis. |
| `ignoreDependencies`, `ignoreBinaries` | The same keys. A regular expression becomes a glob when a glob matches the same names. |
| `ignoreExportsUsedInFile` | The same key. |
| `rules`, `include`, `exclude` | [`rules`](/reference/config-rules#rules), with the fallow name of each issue type. `nsExports` and `nsTypes` follow `exports` and `types`. |
| `cycles.allow` | [`circularDependencies.allow`](/reference/config-architecture#circulardependencies-allow). |
| `ignoreDependencies` and `includeEntryExports` of a workspace | [`workspaces.settings`](/reference/config-workspaces#workspaces-settings) for the same workspace path. |
| A plugin section, such as `vitest` | Nothing. The [built-in plugins](/frameworks/built-in) find the config of the tool. |
| `ignoreGlobalBinaries`, `preprocessor`, `compilers` | Nothing. The migration prints a warning. |

## Steps

1. Preview the config. The command writes no file:

   ```bash
   npx fallow migrate --dry-run
   ```

   For this `knip.json`:

   ```json
   {
     "entry": ["src/index.ts!", "scripts/seed.js"],
     "project": ["src/**/*.ts"],
     "ignore": ["src/**/*.generated.ts"],
     "ignoreDependencies": ["^@types/", "^(react|vue)$"],
     "rules": { "types": "warn", "binaries": "off" },
     "vitest": { "config": ["vitest.config.ts"] }
   }
   ```

   the output is:

   ```text
   {
     "$schema": "https://raw.githubusercontent.com/fallow-rs/fallow/main/schema.json",
     // Migrated from knip.json
     "entry": [
       "src/index.ts"
     ],
     "ignoreFindings": [
       "src/**/*.generated.ts"
     ],
     "ignoreDependencies": [
       "@types/*"
     ],
     "rules": {
       "unused-types": "warn",
       "unlisted-binaries": "off"
     },
     "supportEntry": [
       "scripts/seed.js"
     ]
   }

   Migrated from: knip.json

   Warnings (3):
     [knip] `project`: Fallow auto-discovers project files
     [knip] `ignoreDependencies`: regex pattern `^(react|vue)$` skipped (no glob matches the same names) (suggestion: rewrite it as a glob such as `@scope/*`, or add each name)
     [knip] `vitest`: plugin config `vitest` is auto-detected by fallow's built-in plugins (suggestion: remove this section; fallow detects framework config automatically)
   ```

2. Write the config file:

   ```bash
   npx fallow migrate
   ```

   Fallow writes `.fallowrc.json`, or `.fallowrc.jsonc` for a `knip.jsonc`. Add `--toml` to write `fallow.toml`.

3. Read each warning. Add a skipped setting by hand, for example each package name of a skipped regular expression.

4. Run the analysis:

   ```bash
   npx fallow dead-code
   ```

## Check the result

Compare the findings of fallow with the findings of knip. The two tools use different glob engines, so `entry` and `ignoreFindings` can match a few other files. Fallow names each `ignoreDependencies` glob that matches no dependency, so a typo shows.

## What differs

- knip `ignore` also hides dependency findings by file path. Fallow `ignoreFindings` never hides findings that belong to `package.json`, such as unused dependencies.
- Fallow has more issue types, such as duplicate exports and [stale suppressions](/rules/stale-suppression). A finding that knip did not report can be correct.
- A name with the production marker in `ignoreDependencies`, such as `left-pad!`, loses the marker. Fallow ignores the name in each mode.

## Run both tools for a while

`fallow migrate` does not change or delete the knip config. Each tool reads its own config, so you can run both in CI. Fallow does not report `knip` as an unused dev dependency. When the results agree, remove knip and its config.

To start on a project with many findings, save a [baseline](/guides/baselines), so that fallow fails only on new findings.
