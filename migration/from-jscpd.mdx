`fallow migrate` reads your jscpd config and writes the `duplicates` section of a fallow [config file](/configuration/overview). `fallow dupes` then finds the duplicated code. [Duplication](/analysis/duplication) explains how fallow compares code.

## Before you start

- A jscpd config: `.jscpd.json`, or the `jscpd` field of `package.json`.
- No fallow config file in the project. `fallow migrate` does not overwrite one.

## What maps to what

| jscpd | fallow |
|:--|:--|
| `threshold` | [`duplicates.threshold`](/reference/config-duplication#duplicates-threshold) |
| `minTokens` | [`duplicates.minTokens`](/reference/config-duplication#duplicates-mintokens) |
| `minLines` | [`duplicates.minLines`](/reference/config-duplication#duplicates-minlines) |
| `mode` | [`duplicates.mode`](/reference/config-duplication#duplicates-mode) |
| `skipLocal` | [`duplicates.skipLocal`](/reference/config-duplication#duplicates-skiplocal) |
| `ignore` | [`duplicates.ignore`](/reference/config-duplication#duplicates-ignore) |
| `ignoreIdentifiers: true` or `"consistent"` | `duplicates.normalization.ignoreIdentifiers` and `consistentIdentifiers`, both `true` |
| `ignoreIdentifiers: "blind"` | `duplicates.normalization.ignoreIdentifiers: true` |
| `ignoreLiterals: true` | `duplicates.normalization.ignoreStringValues` and `ignoreNumericValues`, both `true` |
| `format` | Nothing. Fallow finds the JavaScript and TypeScript files itself. |
| `maxLines`, `maxSize`, `ignorePattern`, `reporters`, `output`, `gitignore` and the other options | Nothing. The migration prints a warning for each one. For `ignorePattern`, it proposes a [range suppression](/guides/suppress). |

## Steps

1. Preview the config. The command writes no file:

   ```bash
   npx fallow migrate --dry-run
   ```

   For this `.jscpd.json`:

   ```json
   { "threshold": 5, "minTokens": 60, "minLines": 6, "mode": "weak", "ignore": ["**/*.generated.ts"], "ignoreIdentifiers": true, "format": ["typescript"] }
   ```

   the output is:

   ```text
   {
     "$schema": "https://raw.githubusercontent.com/fallow-rs/fallow/main/schema.json",
     // Migrated from .jscpd.json
     "duplicates": {
       "minTokens": 60,
       "minLines": 6,
       "threshold": 5.0,
       "mode": "weak",
       "ignore": [
         "**/*.generated.ts"
       ],
       "normalization": {
         "ignoreIdentifiers": true,
         "consistentIdentifiers": true,
         "ignoreStringValues": false
       }
     }
   }

   Migrated from: .jscpd.json

   Warnings (2):
     [jscpd] `mode`: jscpd's "weak" mode may differ semantically from fallow's "weak" mode. jscpd uses lexer-based tokens while fallow uses AST-based tokens. (suggestion: test with both "weak" and "mild" to find the best match)
     [jscpd] `format`: fallow auto-detects JS/TS files
   ```

2. Write the config file:

   ```bash
   npx fallow migrate
   ```

   Add `--toml` to write `fallow.toml`.

3. Run the analysis:

   ```bash
   npx fallow dupes
   ```

## Check the result

Compare the clone groups of fallow with the result of jscpd. The fallow modes `strict` and `mild` (the default) give the same result, because fallow compares parsed code. To also match copies with other names, try the `semantic` mode:

```bash
npx fallow dupes --mode semantic
```

## What differs

- The fallow `weak` mode ignores the text of strings. When the jscpd config has `mode: "weak"` without `ignoreLiterals: true`, the migration adds `ignoreStringValues: false`, so that strings stay compared.
- Fallow compares parsed code, so comments and formatting never hide a copy.
- An `ignoreIdentifiers` value other than `true`, `false`, `"consistent"` or `"blind"` gets a warning, and the migration skips it.

## Run both tools for a while

`fallow migrate` does not change or delete the jscpd config, so you can run both tools in CI. When the results agree, remove jscpd and its config.
