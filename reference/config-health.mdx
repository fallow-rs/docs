### `mutation.runner` {#mutation-runner}

- Type: `string`
- Default: `"auto"`

The test runner: `auto`, `vitest`, `node-test` or `bun-test`. `auto` detects it from the project.

Allowed values:

- `auto`: Detect the runner from the project: the `vitest` dependency, the test module that the test files import, the `vite-plus` dependency, a Bun file at the root, or a `node --test` script.
- `vitest`: Vitest 4.1 to 5 from the project `node_modules`.
- `node-test`: `node:test` of Node.js 22.18 or later. Each test file runs in its own Node process.
- `bun-test`: `bun test` of Bun 1.4 or later. Each test file runs in its own Bun process.

### `mutation.operators` {#mutation-operators}

- Type: `string[]` (optional)

The operators to use. Unset uses the default set. An opt-in operator runs only when this list or `--operators` names it. `--operators` wins.

Allowed values:

- `arithmetic-operator`: `a + b` to `a - b`, and the other arithmetic pairs.
- `relational-operator`: `a < b` to `a <= b`, and the other relational pairs.
- `logical-operator`: `a && b` to `a || b`, and the reverse.
- `negate-condition`: A condition to its negation.
- `unary-operator`: A unary operator removed or changed.
- `update-operator`: `i++` to `i--`, and the reverse.
- `removed-call`: A call statement removed.
- `return-value`: A return value changed.
- `boolean-literal`: `true` to `false`, and the reverse.
- `string-literal`: A string or template literal emptied or filled.
- `optional-chaining`: `a?.b` to `a.b`.
- `regex-literal`: One token of a regular expression literal changed: an anchor or a quantifier removed, a `{n,m}` range shortened to `{n}`, a character class negated, or a class escape with the opposite case.
- `removed-chain-link`: `z.number().int()` to `z.number()` in a module-level `const` initializer: one call link of a fluent chain removed.
- `block-statement`: Opt-in. The statements of a block or function body removed.
- `array-literal`: Opt-in. `[x]` to `[]`, and `[]` to `["fallow"]`.
- `object-literal`: Opt-in. A non-empty object literal to `{}`.
- `method-expression`: Opt-in. `startsWith` to `endsWith` and the other method pairs, or `s.trim()` to `s`.
- `switch-case`: Opt-in. The statements of a `case` clause removed.
- `call-expression`: Opt-in. A call in an expression position to `void 0`.
- `throw-statement`: Opt-in. A `throw new X(...)` statement removed.
- `regex-constructor`: Opt-in. The regex changes applied to a `new RegExp("...")` pattern.
- `regex-assertion`: Opt-in. A lookaround negated, or `\b` and `\B` swapped.
- `nullish-fallback`: Opt-in. `a ?? b` to `a`.

### `mutation.minScore` {#mutation-minscore}

- Type: `number` (optional)
- Value: at least `0`, at most `100`

The minimum mutation score, from 0 to 100. When the score of a run is lower, `fallow mutation` exits with code 1. Unset never fails a run. `--min-score` wins.

### `mutation.concurrency` {#mutation-concurrency}

- Type: `integer` (optional)
- Value: at least `1`

The number of mutation runner processes. Unset uses half the logical cores. `--concurrency` wins.

### `mutation.mutantsPerLine` {#mutation-mutantsperline}

- Type: `integer` (optional)
- Value: at least `1`

The maximum number of mutants on one source line. The plan keeps the most productive mutants of the line (relational, condition, arithmetic and logical operators first). The others are `pending` with the reason `sampled-out`. Unset keeps each mutant. `--mutants-per-line` wins.

### `mutation.functionScope` {#mutation-functionscope}

- Type: `boolean` (optional)

Widen each changed line to the whole function that holds it, so that a change to a parameter or a signature selects the mutants of the function. Only the changed-code scope uses it. Unset or `false` mutates the changed lines only. `--function-scope` turns it on.

### `mutation.typecheck` {#mutation-typecheck}

- Type: `boolean` (optional)

Type-check each survived mutant through the type-aware companion of `--type-aware`. A survivor that does not type-check becomes `compile_error` and does not count in the score. A survivor that removes an optional-chaining link or a nullish fallback from a receiver whose type excludes `null` and `undefined` gets an advisory `equivalence_hint`. Its status and the score do not change. Unset or `false` checks no survivor. `--typecheck` turns the check on.

### `mutation.runnerConfig` {#mutation-runnerconfig}

- Type: `string` (optional)

The config file of the test runner, relative to the project root, for example `vitest.integration.config.mjs`. The file must exist inside the project root. Only the Vitest runner reads it. Unset uses the default config discovery of the runner. `--runner-config` wins.

### `mutation.runnerProjects` {#mutation-runnerprojects}

- Type: `string[]` (optional)

The names of the Vitest projects that the run uses, as the Vitest `--project` flag selects them, for example `["unit"]`. A name can hold a `*` wildcard. The run then ignores each other project of the config, also a project from a separate config file. Only the Vitest runner reads it. Unset uses each project. `--runner-project` wins.

### `health.maxCyclomatic` {#health-maxcyclomatic}

- Type: `integer`
- Default: `20`
- Value: at most `65535`

Maximum allowed cyclomatic complexity per function (default: 20). Functions exceeding this threshold are reported. Governs findings only; the health score's complexity penalties use fixed calibration (use `health.ignore` to remove a file from the score).

### `health.cyclomaticPolicy` {#health-cyclomaticpolicy}

- Type: `string`

How the cyclomatic gate counts complexity (default: `standard`). `literal-membership` counts a chain of strict equality checks of one identifier against primitive literals (`kind === "a" || kind === "b"`) as one predicate. The policy applies to the `maxCyclomatic` gate and to every CRAP score, so the `maxCrap` gate reads the same value. Findings then report the standard value as `standard_cyclomatic`. The health score, complexity density, and hotspots keep the standard count. Older fallow versions reject this key as unknown, so pair it with `minimumVersion`.

Allowed values:

- `standard`: Count every decision point, `&&`, `||`, and `??` operator (`McCabe`).
- `literal-membership`: Count a literal membership chain as one predicate. A chain such as `kind === "a" || kind === "b" || kind === "c"` adds no cyclomatic increments for its `||` operators. Only strict equality checks of one identifier against string, number, bigint, boolean, or `null` literals qualify. Member access, calls, mixed operators, and different operands keep the standard count.

### `health.maxCognitive` {#health-maxcognitive}

- Type: `integer`
- Default: `15`
- Value: at most `65535`

Maximum allowed cognitive complexity per function (default: 15). Functions exceeding this threshold are reported. Governs findings only, never the health score.

### `health.maxCrap` {#health-maxcrap}

- Type: `number`
- Default: `30`

Maximum allowed CRAP (Change Risk Anti-Patterns) score per function (default: 30.0). CRAP combines cyclomatic complexity with test coverage: high complexity plus low coverage produces a high CRAP score. Functions meeting or exceeding this threshold are reported. Use `--coverage` with Istanbul data for accurate per-function CRAP; otherwise fallow estimates coverage from the module graph. Governs findings and the threshold-relative file-score signals (`crap_above_threshold`, the `risk` triage tag, and the `add_test_coverage` refactoring target); measured values such as `crap_max` and the overall health score never move with it. Set to `0` to disable CRAP enforcement entirely: no findings, nothing counts above threshold, and file-score rows disclose baseline breaches as exempt instead. The `complexity-crap` rule is different: it decides if a finding fails the run, and `off` hides the findings but keeps the file-score signals.

### `health.crapRefactorBand` {#health-craprefactorband}

- Type: `integer`
- Default: `5`
- Value: at most `65535`

Band below `maxCyclomatic` where CRAP-only findings also receive a secondary `refactor-function` action (default: 5). Set to `0` to only suggest refactoring when cyclomatic already meets the configured threshold.

### `health.maxUnitSize` {#health-maxunitsize}

- Type: `integer`
- Default: `60`

Maximum function length in lines of code before it is reported as an oversized "large function" (default: 60). Raise it globally, or per file via `thresholdOverrides[].maxUnitSize`, to relax the bar for generated or test files (where a `describe()` block spans hundreds of lines) without disabling complexity checks on those files. This filters the reported large-functions list only; the descriptive unit-size profile and the health score still reflect raw sizes against fixed calibration (the `unit_size` penalty keeps its `>60` LOC very-high-risk edge so grades stay comparable across projects; use `health.ignore` to remove a file from the score entirely).

### `health.maxFileLines` {#health-maxfilelines}

- Type: `integer`

Maximum file length in physical lines before the file is reported as a complexity finding with `exceeded: "file_lines"` (default: `0`, off). Every line counts, also blank lines and comment lines. A final newline does not add a line. Set a limit such as `500` to enable the check, and raise it per file via `thresholdOverrides[].maxFileLines`. The `complexity-file-lines` rule decides if a finding fails the run. In `fallow audit`, a long file that did not grow stays inherited. Older fallow versions reject this key as unknown, so pair it with `minimumVersion`.

### `health.coverage` {#health-coverage}

- Type: `string` (optional)

Path to Istanbul coverage data (`coverage-final.json`) or raw V8 coverage (a `NODE_V8_COVERAGE` directory or one V8 JSON file) for accurate per-function CRAP scores. A relative path is taken from the project root. A relative or absolute path may name a file up to the project scope base (the git top level of the root); use the CLI flag for a file outside the project. The CLI `--coverage` flag and `FALLOW_COVERAGE` environment variable override this value. Consulted by `fallow health`, bare `fallow`, `fallow audit`, `fallow viz`, and the MCP `audit` / `check_health` tools.

### `health.coverageRoot` {#health-coverageroot}

- Type: `string` (optional)

Absolute prefix to strip from Istanbul file paths before CRAP matching. Use when coverage was generated under a different checkout root in CI or Docker. The CLI `--coverage-root` flag and `FALLOW_COVERAGE_ROOT` environment variable override this value. Consulted by `fallow health`, bare `fallow`, `fallow audit`, `fallow viz`, and the MCP `audit` / `check_health` tools.

### `health.ignore` {#health-ignore}

- Type: `string[]`
- Default: `[]`

Glob patterns to exclude from complexity analysis. A single `*` stays within one path segment; use `**` to match across directories.

### `health.tailwindIgnorePatterns` {#health-tailwindignorepatterns}

- Type: `string[]`

Regular expressions excluding Tailwind arbitrary-value utilities from token-drift findings and analytics, including CVA variants. Matches the normalized `prefix-[value]` token, without variants, negative signs, or suffix modifiers. Both `-mt-[7px]` and `mt-[7px]` match as `mt-[7px]`; `bg-[#abc]/50` matches as `bg-[#abc]`. These spellings cannot be excluded independently. Use `^icon-\[` to exclude Iconify tokens, including variants. Defaults to no exclusions. Invalid regexes fail config loading.

#### `health.ownership.botPatterns` {#health-ownership-botpatterns}

- Type: `string[]`
- Default: `["*\\[bot\\]*","dependabot*","renovate*","github-actions*","svc-*","*-service-account*"]`

Glob patterns that identify bot or service-account commits to exclude from ownership signals. A pattern matches the local part of the author email or the full author value. Overrides the defaults entirely when set.

#### `health.ownership.emailMode` {#health-ownership-emailmode}

- Type: `string`
- Default: `"handle"`

Privacy mode for emitted author emails. Defaults to `handle`. Override on the CLI via `--ownership-emails=raw|handle|anonymized`. The legacy spelling `hash` is still accepted for compatibility.

Allowed values:

- `raw`: Show the raw email address as it appears in git history. Use for public repositories where history is already exposed.
- `handle`: Show the local-part only (before the `@`). Mailmap-resolved where possible. Default. Balances readability and privacy.
- `anonymized`: Show a stable `xxh3:<16hex>` pseudonym derived from the raw email. Non-cryptographic; suitable to keep raw emails out of CI artifacts (SARIF, code-scanning uploads) but not as a security primitive: a known list of org emails can be brute-forced into a rainbow table. Use in regulated environments where even local-parts are sensitive.
- `hash`: Older spelling of `anonymized`.
