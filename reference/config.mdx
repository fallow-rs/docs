The config file holds the settings of fallow. [How config works](/configuration/overview) explains where fallow finds the file and how files merge.

## Files and entry points {#files}

| Key | Type | Description |
|:--|:--|:--|
| [`$schema`](/reference/config-files#schema) | `string` | A string pointing at fallow's JSON Schema URL, used only by editors for autocomplete and validation of the config file; it has no effect on analysis, and fallow does not write it back when it saves a config. |
| [`minimumVersion`](/reference/config-files#minimumversion) | `string` | The lowest fallow version this config is written for, as `MAJOR.MINOR.PATCH`. |
| [`extends`](/reference/config-files#extends) | `string or string[]` | A single parent config source, or an ordered array of them, to inherit before this file's own keys apply; each source is a file-relative path, an `npm:<package>` specifier, or an `https://` URL (`http://` is rejected), deep-merged in order so objects merge field-by-field while arrays and scalars in this file replace the parent's, with a cycle guard and a depth limit of 10 levels. |
| [`entry`](/reference/config-files#entry) | `string[]` | An array of project-root-relative glob patterns whose matching files are seeded as manual entry points, on top of the framework and `package.json` entries fallow discovers automatically, so their transitive imports are not reported as unused. |
| [`ignorePatterns`](/reference/config-files#ignorepatterns) | `string[]` | An array of project-root-relative glob patterns for files to exclude from analysis entirely; entries are unioned with fallow's built-in defaults (\*\*/node_modules/\*\*, \*\*/dist/\*\*, \*\*/build/\*\*, \*\*/.git/\*\*, \*\*/coverage/\*\*, \*\*/\*.min.js, \*\*/\*.min.mjs, \*\*/\*.min.cjs, \*\*/\*.bundle.js, and the root fallow-viz.html that fallow viz writes), so custom globs add to rather than replace them. |
| [`supportEntry`](/reference/config-files#supportentry) | `string[]` | An array of project-root-relative glob patterns whose matching files are support entry points: dev scripts, tooling and setup files that run outside production. |
| [`resolve`](/reference/config-files#resolve) | `object` | Configures the module resolver. |
| [`production`](/reference/config-files#production) | `boolean or object` | Enables production mode, which excludes test/spec/story/dev files from discovery and forces `unused-dev-dependencies` and `unused-optional-dependencies` to `off`. |
| [`dynamicallyLoaded`](/reference/config-files#dynamicallyloaded) | `string[]` | An array of project-root-relative glob patterns for files loaded at runtime by a mechanism the static graph cannot see (dynamic path resolution, config-driven loading); matching files are seeded as entry points so they and their imports stay reachable. |
| [`markupExtensions`](/reference/config-files#markupextensions) | `string[]` | An array of file extensions, without the leading dot, for server-side template files whose text counts as CSS class references for the `unreferenced-css-class` finding of `fallow health --css`. |
| [`codeowners`](/reference/config-files#codeowners) | `string` | A path to a CODEOWNERS file, relative to the project root or absolute, that must resolve inside the project scope base (the git top level of the root), used by `--group-by owner` and `--group-by section` to group findings, and by `fallow health --hotspots --ownership` to attribute declared owners and compute unowned/drifting ownership state; setting it overrides the default probe order (CODEOWNERS, .github/CODEOWNERS, .gitlab/CODEOWNERS, docs/CODEOWNERS). |
| [`publicPackages`](/reference/config-files#publicpackages) | `string[]` | An array of internal workspace package names (or globs matched against workspace package names) whose public API is intentionally consumed outside the analyzed graph; their entry points and re-export surface become reachability roots, so their exported files, the exports on that surface, and the class and enum members of a class or enum on that surface are not reported as unused. |
| [`sealed`](/reference/config-files#sealed) | `boolean` | When true, restricts this config's extends entries to file-relative paths that resolve inside the config file's own directory; any https:// URL, npm: package, or relative path escaping that directory is rejected at load with a hard error. |
| [`includeEntryExports`](/reference/config-files#includeentryexports) | `boolean` | When true, fallow checks the exports of every entry-point file for unused exports. |
| [`autoImports`](/reference/config-files#autoimports) | `boolean` | When true, drops Nuxt convention-based entry-pattern fallbacks so genuinely-unreferenced convention files surface as unused-file. |
| [`failOnParseError`](/reference/config-files#failonparseerror) | `boolean` | When true, the run fails with exit code 1 if fallow could not parse a source file cleanly (a `source-parse-degraded` or `source-nesting-too-deep` entry in `workspace_diagnostics[]`), and the `parse-error` entry of `gate_outcomes` names each such file. |
| [`cache`](/reference/config-files#cache) | `object` | Overrides the location and size ceiling of fallow's persistent extraction cache (default `.fallow/cache.bin` under the project root). |

## Dead code and dependencies {#dead-code}

| Key | Type | Description |
|:--|:--|:--|
| [`ignoreFindings`](/reference/config-dead-code#ignorefindings) | `string[]` | An array of project-root-relative glob patterns whose source-owned dead-code findings are hidden after analysis without excluding matching files from discovery, parsing, resolution, or the module graph. |
| [`ignoreDependencies`](/reference/config-dead-code#ignoredependencies) | `string[]` | A list of package names or package-name globs excluded from both unused-dependency and unlisted-dependency detection, so a runtime-provided or otherwise-untracked package (e.g. `bun:sqlite`, a peer supplied at deploy time) is never flagged as unused when declared nor as unlisted when imported. |
| [`ignoreBinaries`](/reference/config-dead-code#ignorebinaries) | `string[]` | A list of binary names or name globs that the `unlisted-binaries` rule does not report. |
| [`ignoreCommandEntries`](/reference/config-dead-code#ignorecommandentries) | `string[]` | A list of command names whose file arguments fallow does not make entry points. |
| [`ignoreUnresolvedImports`](/reference/config-dead-code#ignoreunresolvedimports) | `string[]` | A list of glob patterns that suppress only `unresolved-import` findings whose raw import specifier matches; it does not change dependency usage accounting or resolver behavior. |
| [`ignoreExports`](/reference/config-dead-code#ignoreexports) | `object[]` | A list of per-file rules that exempt named exports from `unused-export` and from duplicate-exports grouping for files matching a glob. |
| [`ignoreCatalogReferences`](/reference/config-dead-code#ignorecatalogreferences) | `object[]` | A list of rules that suppress `unresolved-catalog-reference` findings (a workspace `package.json` referencing a `catalog:` or `catalog:<name>` that the catalog does not declare); config-only because `package.json` has no inline-suppression comment surface. |
| [`ignoreDependencyOverrides`](/reference/config-dead-code#ignoredependencyoverrides) | `object[]` | A list of rules that suppress `unused-dependency-override` and `misconfigured-dependency-override` findings for override entries: pnpm `overrides` in `pnpm-workspace.yaml` or `package.json`, npm and bun `overrides`, and bun `resolutions`; config-only, matched against the override's target package. |
| [`ignoreExportsUsedInFile`](/reference/config-dead-code#ignoreexportsusedinfile) | `boolean or object` | Controls whether an export referenced only by another symbol in the same file is treated as used (suppressed from `unused-export`) until it becomes completely unreferenced; references inside an export specifier itself (`export { foo }`, `export default foo`) do not count as same-file uses. |
| [`keepExportTags`](/reference/config-dead-code#keepexporttags) | `string[]` | The JSDoc visibility tags that keep an export out of `unused-export`: `public` (also `@api public`), `internal`, `alpha` and `beta`, with or without a leading `@`. |
| [`ignoreDecorators`](/reference/config-dead-code#ignoredecorators) | `string[]` | A list of decorator names that no longer grant a class member automatic exemption from `unused-class-member`: a member whose every decorator is in this set is checked normally, while a member carrying any decorator NOT listed here stays skipped (frameworks consume decorated members reflectively). |
| [`usedClassMembers`](/reference/config-dead-code#usedclassmembers) | `(string or object)[]` | A list of class-member names or glob patterns treated as framework-used, so a method a library invokes reflectively (ag-Grid `agInit`/`refresh`, Web Component `connectedCallback`) is not reported as `unused-class-member`; it applies to class members only, not enum members. |
| [`unusedComponentProps`](/reference/config-dead-code#unusedcomponentprops) | `object` | Options for the `unused-component-props` rule. |
| [`effect`](/reference/config-dead-code#effect) | `object` | Options for projects that use the Effect library. |
| [`sharedStateAllowlist`](/reference/config-dead-code#sharedstateallowlist) | `string[][]` | Global slots that `fallow architecture --shared-state` leaves out of its inventory. |
| [`fix`](/reference/config-dead-code#fix) | `object` | Configures `fallow fix` behavior. |

## Rules and gates {#rules}

| Key | Type | Description |
|:--|:--|:--|
| [`rules`](/reference/config-rules#rules) | `object` | Sets per-issue-type severity, keyed by kebab-case rule id: `error` reports and fails CI (non-zero exit), `warn` reports without failing, `off` disables detection and reporting entirely (e.g. `{ "unused-files": "error", "unused-exports": "warn", "private-type-leaks": "off" }`). |
| [`overrides`](/reference/config-rules#overrides) | `object[]` | An ordered list of per-file rule-severity overrides: each entry re-severities specific analysis rules for files its globs match, layered on top of the top-level `rules` defaults. |
| [`regression`](/reference/config-rules#regression) | `object` | Holds a saved issue-count baseline that the `--fail-on-regression` gate compares the current run against, failing only when counts grow beyond tolerance relative to the baseline. |
| [`audit`](/reference/config-rules#audit) | `object` | Sets in-repo defaults for `fallow audit` (the changed-files quality gate) so CLI flags need not repeat per run. |
| [`showCascade`](/reference/config-rules#showcascade) | `boolean` | When true, the report keeps the unused exports, unused types, unused class members and unused enum members of a file that is an unused file. |
