To try fallow without an install, run it with `npx`:

```bash
npx fallow
```

If you use fallow often, install it globally.

<Tabs>
  <Tab title="npm (recommended)">
    The npm package has prebuilt binaries for macOS, Linux, and Windows. You do not need a Rust toolchain.

    ```bash
    npm install -g fallow
    ```

    <Tip>
      The npm package uses `optionalDependencies` to download the correct binary for your platform automatically.
    </Tip>
  </Tab>

  <Tab title="pnpm">
    ```bash
    pnpm add -g fallow
    ```
  </Tab>

  <Tab title="yarn">
    ```bash
    yarn global add fallow
    ```
  </Tab>

  <Tab title="Cargo">
    Use this option if you already have a Rust toolchain.

    ```bash
    cargo install fallow-cli
    ```
  </Tab>

  <Tab title="Docker">
    Use Docker to run fallow without Node.js, npm, or Rust on the host.

    ```bash
    docker build -t fallow:local https://github.com/fallow-rs/fallow.git#main
    docker run --rm -v "$PWD:/workspace" --user "$(id -u):$(id -g)" fallow:local audit --format json --quiet
    ```

    The image runs fallow once as a CLI against `/workspace`. The `--user` mapping has two effects:

    - Your host user owns the `.fallow/` caches and the generated reports.
    - `fallow audit` can detect the git base. Git's dubious-ownership guard does not block the mounted repository.

    The image includes git, Node.js, npm, and Corepack. Fallow does not install your project dependencies automatically.

    To use Compose, build the image first. Then copy [`examples/docker/compose.yaml`](https://github.com/fallow-rs/fallow/blob/main/examples/docker/compose.yaml) into the target project and run:

    ```bash
    docker compose run --rm fallow audit --format json --quiet
    ```

    <Warning>
    fallow is a one-shot CLI, not a long-running service. In Portainer or other stack tools, use a one-shot run command, or override the command for an interactive shell. Do not deploy it as an always-on service. The container exit code is the fallow exit code, so CI can gate directly on the result of `docker run` or `docker compose run`.
    </Warning>

    On Linux and WSL, the commands above work as written. On Windows outside WSL, pass an absolute project path that Docker Desktop accepts, and keep `/workspace` as the mounted working directory.

    For runtime coverage inventory in a container, pass the container path prefix. The inventory paths then match the paths that the runtime beacon reports:

    ```bash
    docker run --rm -v "$PWD:/workspace" --user "$(id -u):$(id -g)" fallow:local coverage upload-inventory --path-prefix /workspace --format json --quiet
    ```
  </Tab>

  <Tab title="Binary download">
    Download a prebuilt binary from [GitHub Releases](https://github.com/fallow-rs/fallow/releases).

    | Target | Platform |
    |:-------|:---------|
    | `fallow-aarch64-apple-darwin.tar.gz` | macOS Apple Silicon |
    | `fallow-x86_64-apple-darwin.tar.gz` | macOS Intel |
    | `fallow-x86_64-unknown-linux-gnu.tar.gz` | Linux x64 (glibc) |
    | `fallow-aarch64-unknown-linux-gnu.tar.gz` | Linux ARM64 (glibc) |
    | `fallow-x86_64-unknown-linux-musl.tar.gz` | Linux x64 (musl) |
    | `fallow-aarch64-unknown-linux-musl.tar.gz` | Linux ARM64 (musl) |
    | `fallow-x86_64-pc-windows-msvc.zip` | Windows x64 |
    | `fallow-aarch64-pc-windows-msvc.zip` | Windows ARM64 |

    Each release also has a CycloneDX SBOM for each target, named `fallow-<target>.cdx.json`. For example, `fallow-x86_64-unknown-linux-gnu.cdx.json` lists the components of the Linux x64 (glibc) binary. The [`.vex/openvex.json`](https://github.com/fallow-rs/fallow/blob/main/.vex/openvex.json) file in the fallow repository states why fallow is not affected by each advisory that the repository ignores.
  </Tab>
</Tabs>

## Verify

```bash
fallow --version
```

<Check>
  If the command prints a version number, fallow is installed.

## FAQ

<Accordion title="Do I need Node.js or Rust?">
  The npm package needs Node.js 22 or newer, because its `fallow` command is a small Node.js launcher for the native binary. The Cargo install needs a Rust toolchain. The prebuilt binary and the Docker image need neither on the host for the default analysis. Optional features, such as [type-aware analysis](/analysis/type-aware), can have their own requirements.
</Accordion>

<Accordion title="Should I install fallow globally or per project?">
  Both work. A global install puts `fallow`, `fallow-lsp`, and `fallow-mcp` on your `PATH`. A project devDependency (`npm install -D fallow`) pins one version for the whole team and for CI. Then run it with your package manager, for example `npx fallow`. For an MCP client, see the devDependency note in [Agent integration](/integrations/mcp).
</Accordion>

<Accordion title="Why does fallow say that it cannot find the platform binary?">
  The npm package installs the binary for your platform as an optional dependency. An install that skips optional dependencies, or a `node_modules` folder from another operating system, has no matching binary. Run `npm install` again on the host that runs fallow. On Linux, the error message names the detected libc and gives the `npm install` command with the `--os`, `--cpu`, and `--libc` flags.
</Accordion>

<Accordion title="Does fallow need network access after the install?">
  No. The analysis runs on your machine. Telemetry is opt-in and off by default. A local terminal run can check for a newer release in the background. Set `FALLOW_UPDATE_CHECK=off` to turn off that check. See [Telemetry](/explanations/telemetry).
</Accordion>

<Accordion title="How do I check that fallow sees my project correctly?">
  Run `fallow doctor`. It checks the config, the workspaces, the plugins, and the caches, and it runs no analysis. See [`fallow doctor`](/cli/doctor).
</Accordion>
