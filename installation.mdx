To try fallow, you need no install: run `npx fallow` in your project. To give your team and your CI the same version, add fallow as a development dependency. The other options on this page are for machines without Node.js, or for a fixed binary that you download yourself.

Fallow is one native binary for macOS, Linux and Windows. The npm package `fallow` installs the binary for your platform and starts it through a small Node.js launcher.

## Requirements

- The npm package needs Node.js 22 or later.
- The prebuilt binary and the Docker image need no Node.js for the analysis.
- `cargo install` needs a Rust toolchain.

## Run fallow without an install

```bash
npx fallow
```

`npx` downloads the package on the first run. Use this to try fallow. The [first run](/quickstart) starts here.

## Add fallow to your project

Install fallow as a development dependency. Your team and your CI then use the same version.

<Tabs>
  <Tab title="npm">
    ```bash
    npm install --save-dev fallow
    ```
  </Tab>
  <Tab title="pnpm">
    ```bash
    pnpm add --save-dev fallow
    ```
  </Tab>
  <Tab title="yarn">
    ```bash
    yarn add --dev fallow
    ```
  </Tab>
  <Tab title="bun">
    ```bash
    bun add --dev fallow
    ```
  </Tab>
</Tabs>

Run it through your package manager, for example `npx fallow` or `pnpm fallow`. The package has three commands: `fallow`, `fallow-lsp` for editors, and `fallow-mcp` for coding agents.

To install fallow for all projects on your machine, run `npm install -g fallow`.

## Download a prebuilt binary

Download the archive for your platform from [GitHub Releases](https://github.com/fallow-rs/fallow/releases). Each archive holds `fallow`, `fallow-lsp`, `fallow-mcp` and `fallow-similar-code`. Put them in a folder on your `PATH`.

| Archive | Platform |
|:--|:--|
| `fallow-aarch64-apple-darwin.tar.gz` | macOS, Apple Silicon |
| `fallow-x86_64-apple-darwin.tar.gz` | macOS, Intel |
| `fallow-x86_64-unknown-linux-gnu.tar.gz` | Linux x64, glibc |
| `fallow-aarch64-unknown-linux-gnu.tar.gz` | Linux ARM64, glibc |
| `fallow-x86_64-unknown-linux-musl.tar.gz` | Linux x64, musl |
| `fallow-aarch64-unknown-linux-musl.tar.gz` | Linux ARM64, musl |
| `fallow-x86_64-pc-windows-msvc.zip` | Windows x64 |
| `fallow-aarch64-pc-windows-msvc.zip` | Windows ARM64 |

## Install with cargo

```bash
cargo install fallow-cli
```

This installs the `fallow` command. To get the MCP server for coding agents too, run `cargo install fallow-mcp`.

## Run fallow in Docker

Build the image from the fallow repository, then run it on the current folder:

```bash
docker build -t fallow:local https://github.com/fallow-rs/fallow.git#main
docker run --rm -v "$PWD:/workspace" --user "$(id -u):$(id -g)" fallow:local audit --format json --quiet
```

The image runs one fallow command on `/workspace` and exits. The exit code of the container is the exit code of fallow. With `--user`, your user owns the files that fallow writes, and git accepts the mounted repository. The image holds git and Node.js, but it does not install the dependencies of your project. For Docker Compose, copy [`examples/docker/compose.yaml`](https://github.com/fallow-rs/fallow/blob/main/examples/docker/compose.yaml) to your project.

## Check the install

```bash
fallow --version
```

The command prints `fallow` and the version number. In a project that has fallow as a development dependency, run `npx fallow --version`. The npm package then also prints a `verified:` line with the result of the binary check (see the next section).

To check that fallow reads your project correctly, run `fallow doctor`. It checks the config, the workspaces, the plugins and the installed dependencies, and it runs no analysis. See [`fallow doctor`](/cli/doctor).

## Binary verification

Fallow reads all of your source code, so a changed binary is a risk. That is why each release signs its binaries. Before the first run, the npm package checks the Ed25519 signature and the SHA-256 digest of the binary for your platform. It saves the result next to the binary, so later runs skip the check. When the check fails, fallow prints `fallow: binary verification failed`, does not start, and exits with code 1.

The check needs no network access. When the folder of the binary is read-only, the npm package saves the result in a cache folder. Set `FALLOW_VERIFY_CACHE_DIR` to choose that folder. Set `FALLOW_SKIP_BINARY_VERIFY=1` only when you replace the published binary on purpose. The [security policy](https://github.com/fallow-rs/fallow/blob/main/SECURITY.md) describes the trust model.

Each release on GitHub Releases has a CycloneDX SBOM for each platform, named `fallow-<target>.cdx.json`. The OpenVEX document [`.vex/openvex.json`](https://github.com/fallow-rs/fallow/blob/main/.vex/openvex.json) in the fallow repository lists the advisories that do not affect fallow, with the reason for each.

## Update fallow

| Install | Update |
|:--|:--|
| `npx` | `npx fallow@latest` |
| Development dependency | `npm install --save-dev fallow@latest`, or the same command of your package manager |
| Global npm install | `npm install -g fallow@latest` |
| Prebuilt binary | Download the new archive. |
| cargo | `cargo install fallow-cli` |
| Docker | Build the image again. |

The analysis reads only local files. In a local terminal, fallow also checks once a day for a newer release, and prints one line when it finds one. It does not check in CI, with `--quiet` or in a machine format. To turn off this check, set [`FALLOW_UPDATE_CHECK=off`](/configuration/environment#fallow_update_check).

## If fallow does not start

**`Could not find @fallow-cli/...`.** The npm package installs the binary for your platform as an optional dependency. An install that skips optional dependencies, or a `node_modules` folder from another operating system, has no binary for your platform. Run `npm install` again on the machine that runs fallow. On Linux, the message names your C library (glibc or musl) and gives the exact `npm install` command.

**An old Node.js.** The npm package supports Node.js 22 or later. Check with `node --version`. When you cannot update Node.js, use the prebuilt binary.
