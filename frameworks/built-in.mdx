Fallow ships with built-in plugins for popular TypeScript and JavaScript tools. Each plugin teaches fallow about framework-specific conventions: entry points, config files, used exports, and tooling dependencies. Analysis is accurate out of the box.

<Info>
Most plugins activate automatically when the relevant package is in your `package.json`. Some plugins (ESLint, Vitest) also activate when a config file is present in the workspace root, even without the package. This covers monorepos where the tool is installed at the root but workspace packages have their own config files.
</Info>

## Module Federation

Fallow reads `exposes` and `remotes` from `module-federation.config.{ts,js,mjs,cjs,mts,cts}`. It also reads them from a Federation plugin call in a webpack, rspack, rsbuild, vite or `next.config.*` file. The recognised plugin calls are `ModuleFederationPlugin`, `NextFederationPlugin`, `moduleFederationPlugin`, `pluginModuleFederation` and `federation`. Fallow reads such a call wherever it is in the config program. A call counts only when its first argument is an object that declares `exposes` or `remotes`.

- `exposes`: each target becomes a runtime entry point. The exposed module, and everything it reaches, stays out of `unused-file`. Its exports follow [`includeEntryExports`](/configuration/overview#includeentryexports), like the exports of any other entry point. A target that names a bare module request instead of a local path (`"./utils": "shared-utils"`) credits that dependency.
- `remotes`: fallow treats each alias and its subpaths as provided by the remote container, so it does not report `import("checkout/Button")` as an unlisted dependency. The alias holds only under the directory of the config that declared it. A sibling workspace package that declares no remote still reports the dependency.

Fallow reads a plugin call in these positions:

- A nested plugin array, and a plugin list that a variable holds.
- A tool-specific key such as `tools.rspack.plugins`.
- A hook body, such as an rsbuild `appendPlugins` hook or a Next.js `webpack(config)` hook.

Fallow also reads:

- Options that a `const` in the same file holds. The program must hold one binding of that name, and nothing may write to the binding or to one of its members.
- The array form of `exposes`. A string element is both the public name and the module request. An object element uses the object reader.

Fallow does not read:

- `shared`, and the runtime `registerRemotes` and `loadRemote` calls.
- The array form of `remotes`. A bundler derives the request scope of an element from the whole container location, so the alias is not a bare specifier.
- A spread, and a value that is not a static object literal. An array element that holds glob syntax, a nested array, or a value that is not a string.

Fallow reads the config syntactically. It fetches no remote container, and it validates nothing about the remote. The availability of the remote, its exports, its versions and its shared singletons are out of scope.

A declaration that fallow could not read in full reaches the report as a `plugin-config-unreadable` entry in `workspace_diagnostics[]`, and it warns on stderr. The entry names the plugin, the key and the reason, with the config file in `path`. Its `reason` is `not-object-literal`, `array-form`, `spread` or `unreadable-entries`. Read that set as open. The plugin is `module-federation` for a standalone config file. It is `webpack`, `rspack`, `rsbuild`, `vite` or `nextjs` for the options fallow read from that plugin's own config. Two unreadable keys in one file give two entries. The entry carries `degrades_analysis`, so both shipped CI integrations report it under degraded inputs.

```text
fallow: Plugin 'module-federation': `exposes` in 'module-federation.config.ts' is not a static object literal, so the targets are not registered as entry points. Name the exposed files in `dynamicallyLoaded`.
fallow: Plugin 'webpack': `remotes` in 'webpack.config.js' uses the array form, which is not read yet, so the aliases are not treated as provided by a remote container. Name the aliases in `ignoreDependencies`, or declare them as the keys of an object literal, whose values may be computed.
```

Use [`dynamicallyLoaded`](/configuration/overview#dynamicallyloaded) for an exposed file fallow cannot see. [`entry`](/configuration/overview#entry) fits a file that is a project entry point of its own. A remote alias belongs in [`ignoreDependencies`](/configuration/overview#ignoredependencies), which covers more: it also hides unused-dependency findings for that name.
