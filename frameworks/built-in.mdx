Fallow ships with built-in plugins for popular TypeScript and JavaScript tools. Each plugin teaches fallow about framework-specific conventions: entry points, config files, used exports, and tooling dependencies. Analysis is accurate out of the box.

<Info>
Most plugins activate automatically when the relevant package is in your `package.json`. Some plugins (ESLint, Vitest) also activate when a config file is present in the workspace root, even without the package. This covers monorepos where the tool is installed at the root but workspace packages have their own config files.
</Info>

## Module Federation

Fallow reads `exposes` and `remotes` from `module-federation.config.{ts,js,mjs,cjs,mts,cts}`, and from inline plugin options in the top-level `plugins` array of a webpack, rspack, rsbuild, or vite config. The recognised plugin calls there are `ModuleFederationPlugin`, `moduleFederationPlugin`, `pluginModuleFederation`, and `federation`. Both keys are read only as static object literals.

- **`exposes`**: each target becomes a runtime entry point, so the exposed module and everything it reaches stays out of `unused-file`. Its exports follow [`includeEntryExports`](/configuration/overview#includeentryexports) like any other entry point. A target that names a bare module request instead of a local path (`"./utils": "shared-utils"`) is credited as a used dependency.
- **`remotes`**: each alias and its subpaths count as provided by the remote container, so `import("checkout/Button")` is not reported as an unlisted dependency. That holds only under the directory of the config that declared the alias, so a sibling workspace package that declares no remote keeps reporting.

Reading is syntactic. No remote container is fetched and nothing about the remote is validated: its availability, its exports, versions, and shared singletons are all out of scope. `shared` is not read. Neither is the array form of either key, a spread, a non-literal value, or plugin options registered outside the top-level `plugins` array, such as a Next.js `webpack(config)` hook.

A declaration that is present but not readable is named on stderr together with the configuration key that covers the gap:

```text
Plugin 'module-federation': `exposes` in 'module-federation.config.ts' is not a static object literal, so the targets are not registered as entry points. Name the exposed files in `dynamicallyLoaded`.
Plugin 'webpack': `remotes` in 'webpack.config.js' uses the array form, which is not read yet, so the aliases are not treated as provided by a remote container. Name the aliases in `ignoreDependencies`, or declare them as the keys of an object literal, whose values may be computed.
```

Reach for [`dynamicallyLoaded`](/configuration/overview#dynamicallyloaded) for an exposed file fallow cannot see, [`entry`](/configuration/overview#entry) when the file is a project entry point in its own right, and [`ignoreDependencies`](/configuration/overview#ignoredependencies) for a remote alias. `ignoreDependencies` is the broader tool: it also hides unused-dependency findings for that name.
