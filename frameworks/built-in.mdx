A [plugin](/concepts/plugins) tells fallow the conventions of one framework or tool: its entry points, its config files, the exports that it uses and its tool dependencies. Fallow turns a built-in plugin on when the project declares one of its packages, or, for some plugins, when a config file exists. This page lists each built-in plugin.

To see the active plugins of your project, run:

```bash
npx fallow list --plugins
```

```text
Active plugins:
  - vitest
  - typescript
```

When your tool has no plugin, write a [custom plugin](/guides/custom-plugins).

## Notes for some plugins {#plugin-notes}

### Jest {#jest-configs}

The Jest plugin reads each Jest config of a package: `jest.config.*`, `jest-*.config.*` and `jest.*.config.*`. Each config adds its own test patterns. A `--config` file that a script passes to `jest` is also an entry point.

Fallow changes a simple `testRegex` to a glob. For example, `\.integration-spec\.ts$` becomes `**/*.integration-spec.ts`. When fallow cannot change a regex, add the test files to `entry`.

### Nx {#nx-run-commands-targets}

Fallow reads the `command` and `commands` of each `nx:run-commands` target as a script, also in the `configurations` of the target. For example, `tsx scripts/seed.ts` makes `scripts/seed.ts` an entry point. Fallow replaces `{projectRoot}` and `{workspaceRoot}`.

Fallow reads a target only when it runs in the project directory, for example with `cwd` set to `{projectRoot}`. A target without `cwd` in a nested project runs from the workspace root, so fallow skips it.

### TypeORM {#typeorm-migrations}

Fallow reads the `migrations` option of a `DataSource` in `data-source.{ts,js}`, `*.data-source.{ts,js}`, `*.datasource.{ts,js}` and `ormconfig.{ts,js,json}`. Each glob becomes an entry pattern, because TypeORM loads the migrations at run time. When a template selects between two paths, fallow uses the path that starts with `src/`, or changes a `dist/` path to `src/`.

Fallow does not read `entities` and `subscribers`. An entry point for each such file would hide the other unused exports of the file.

### Classes and enums that a library reads by reflection {#classes-and-enums-that-a-library-reads-by-reflection}

Fallow counts each member of a class or an enum as used in these cases:

- An entity class that you give to `getRepository`, `getCustomRepository`, `getTreeRepository`, `getMongoRepository` or `createQueryBuilder`, also as a type argument.
- An entity class that you give to `find`, `findBy`, `findOne`, `findOneBy`, `findOneOrFail`, `findOneByOrFail`, `findAndCount` or `findAndCountBy`, in a file that imports `typeorm`, `@nestjs/typeorm` or a `@mikro-orm/` package.
- An enum that you give to `registerEnumType` of `@nestjs/graphql` or `type-graphql`.

### OpenTelemetry SDK classes {#opentelemetry-sdk-classes}

The OpenTelemetry SDK calls the methods of the classes that you register. Fallow counts these members as used:

| Class | Members that count as used |
|:--|:--|
| `implements Sampler` | `shouldSample`, `toString` |
| `implements SpanProcessor` | `onStart`, `onEnding`, `onEnd`, `shutdown`, `forceFlush` |
| `implements SpanExporter` | `export`, `shutdown`, `forceFlush` |
| `implements PushMetricExporter` | `export`, `forceFlush`, `selectAggregationTemporality`, `selectAggregation`, `shutdown` |
| `extends MetricReader` | `onInitialized`, `onForceFlush`, `onShutdown` |
| `implements LogRecordProcessor` | `onEmit`, `enabled`, `shutdown`, `forceFlush` |
| `implements LogRecordExporter` | `export`, `shutdown`, `forceFlush` |
| `implements ContextManager` | `active`, `with`, `bind`, `enable`, `disable` |
| `implements TextMapPropagator` | `inject`, `extract`, `fields` |
| `implements TextMapGetter` | `keys`, `get` |
| `implements TextMapSetter` | `set` |

### Cloudflare Workers {#cloudflare-durable-objects}

A method call on a Durable Object stub counts as a use of the method of the Durable Object class. Fallow reads the binding types from the `worker-configuration.d.ts` file that `wrangler types` writes. The stub can come from the `env` import of `cloudflare:workers`, from `this.env` in a class that extends a base class of `cloudflare:workers`, or from the `env` parameter of a handler of the type `ExportedHandler<Env>`.

```ts
import { env } from "cloudflare:workers";

export async function join(name: string): Promise<void> {
  // uses Room.join() through the ROOM binding of Env
  await env.ROOM.getByName(name).join();
}
```

A stub at the top level of a module gives no credit: create it in a function body. A handler that names a separate function, as in `{ fetch }`, gets no `env` type.

The Workers runtime calls the handler methods of a class by name. A class that extends a base class of `cloudflare:workers`, also through a chain of local classes, gets credit for these methods:

| Base class | Methods that count as used |
|:--|:--|
| `DurableObject` | `alarm`, `fetch`, `connect`, `webSocketMessage`, `webSocketClose`, `webSocketError` |
| `WorkerEntrypoint` | `email`, `fetch`, `connect`, `queue`, `scheduled`, `tail`, `tailStream`, `test`, `trace` |
| `WorkflowEntrypoint` | `run` |

### Alchemy stacks {#alchemy-stacks}

No project code imports an Alchemy stack file, so fallow uses these files as entry points:

- each `alchemy.run.*` file, at any depth,
- each stack file that a `package.json` script gives to `alchemy deploy`, `dev`, `destroy` or `plan`,
- the bundle entry that a resource names in its `main` property.

A stack runs at deploy time, so a stack file is a support entry. The Worker code that a stack imports stays reachable in [production mode](/concepts/production-mode). Fallow does not report `@effect/platform-node` and `@effect/platform-bun` as unused, because the Alchemy CLI loads them with a dynamic `import()`.

### Webpack {#webpack-config-directories}

Fallow also reads a webpack config under `config/`, `build/` or `webpack/`, when the file exports a webpack configuration: an object with webpack config keys, an array of configurations, or a `webpack-merge` call. Under `build/`, fallow reads only `webpack.<target>.{ts,js,mjs,cjs}`, because that directory also holds build output. A helper file such as `config/webpack.paths.js` that exports no configuration stays reported as unused when nothing imports it.

An entry value that names a package counts as a use of that package. An entry without an extension matches the source file or the directory index.

#### Inline loader requests {#webpack-inline-loader-requests}

An import can name its loaders inline, for example `require('!raw-loader!./shim.js')`. Fallow reads these requests in each project, also without the webpack plugin:

- The request resolves to its last segment (`./shim.js`). Each loader package counts as a used dependency.
- A loader import uses each value export of the resource.
- A text loader (`raw-loader`, `file-loader`, `url-loader` and similar) reads the file as text, bytes or a URL. The resource counts as used, but its own imports do not.
- A worker loader (`worker-loader`, `comlink-loader` and similar) loads the resource like `new Worker(...)`. [`circularDependencies.ignoreLazyImports`](/reference/config-architecture#circulardependencies-ignorelazyimports) skips a cycle through such an import.
- A loader in `module.rules` of a webpack config does not change how fallow reads an import. Its package still counts as used.
- When the resource does not resolve, the unresolved import shows the full request. An `ignoreUnresolvedImports` entry must then use the full request.

### Vite+ {#vite-plus}

Vite+ keeps the config of each tool that it bundles in `vite.config.*`. Fallow reads each block with the rules of that tool:

| Block | What fallow reads |
|:--|:--|
| `test` | The Vitest settings. A `vite-plus` dependency turns the Vitest plugin on. |
| `pack` | Each `entry` value as a runtime entry point. |
| `lint` | The packages of `jsPlugins`, `overrides[].jsPlugins` and `extends`, as used dependencies. |
| `fmt` | Nothing. |
| `staged` | The commands, like a lint-staged config. |
| `run.tasks` | The commands, like `package.json` scripts. A task with `cwd` gives no command. |

The `vp`, `vpr` and `vpx` commands count as uses of `vite-plus`. `vp pack <file>` makes the file an entry point, and `vp test -c <file>` reads the file as a Vitest config.

### Egg.js and tegg {#eggjs-and-tegg}

The Egg loader loads files by directory convention. Fallow makes these files entry points: `app.js`, `agent.js`, `app/router.js` or `app/router/index.js`, the files in `app/controller`, `app/service`, `app/middleware`, `app/schedule` and `app/extend`, and `config/config.*.js` and `config/plugin.*.js`. The same rules apply to a nested app, such as a test fixture app.

tegg loads each source file of a directory whose `package.json` has an `eggModule` key, or that `config/module.json` lists. Fallow makes these files entry points too. A `package` value in `config/plugin.*` counts as a used dependency of the `package.json` that owns the app.

### Module Federation {#module-federation}

Fallow reads `exposes`, `remotes` and `shared` from `module-federation.config.*`, and from a Federation plugin call in a webpack, rspack, rsbuild, vite or `next.config.*` file. Fallow knows these calls: `ModuleFederationPlugin`, `NextFederationPlugin`, `moduleFederationPlugin`, `pluginModuleFederation` and `federation`.

- `exposes`: each target becomes a runtime entry point, so the exposed module is not an unused file.
- `remotes`: fallow does not report an import of a remote alias, such as `import("checkout/Button")`, as an unlisted dependency. The alias applies only below the directory of its config.
- `shared`: each package that the option names counts as used, in the package that owns the config.

Fallow also reads remotes from literal calls of the Federation runtime: `registerRemotes`, `loadRemote`, and the `remotes` option of `init` and `createInstance`.

Fallow reads the config as syntax. It does not fetch a remote container and does not check the remote. When fallow cannot read a declaration, for example a value that is not a static object, it adds a `plugin-config-unreadable` entry to `workspace_diagnostics[]` and prints a warning. Then name the exposed files in [`dynamicallyLoaded`](/reference/config-files#dynamicallyloaded), or the remote aliases in [`ignoreDependencies`](/reference/config-dead-code#ignoredependencies).

#### Trace the Federation source {#trace-the-federation-source}

`--trace-file` on an exposed file lists each config that exposes it. `--trace-dependency` on a remote alias lists each config that declares the alias. The JSON output has a `sources` array for these traces.

### Nuxt {#nuxt}

#### Convention directories {#nuxt-convention-directories}

Fallow scans `plugins/`, `middleware/` and `modules/` one level deep, as Nuxt does. `plugins/bar.ts` and `plugins/foo/index.ts` are entry points. `plugins/foo/helper.ts` is not, so fallow reports it when nothing imports it. A file in the `plugins` list of `nuxt.config` is an entry point at any depth. The `dir.*` settings of `nuxt.config` change these directories.

#### Local layers {#nuxt-local-layers}

A directory is a local layer when it has a `nuxt.config` file, and a `nuxt.config` names it in `extends` by a relative path, or it is under `layers/<name>`. Fallow scans a local layer like the project root: its convention files are entry points, and with [`autoImports`](/reference/config-files#autoimports) on, its components and composables are auto-import sources. Fallow does not scan the files of a remote layer or a package layer. It reads the `modules` of a package layer.

#### Auto-import scope {#nuxt-auto-import-scope}

With [`autoImports`](/reference/config-files#autoimports) on, an auto-import name marks as used only the files of the app that uses it, and of the layers that this app extends. In a monorepo, a `<Card />` in one app does not keep the unused `Card.vue` of another app. Components in `components/global/`, `*.global.vue` files, and, with `@nuxt/content`, the files in `components/content/` stay entry points.

### Storybook {#storybook-stories}

Fallow reads each `stories` pattern of `.storybook/main` relative to the `.storybook/` directory, as Storybook does. A pattern can point into another workspace. Fallow drops a pattern that leaves the project root. Fallow reads the object form `{ directory, files }` and the extglob groups `@(..)`, `?(..)`, `+(..)`, `*(..)` and `!(..)`.
