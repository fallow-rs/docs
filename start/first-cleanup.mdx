On this page, you act on the dead code part of the first report. You check each finding before you remove code. Then you remove the code, with `fallow fix` and by hand, and you see the report get smaller.

## Before you start

- Do the [first run](/quickstart). This page uses the findings of the same demo project.
- Commit your work, or use a copy of the project. `fallow fix` changes your files.

## Check an unused export

Before you remove code, ask fallow why it reports the code. For an export, give the file and the name:

```bash
npx fallow dead-code --trace src/services/orders.ts:cancelOrder
```

```text
  UNUSED cancelOrder in src/services/orders.ts

  File: reachable
  Namespace: value
  Reason: No references found, export is unused
```

The file is [reachable](/concepts/entry-points), but no file imports `cancelOrder`. If a file used the name, the trace would name that file. [Trace a finding](/guides/trace-a-finding) shows the other trace commands.

## Preview the automatic fix

`fallow fix` removes unused exports and unused dependencies. Run it with `--dry-run` first. This changes no files:

```bash
npx fallow fix --dry-run
```

```text
Would remove export from src/lib/index.ts:1 `formatPercent`
Would remove export from src/services/orders.ts:18 `cancelOrder`
Would remove export from src/lib/format.ts:3 `formatPercent`
Would remove `left-pad` from dependencies in package.json
Dry run complete. No files were modified.
```

## Apply the fix

```bash
npx fallow fix --yes
```

```text
Fixed 4 issue(s).
```

`--yes` skips the confirmation prompt. The change in your files:

```diff
--- a/package.json
+++ b/package.json
   "dependencies": {
-    "zod": "^3.23.8",
-    "left-pad": "^1.3.0"
+    "zod": "^3.23.8"
   },
--- a/src/lib/index.ts
+++ b/src/lib/index.ts
-export { formatPrice, formatPercent } from "./format";
+export { formatPrice } from "./format";
 export { parseAmount } from "./parse";
--- a/src/services/orders.ts
+++ b/src/services/orders.ts
-export const cancelOrder = (order: Order): Order => ({ ...order, quantity: 0 });
+const cancelOrder = (order: Order): Order => ({ ...order, quantity: 0 });
```

The fix removes the `export` keyword and keeps the function. The change in `src/lib/format.ts` is the same. If you do not need the function, delete it yourself.

## Delete the unused file

`fallow fix` does not delete files. Check the file first:

```bash
npx fallow dead-code --trace-file src/utils/legacy-currency.ts
```

```text
  UNREACHABLE src/utils/legacy-currency.ts

  Exports (2):
    export toGuilders [unused]
    export fromGuilders [unused]
```

No entry point reaches the file, and no file uses its exports. Delete the file.

## Fix the dependencies

The fix removed `left-pad` from `package.json`. To check a dependency before you remove it, run `npx fallow dead-code --trace-dependency left-pad`.

`uuid` is the opposite case: `src/services/orders.ts` imports it, but `package.json` does not list it. `fallow fix` does not add packages. Add it with your package manager. This also updates the lock file:

```bash
npm install uuid
```

## Run fallow again

```bash
npx fallow
```

```text
■ Metrics: dead files 0.0% (0 of 15) · dead exports 0.0% (0 of 16) · MI 95.6 (good)
  15 files analyzed
  3 entry points detected (2 package.json, 1 plugin)

── Dead Code ──────────────────────────────────────

✓ No issues found (0.06s)
```

The dead code part is clean. The `Failed:` line of the report names the parts that remain:

```text
Failed: dupes (1 clone group), health (1 above threshold): start with src/services/customers.ts
```

To act on them, read [Duplication](/analysis/duplication) and [Health and complexity](/analysis/health).

## When a finding is wrong

Fallow can report code as unused when it cannot see how the code is loaded, for example by a framework or a config file. Do not delete that code: tell fallow about it, as [Handle false positives](/guides/false-positives) shows.

When your project has hundreds of findings, do not fix them in one pass. [Adopt fallow in an existing project](/guides/adopt) shows how to start with new code only.

## What you learned

- A trace tells you why fallow reports a name, a file or a package.
- `fallow fix --dry-run` shows each change. `fallow fix --yes` applies it.
- `fallow fix` removes exports and dependencies. You delete unused files and add missing packages yourself.
