An environment variable sets a value once for each fallow command in a shell, a CI job, the editor or the MCP server. A command-line option wins over the variable, and the variable wins over the config file. [Which setting wins](/configuration/overview#precedence) has the full order.

## Output {#output}

{/* generated:start environment-variables group:output */}

| Variable | Default | Description |
|:--|:--|:--|
| `FALLOW_FORMAT` | `human` | Default output format (json/human/sarif/compact/markdown/codeclimate/gitlab-codequality/pr-comment-github/pr-comment-gitlab/review-github/review-gitlab/badge/github-annotations/github-summary). CLI `--format` flag overrides this. |
| `FALLOW_QUIET` |  | Set to "1" or "true" to suppress progress output. CLI `--quiet` flag overrides this. |
| `FALLOW_UPDATE_CHECK` | `on` | Set to off/0/false to disable the human-TTY upgrade nudge and its background version check. |
| `FALLOW_CLAUDE_CODE_HINT` | `on` | Set to off/0/false/no/disabled to suppress the one-line Claude Code plugin hint on stderr. Fallow writes the hint only inside a Claude Code session (CLAUDECODE or `CLAUDE_CODE_CHILD_SESSION`), for human output without `--quiet`, outside CI, and when no Fallow plugin or skill is set up for the project. Default on. |
| `FALLOW_SUGGESTIONS` | `on` | Set to off/0/false/no/disabled to suppress the next_steps[] array of read-only follow-up commands in JSON output (and the human Next: line). Useful for CI consumers that snapshot-diff raw `--format` json output. Default on. |

{/* generated:end */}

- `FALLOW_SUGGESTIONS=off` removes the `next_steps` array from the JSON output of `fallow`, `dead-code`, `health`, `dupes` and `audit`. Use it when a CI job compares the JSON output with a saved copy. It also turns off the Claude Code hint.

### Update check {#fallow_update_check}

In a terminal, fallow can show one line when a newer version exists. It does not show the line in machine formats, in CI, with `--quiet` or without a terminal. `FALLOW_UPDATE_CHECK=off` turns off the line and the version check. `DO_NOT_TRACK` and `FALLOW_TELEMETRY_DISABLED` also turn them off.

### Color {#no_color-and-clicolor_force}

Fallow writes color only when the output is a terminal. Set `NO_COLOR` to a value that is not empty to turn off color in a terminal. Set `CLICOLOR_FORCE` to a value other than `0` to turn on color in a pipe. `CLICOLOR_FORCE` wins over `NO_COLOR`.

## Analysis {#analysis}

{/* generated:start environment-variables group:analysis */}

| Variable | Default | Description |
|:--|:--|:--|
| `FALLOW_PRODUCTION` |  | Set to true/false to override production mode for all analyses. |
| `FALLOW_PRODUCTION_DEAD_CODE` |  | Set to true/false to override production mode for dead-code analysis. |
| `FALLOW_PRODUCTION_HEALTH` |  | Set to true/false to override production mode for health analysis. |
| `FALLOW_PRODUCTION_DUPES` |  | Set to true/false to override production mode for duplication analysis. |
| `FALLOW_PACKAGE_BASELINES` |  | Set to false, 0, no or off to ignore workspaces.changedSince for every run of the process, like `--no-package-baselines`. |
| `FALLOW_EXTENDS_TIMEOUT_SECS` | `5` | Timeout in seconds for fetching https:// configs referenced via the extends field (default 5). |
| `FALLOW_MAX_FILE_SIZE` | `5` | Per-file size ceiling in megabytes for source discovery (default 5; 0 = no limit). CLI `--max-file-size` flag overrides this. |
| `FALLOW_AUDIT_BASE` |  | Pins the fallow audit comparison base ref when no `--base`/`--changed-since` is passed (e.g. upstream/main). |
| `FALLOW_CLOCK_EPOCH` |  | Reference instant in unix seconds for commit recency and ownership staleness. Default: the committer timestamp of HEAD. Set it to compare two checkouts against one fixed instant. An empty or non-numeric value is ignored with a warning. |

{/* generated:end */}

### Production mode for each analysis {#fallow_production-and-per-analysis-overrides}

`FALLOW_PRODUCTION` sets [production mode](/concepts/production-mode) for each analysis. `FALLOW_PRODUCTION_DEAD_CODE`, `FALLOW_PRODUCTION_HEALTH` and `FALLOW_PRODUCTION_DUPES` set it for one analysis, and win over `FALLOW_PRODUCTION`:

```bash
# Health on production code only, dead code and duplication on all code
FALLOW_PRODUCTION=false FALLOW_PRODUCTION_HEALTH=true fallow --format json --quiet
```

- The order is: the command-line option, the variable for one analysis, `FALLOW_PRODUCTION`, then the `production` key of the config file.
- The values `1`, `true`, `yes` and `on` turn production mode on. The values `0`, `false`, `no` and `off` turn it off. Fallow ignores each other value.

### Audit base {#fallow_audit_base}

`fallow audit` takes its base from `--base`, then from `FALLOW_AUDIT_BASE`, then from Git. Without both, it uses the merge base with the upstream branch, or with `origin/HEAD`, `origin/main` or `origin/master`. Set the variable in these cases:

- On a fork, `origin` can be behind the real project. Set `FALLOW_AUDIT_BASE=upstream/main`.
- The agent hook of `fallow hooks install --target agent` runs `fallow audit` without options. The variable sets its base, and a new install keeps it.

A ref that Git cannot find stops the audit with exit code 2.

## Cache and stored data {#cache}

{/* generated:start environment-variables group:cache */}

| Variable | Default | Description |
|:--|:--|:--|
| `FALLOW_CACHE_DIR` |  | Directory for fallow's persistent analysis cache. Relative paths resolve from the project root and override cache.dir. |
| `FALLOW_CACHE_MAX_SIZE` | `256` | Extraction cache size cap in megabytes (default 256). Wins over the cache.maxSizeMb config field. When the cache file grows past 80 percent of the cap, fallow drops the least recently used entries until the file is below 60 percent. |
| `FALLOW_AUDIT_CACHE_MAX_AGE_DAYS` | `30` | GC threshold in days for reusable audit base-snapshot caches (default 30; 0 disables the sweep). Each cache version keeps only its 32 newest snapshot files. |
| `FALLOW_IMPACT_STORE_MAX_AGE_DAYS` |  | GC threshold in days for per-project fallow impact stores; a recorded run reclaims stores older than this (unset/0 keeps every store forever). |

{/* generated:end */}

- When the cache file grows past 80 percent of `FALLOW_CACHE_MAX_SIZE`, fallow removes the entries of the files that the last run did not read, until the file is at 60 percent.
- `fallow audit` keeps at most 32 base-snapshot files in the cache directory. This limit also applies when `FALLOW_AUDIT_CACHE_MAX_AGE_DAYS` is `0`.
- `FALLOW_IMPACT_STORE_MAX_AGE_DAYS` counts the days since the last change of a store file. Each recorded run rewrites the store of its project, so a project that you use does not expire. Fallow records impact data only outside CI.

### One cache directory for several projects {#fallow_cache_dir}

An absolute `FALLOW_CACHE_DIR` outside the project is one directory for each project that uses it:

- The CLI, the MCP server and the Node.js bindings write the cache files directly into the directory. Use one directory for one project. When two projects share it, each run replaces the cache of the other project.
- The language server writes into one subdirectory for each project root. Two editor windows can share one directory.

## Coverage {#coverage}

{/* generated:start environment-variables group:coverage */}

| Variable | Description |
|:--|:--|
| `FALLOW_COVERAGE` | Path to Istanbul coverage data (`coverage-final.json`) or raw V8 coverage (a `NODE_V8_COVERAGE` directory or one V8 JSON file) for accurate per-function CRAP scores. CLI `--coverage` flag overrides this; it wins over the health.coverage config field. Honored by the health, bare fallow, audit, and viz CLI commands and by the MCP audit and check_health tools on both their typed route and their CLI fallback, where the explicit coverage parameter overrides it. Viz reads it through the same precedence and has no coverage flag of its own. |
| `FALLOW_COVERAGE_ROOT` | Absolute coverage-data path prefix for rebasing Istanbul paths in CI or containers. CLI `--coverage-root` flag overrides this; it wins over the health.coverageRoot config field. Honored by the health, bare fallow, audit, and viz CLI commands and by the MCP audit and check_health tools on both their typed route and their CLI fallback, where the explicit coverage_root parameter overrides it. Viz reads it through the same precedence and has no coverage flag of its own. |
| `FALLOW_COV_BIN` | Path to the runtime coverage add-on (`fallow-cov`). Fallow checks it before every other location. |
| `FALLOW_COV_BINARY_PATH` | Second path to the runtime coverage add-on (`fallow-cov`), checked after `FALLOW_COV_BIN` (air-gapped installs, distro packages, shared Docker images). |
| `FALLOW_RUNTIME_COVERAGE_SOURCE` | Set to cloud to select cloud runtime coverage in fallow coverage analyze without passing `--cloud`. |

{/* generated:end */}

## Type-aware analysis {#type-aware-analysis}

{/* generated:start environment-variables group:type-aware */}

| Variable | Default | Description |
|:--|:--|:--|
| `FALLOW_TYPE_AWARE` |  | Enable or disable TypeScript semantic (type-aware) analysis for the run (true/false/1/0/yes/no/on/off). Precedence: `--type-aware`/`--no-type-aware` CLI flags, then `FALLOW_TYPE_AWARE`, then the audit.typeAware config field, then typeAware.enabled. |
| `FALLOW_TYPE_AWARE_TIMEOUT_SECS` | `120` | Wall clock in seconds allowed for one request to the type-aware companion (default 120; unset, 0, or a non-numeric value keeps the default). Raise it for very large TypeScript programs, where a semantic query scans the whole program. |
| `FALLOW_TYPE_AWARE_BACKEND` | `typescript-go` | Experimental. Type-checker backend for the type-aware companion: typescript-go (default) or tsrs. The tsrs backend needs a tsrs npm package in the supported range of the type-aware protocol manifest, where fallow-type-aware can resolve it. An unknown value makes the type-aware pass unavailable. |
| `FALLOW_TYPE_AWARE_BIN` |  | Trusted executable override for the type-aware companion that `--type-aware` runs. Relative paths resolve from the caller's working directory before `--root` is applied; project node_modules and PATH are intentionally not searched. Default: sibling of the active Fallow executable. |

| Variable | Default | Description |
|:--|:--|:--|
| `FALLOW_REVIEW_GUIDANCE` |  | Set to true to append collapsed guidance blocks to review-github/review-gitlab inline comment bodies. |
| `FALLOW_REVIEW_ID` |  | Stable 1-64 character identifier that isolates inline comments when multiple review jobs target the same PR/MR. |
| `FALLOW_SUMMARY_SCOPE` | `all` | Summary scope for pr-comment-github/pr-comment-gitlab: all (default) keeps project-level dependency/catalog/override findings outside the diff filter; diff applies the diff filter to them too. Inline review comments are unaffected. |
| `FALLOW_PR_COMMENT_LAYOUT` | `default` | Sticky PR comment layout: default, compact, gate-only, or details. |
| `FALLOW_CONSOLIDATED_STATUS` |  | When split PR gate check runs are enabled, truthy values add one aggregate Fallow check alongside the per-gate checks. |
| `FALLOW_DIFF_CONTEXT` | `3` | Line radius around changed diff lines when scoping findings to a diff in the review/PR-comment formats (default 3). |
| `FALLOW_BOT_LOGIN` |  | Allowlisted posting username used to recognize fallow-owned finding roots and resolution replies. When set, it narrows ownership to that exact username (an empty value matches nobody); when unset, provider-native bot metadata is trusted. This is an authorship control, not a lifecycle or deduplication token. |
| `FALLOW_API_RETRIES` | `3` | Maximum HTTP attempts for review-comment reconciliation API calls (default 3). |
| `FALLOW_API_RETRY_DELAY` | `2` | Floor delay in seconds between HTTP retry attempts (default 2); a server-supplied Retry-After overrides it on 429 responses. |
| `FALLOW_ROOT` |  | Project root used by the review-github/review-gitlab renderers to read source for suggestion blocks. Set it alongside `--root` when rendering review formats outside the bundled CI integrations. |

## MCP server {#mcp-server}

Set these variables in the `env` object of the [MCP server](/integrations/mcp) entry of your client.

{/* generated:start environment-variables group:mcp */}

| Variable | Default | Description |
|:--|:--|:--|
| `FALLOW_BIN` |  | Path to the fallow binary that the fallow-mcp server runs. When it is unset, the server runs the `fallow` file next to its own executable, else `fallow` on PATH. |
| `FALLOW_TIMEOUT_SECS` | `120` | MCP server: per-tool-call CLI subprocess timeout in seconds (default 120). Raise for long runs like production coverage on large dumps. |
| `FALLOW_MCP_MAX_OUTPUT_BYTES` | `1000000` | MCP server: response cap in bytes for each tool call (default 1000000, highest 16777216). A larger response is refused with `FALLOW_MCP_SUBPROCESS_OUTPUT_LIMIT` and a narrow list of parameters. The max_output_bytes parameter of a call can only lower this cap. |
| `FALLOW_DIFF_FILE` |  | MCP server: path to a unified diff that scopes all findings by changed line. |
| `FALLOW_CHANGED_SINCE` |  | MCP server: git ref that scopes file discovery for analysis tools. |
| `FALLOW_MCP_WARM_SESSION` | `on` | MCP server: set to 0, false, off or no to stop typed tool calls from keeping parsed modules in memory between calls (default on). |
