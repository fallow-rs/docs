Fallow analyzes a monorepo as one project graph. When only a sibling package uses an export, fallow does not report it as unused. You do not configure workspaces, because fallow reads the npm, yarn, pnpm, and Deno workspace formats.

Fallow resolves cross-package imports through `node_modules` symlinks or Deno import maps. You can scope the output to one package or to a set of packages.

<Info>
Workspace detection is automatic. Fallow finds and analyzes all packages if your repo has one of these:

- A `workspaces` field in `package.json`.
- A `pnpm-workspace.yaml` file.
- A `workspace` field in a root `deno.json` or `deno.jsonc`.
</Info>

## Workspace auto-detection

Fallow detects workspaces from these sources:

| Source | Example |
|:-------|:--------|
| `package.json` `workspaces` field | `"workspaces": ["packages/*"]` |
| `pnpm-workspace.yaml` | `packages: ["packages/*", "apps/*"]` |
| `deno.json` / `deno.jsonc` `workspace` field | `"workspace": ["./packages/*"]` |

<CodeGroup>
```json package.json (npm / yarn)
{
  "workspaces": [
    "packages/*",
    "apps/*"
  ]
}
```

```yaml pnpm-workspace.yaml
packages:
  - "packages/*"
  - "apps/*"
```
</CodeGroup>

## Deno workspaces

Fallow reads a root `deno.json` or `deno.jsonc` the same way it reads `package.json` for npm. The `workspace` field lists member globs. It accepts the bare array form and the object form:

<CodeGroup>
```jsonc deno.json (array form)
{
  "workspace": ["./apps/*", "./packages/*"]
}
```

```jsonc deno.json (object form)
{
  "workspace": {
    "members": ["./apps/*", "./packages/*"]
  }
}
```
</CodeGroup>

Fallow reads the `name` and `exports` of each member like the same fields in `package.json`. For example, `@scope/lib` with `"exports": { ".": "./mod.ts" }` resolves like an npm package export map. When a member directory has both a `package.json` and a `deno.json`, fallow takes the package identity from `package.json`.

Fallow resolves import maps (`imports` in the root or member configs) per package. An exact specifier match wins. If there is no exact match, the longest matching slash-prefix entry applies.

Deno workspace member names count as listed dependencies. When you import a sibling package by name, fallow does not report it as an unlisted dependency.

With a pure Deno root (no root `package.json`), fallow does not warn about a missing `node_modules` directory. If the root `deno.json` or `deno.jsonc` is malformed, fallow stops with an analysis error (exit 2). It does not continue with an empty workspace list.

## Cross-workspace imports

When `apps/web` imports from `@myorg/ui`, fallow follows the `node_modules` symlink back to the workspace source files. Fallow canonicalizes symlinked paths, so it records the usage on the real source file.

```ts apps/web/src/App.tsx
// Resolves to packages/ui/src/Button.tsx via node_modules symlink
import { Button } from '@myorg/ui'
```

### Pnpm content-addressable store

pnpm uses a content-addressable store with a `.pnpm` virtual store inside `node_modules`. Fallow detects these paths and maps them back to the workspace source files. Fallow also tracks cross-package usage correctly in the strict isolation mode of pnpm.

## Package exports resolution

Fallow resolves the `exports` field in the `package.json` of each package, including subpath patterns:

```json packages/ui/package.json
{
  "name": "@myorg/ui",
  "exports": {
    ".": "./src/index.ts",
    "./icons": "./src/icons/index.ts",
    "./theme/*": "./src/theme/*.ts"
  }
}
```

An import of `@myorg/ui/icons` resolves to `packages/ui/src/icons/index.ts`.

## Output directory mapping

Packages often point `exports` or `main` at build output. Fallow maps these paths back to the source file, so usage counts against the code you edit. This applies to the `dist`, `build`, `out`, `esm`, and `cjs` directories. Fallow tries the same relative path under `src/` with the source extensions `.ts`, `.tsx`, `.js`, and `.jsx`.

```json packages/utils/package.json
{
  "main": "dist/index.js"
}
```

Fallow maps `dist/index.js` back to `src/index.ts` (or `.js`, `.tsx`, and so on) if the source file exists.

## Per-package tsconfig.json

Fallow finds the `tsconfig.json` file in each workspace package automatically. It uses the path aliases of a package to resolve imports in that package.

```json packages/ui/tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  }
}
```

## Scoping output to workspaces

To see the issues of one or more workspaces only, pass `-w` or `--workspace`. Fallow still analyzes the full monorepo graph and filters only the reported issues.

A pattern has one of these forms:

- **Exact package name** or **workspace path**: `web`, `@myorg/ui`, `apps/web`
- **Glob**, matched against both the package name and the workspace path relative to the repo root: `apps/*`, `@scope/*`
- **Negation** with a `!` prefix: `!apps/legacy`

Separate values with commas, or repeat the flag. Quote patterns that contain `!` or glob characters, so that your shell does not expand them.

```bash
# Single package (back-compat with earlier fallow versions)
fallow dead-code -w @myorg/ui

# Multiple packages (comma-separated or repeated)
fallow dead-code -w web,admin
fallow dead-code -w web -w admin

# Glob: all apps, all scoped packages
fallow dead-code -w 'apps/*'
fallow dead-code -w '@myorg/*'

# Everything under apps/ except legacy
fallow dead-code -w 'apps/*,!apps/legacy'

# Everything except a workspace (negation only)
fallow dead-code -w '!apps/legacy'
```

```bash title="$ fallow dead-code -w 'apps/*,!apps/legacy'"
● Unused exports (2)
  apps/web/src/Button.tsx
    :15 ButtonVariant
  apps/admin/src/Modal.tsx
    :8  ModalContext
  Exported symbols with zero references

✗ 2 issues (31ms, 1,247 files)
```

<Tip>
For CI matrix jobs, combine `--workspace` with `--changed-since`. Fallow applies both filters, so you get only the changed files inside the matched workspaces.
</Tip>

## Additional workspace patterns

If fallow does not detect all your workspace packages, add patterns in your config:

<CodeGroup>
```jsonc .fallowrc.json
{
  "workspaces": {
    "patterns": ["tools/*", "shared/*"]
  }
}
```

```toml fallow.toml
[workspaces]
patterns = ["tools/*", "shared/*"]
```
</CodeGroup>

These patterns add to the packages that fallow detects from `package.json`, `pnpm-workspace.yaml`, or a root Deno config.
