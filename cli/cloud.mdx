Log this machine in to Fallow Cloud with a read-only API key, or remove the stored key.

For the setup of Fallow Cloud, read the [Fallow Cloud docs](https://docs.fallow.cloud).

### login {#login}

Show a code and a URL. After a person approves the code in the dashboard, Fallow Cloud creates a read-only API key for this machine, and fallow stores it.

{/* generated:start cli-synopsis cloud login */}

```bash
fallow cloud login [OPTIONS]
```

{/* generated:end */}

{/* generated:start cli-options cloud login */}

| Option | Description |
|:--|:--|
| `--machine-name <NAME>` | Name of this machine on the key, shown in the dashboard. Default: the host name |
| `--api-url <URL>` | Fallow Cloud API base URL. Default: $FALLOW_API_URL, else `https://api.fallow.cloud` |

{/* generated:end */}

Only an organization owner can approve a key. When a member approves the code, fallow stores no key and exits with code 2. The key starts with `fallow_read_k1_`. It can read production data, for example for [`fallow inspect --cloud`](/cli/inspect#production-data), and cannot upload. The dashboard lists it under **Settings > API keys** as `fallow cloud login (<machine name>)`.

Fallow stores the key for the service `fallow-cloud`, with the API URL as the account:

| System | Store |
|:--|:--|
| macOS | The login keychain. |
| Linux with a desktop session | The Secret Service, through `secret-tool`. |
| Other, or no keychain | `~/.config/fallow/credentials` (or `$XDG_CONFIG_HOME/fallow/credentials`), mode 0600 on Unix. |

`FALLOW_CREDENTIAL_STORE=file` selects the credentials file. `FALLOW_CREDENTIAL_STORE=none` turns off the stored key, for example on a shared runner.

#### Key order {#key-order}

Each command that reads production data takes the first key that it finds:

1. `--api-key`, when the command has this option.
2. `$FALLOW_API_KEY`.
3. The key in the keychain.
4. The key in the credentials file.

The upload commands of [`fallow coverage`](/cli/coverage) and `fallow coverage setup --cloud --wait` read only `--api-key` and `$FALLOW_API_KEY`, because Fallow Cloud refuses a read-only key for them.

### logout {#logout}

## Output

`fallow cloud login` prints `Open <URL> and enter the code <CODE>`, then the machine name and `Waiting for approval...`. After the approval, it prints `Logged in. Stored the read-only key <prefix>... in <store>.` Fallow never prints the full key.

```bash
fallow cloud logout
```

```text
No stored API key for https://api.fallow.cloud.
```

With `--format json`, `login` prints `kind: "cloud-login"` with `status`, `api_url`, `key_prefix`, `key_name` and `store`. `logout` prints `kind: "cloud-logout"` with `api_url`, `removed_from_keychain` and `removed_from_credentials_file`.

When the keychain does not confirm the removal, `logout` says that the logout is incomplete and exits with code 2. The cause can be a denied prompt, a prompt that timed out, or a keychain tool that failed. With `--format json`, the command then prints the error object with `error`, `message` and `exit_code`, not `kind: "cloud-logout"`. It still removes any key for the API URL from the credentials file. Run `fallow cloud logout` again and allow the prompt, or remove the `fallow-cloud` entry from the keychain by hand.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The command completed. |
| `2` | The login failed, for example because a member approved the code, the input is invalid, or the keychain did not confirm the removal of the key at logout. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Log in, and approve the code in the dashboard
fallow cloud login

# Log in with another name for this machine
fallow cloud login --machine-name ci-runner-1

# Remove the stored key
fallow cloud logout
```
