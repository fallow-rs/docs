Send a report to the Fallow maintainers as a public GitHub issue: a bug, a false positive, a false negative, friction, a docs gap or a missing feature.

Before you report an unexpected finding, read [False positives](/guides/false-positives).

## Synopsis

{/* generated:start cli-synopsis feedback */}

```bash
fallow feedback [OPTIONS] [MESSAGE]
```

## Options

{/* generated:start cli-options feedback */}

| Argument | Description |
|:--|:--|
| `[MESSAGE]` | A short note. The first line becomes the issue title |

### Input {#options-input}

| Option | Description |
|:--|:--|
| `--type <KIND>` | What kind of feedback this is (default: friction). Values: `bug`, `false-positive`, `false-negative`, `friction`, `feature`, `docs`. |
| `--impact <IMPACT>` | How much the problem cost. Values: `blocked`, `worked-around`, `minor`. |
| `--task <TASK>` | The task that you tried to do |
| `--command <COMMAND>` | The Fallow command that you ran |
| `--expected <EXPECTED>` | The result that you expected |
| `--actual <ACTUAL>` | The result that you got |
| `--agent <AGENT>` | The name of the coding agent that writes the report, such as `claude-code` |
| `--input-json <FILE>` | Read the report from a JSON file, or from stdin with `-`. A flag overrides the same field in the file |

### Run {#options-run}

| Option | Description |
|:--|:--|
| `--yes` | Create the issue with the GitHub CLI (`gh`). Without this flag the command prints a preview and a prefilled link, and sends nothing |
| `--confirm <DIGEST>` | Create the issue only when the report still has this digest, the `feedback.digest` of the preview. A changed report exits 2 |
| `--dry-run` | Print the preview and the prefilled link only. This is the default |
| `--no-diagnostics` | Leave out the Fallow version and the operating system |

## Option details

### Preview and submit

Without `--yes`, the command sends nothing. It prints the issue preview and a prefilled `issues/new` link. `--dry-run` gives the same result.

With `--yes`, the GitHub CLI (`gh`) creates the issue on `fallow-rs/fallow`, and the command prints the issue URL. `--confirm <digest>` takes the `digest` of the preview. When the report changed after that preview, the command creates nothing and exits with code 2.

The MCP tool `submit_feedback` wraps this command. It returns the preview by default. It creates the issue only with `submit: true` and `confirm` set to the digest of the preview, after the user approves the preview.

### Report content

The first line of the message becomes the issue title. `--input-json <file>` reads the report from a JSON file, and `--input-json -` reads it from stdin. A flag overrides the same field in the file.

The report holds only the text that you give, the Fallow version and the operating system. `--no-diagnostics`, `DO_NOT_TRACK=1` and `FALLOW_TELEMETRY_DISABLED=1` leave out the version and the operating system. Fallow replaces the home directory in a path with `~`. Fallow also replaces common secret shapes with `[redacted]`: access tokens, JWTs, `Bearer` values, URL passwords and PEM private keys.

## Output

```bash
fallow feedback --type false-positive --impact minor --command "fallow dead-code" "Export reported as unused"
```

````text
Feedback preview. Nothing was sent. The issue will be public on github.com/fallow-rs/fallow.

Title: Feedback (false positive): Export reported as unused

<!-- fallow-feedback v1 -->

**Type:** false positive
**Impact:** minor

### Summary

Export reported as unused

### Command

```text
fallow dead-code
```

### Environment

- fallow 3.50.0
- OS: macos (aarch64)

---
_Filed with `fallow feedback`._

To create the issue, run the same command with --yes (uses the GitHub CLI).
Or open this link: https://github.com/fallow-rs/fallow/issues/new?title=...
````

With `--format json`, the output has one `feedback` object with these fields:

| Field | Content |
|:--|:--|
| `status` | `"preview"` for a preview. |
| `repository` | The repository of the issue: `fallow-rs/fallow`. |
| `public` | `true`, because the issue is public. |
| `title` | The issue title. |
| `body` | The issue body in Markdown. |
| `digest` | The digest of the report. Give it to `--confirm`. |
| `diagnostics_included` | `true` when the report holds the Fallow version and the operating system. |
| `issue_url` | The URL of the created issue, or `null`. |
| `new_issue_url` | The prefilled `issues/new` link. |
| `new_issue_url_truncated` | `true` when the link does not hold the full body. |
| `reason` | The reason when the command created no issue, or `null`. |
| `submit_command` | The step that creates the issue. |

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The command printed the preview, or created the issue. |
| `2` | The report changed after the preview of the `--confirm` digest, or the input is invalid. |
| `3` | `gh` is not available. The command prints the prefilled link. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Preview a false positive report
fallow feedback --type false-positive --command "fallow dead-code" "Export reported as unused"

# Read the digest of the preview
fallow feedback --format json --quiet "Export reported as unused" | jq -r '.feedback.digest'

# Create the issue only when the report did not change after the preview
fallow feedback --yes --confirm <digest> "Export reported as unused"

# Read the report from stdin, without the version and the operating system
fallow feedback --input-json - --no-diagnostics < report.json
```
