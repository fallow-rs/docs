Run the dead-code analysis again each time a source file or a config file changes.

For the findings of the analysis, read [Dead code](/analysis/dead-code).

## Synopsis

{/* generated:start cli-synopsis watch */}

```bash
fallow watch [OPTIONS]
```

{/* generated:end */}

## Options

{/* generated:start cli-options watch */}

| Option | Description |
|:--|:--|
| `--no-clear` | Don't clear the screen between re-analyses |

{/* generated:end */}

Fallow analyzes the project once at the start. Then it waits 500 ms after the last change, and analyzes again. A change to a source file, `package.json`, `tsconfig.json` or a fallow [config file](/configuration/overview) starts a run. Fallow skips the files that `.gitignore` or `ignorePatterns` ignores. Press `Ctrl+C` to stop.

The [global options](/cli/global-flags) apply, for example `--production`, `--format` and `--quiet`. The issue type filters of [`fallow dead-code`](/cli/dead-code), for example `--unused-exports`, do not apply.

## Output

Each run prints the report of [`fallow dead-code`](/cli/dead-code#output) in the format that `--format` selects. Before a new run, fallow prints the changed files after `Changed:`. After each run, fallow prints `Watching for changes... (press Ctrl+C to stop)` on stderr. Fallow clears the screen before each run when stderr is a terminal, except with `--no-clear`.

## Examples

```bash
# Watch the project
fallow watch

# Watch only the production code
fallow watch --production

# Keep the output of each run on the screen
fallow watch --no-clear
```
