`fallow type-aware` checks and installs `fallow-type-aware`, the separate program that runs the TypeScript type checker for [type-aware analysis](/analysis/type-aware).

For the concepts and the setup, read [Type-aware analysis](/analysis/type-aware).

### setup {#setup}

{/* generated:start cli-synopsis type-aware setup */}

```bash
fallow type-aware setup [OPTIONS]
```

{/* generated:end */}

{/* generated:start cli-options type-aware setup */}

| Option | Description |
|:--|:--|
| `--yes` | Confirm non-interactively. Required when stdin is not a terminal |
| `--from <FILE>` | Install a bundle file of this version in place of a download. The signature must be next to it as `<file>.sig` |

{/* generated:end */}

- `setup` is for a `fallow` binary from Homebrew, `cargo install` or a release archive, on macOS and Linux. The npm package of `fallow` installs the program itself.
- `setup` downloads the bundle of its own fallow version, checks the signature, and installs the program into a user directory for that version.
- Node.js 20 or later must be on `PATH`.
- Windows has no setup bundle. Install `fallow` from npm.

## Output

```text
[-] Type-aware companion: unavailable
[W] Action: This Fallow binary is not the npm install (for example Homebrew or `cargo install`). No npm launcher passes the companion to it. Run `fallow type-aware setup` to download the signed companion of this version into your user directory. The companion needs Node.js 20 or later on PATH. Or set FALLOW_TYPE_AWARE_BIN to a trusted `fallow-type-aware` executable.
```

The first line gives the state. When the program is not available, the `Action:` line gives the fix.

With `--format json`, `status` gives these fields:

| Field | Content |
|:--|:--|
| `kind` | `"type-aware-status"` |
| `schema_version`, `version` | The version of this output format and the fallow version. |
| `available` | `true` when fallow found the program, its protocol version matches, and its TypeScript version is supported. |
| `discovery_source` | How fallow found the program: `environment-override` (`FALLOW_TYPE_AWARE_BIN`), `installed-sibling` (next to the `fallow` executable), `setup-directory` (from `setup`), or a launcher marker such as `npm-wrapper`. `null` when fallow did not find it. |
| `companion_path` | The path of the program. Relative to the project root when it is inside the root, else only the file name. |
| `package_version` | The version of the `fallow-type-aware` package. |
| `protocol_version` | The protocol version of the program, or of this fallow build when the program did not answer. |
| `backend_family`, `backend_version` | The type checker and its version, for example `typescript-go`. |
| `remediation` | The fix when `available` is `false`, else `null`. |

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The command ran. `status` also exits with `0` when the program is not available: read `available`. |
| `2` | Invalid input, for example `status --format sarif`, or `setup` without `--yes` when no terminal is available. |
| `3` | `setup` cannot run: Node.js is missing, the platform has no bundle, or the installed program is not usable. |
| `7` | `setup` cannot download the bundle. |

[Exit codes](/reference/exit-codes) has the codes that all commands share.

## Examples

```bash
# Check that type-aware analysis can run
fallow type-aware status --format json --quiet

# Install the program for a Homebrew or Cargo binary
fallow type-aware setup --yes

# Install from a bundle that you copied to the machine
fallow type-aware setup --from fallow-type-aware-<platform>-<arch>.tar.gz

# Remove the programs of other fallow versions
fallow type-aware cleanup --yes
```
