Check if fallow can read the project correctly: the root, the config file, the workspaces, the plugins, the dependencies and the caches. The command runs no analysis and writes nothing.

For the causes of an unexpected result, read [False positives](/guides/false-positives).

## Synopsis

{/* generated:start cli-synopsis doctor */}

```bash
fallow doctor [OPTIONS]
```

{/* generated:end */}

## Options

This command has no options of its own. It refuses analysis and gate options, for example `--production` and `--fail-on-issues`, and `--output-file`.

## Output

```bash
fallow doctor
```

```text
Fallow doctor (.)
[OK] root: Project root is an accessible directory.
[OK] config: Zero-config defaults resolved successfully.
[OK] workspaces: Workspace discovery completed (0 workspace packages).
[OK] plugins: No external plugins are configured; built-in detection remains available.
[-] type-aware: Type-aware analysis is not enabled.
[OK] dependencies: Dependencies are installed, or the project runs without a node_modules directory.
[OK] cache: Extraction cache is reusable (9.9 KB).
[OK] graph-cache: Module-graph cache (6.2 KB) loads; a run reuses it when the analysed files and options are unchanged.
[W] mutation-runner: vitest 2.1.9 is not supported; the supported range is >=4.1.0 <6.0.0. A mutation run stops before the first mutant. Fix: install vitest 4.1.0 or a later version below 6.0.0; a vitest 4.x release from 4.1.0 is in the range.
    Action (from project root): npm install --save-dev vitest@^4.1.0
Status: ready with warnings
```

Each line gives the result of one check: `[OK]` passed, `[W]` warns, `[X]` failed, and `[-]` was skipped. An `Action` line gives the command that fixes a problem. The last line is `ready`, `ready with warnings` or `not ready`.

| Check | Required | Question |
|:--|:--|:--|
| `root` | Yes | Can fallow read the project root? |
| `config` | Yes | Which config file applies, or do the defaults apply? |
| `workspaces` | No | Did fallow find the workspaces? |
| `plugins` | Yes | Do the external plugins load? |
| `type-aware` | No | Is [type-aware analysis](/analysis/type-aware) on and available? |
| `dependencies` | No | Is `node_modules` present, when the project needs it? |
| `cache` | No | Can the next run use the cache of the parsed files? |
| `graph-cache` | No | Can the next run use the cache of the module graph? |
| `mutation-runner` | No | Is the installed Vitest in the range that [`fallow mutation`](/cli/mutation) supports? |

A check that is not required can only warn or be skipped. A `graph-cache` pass does not prove that the next run uses the cache, because that also depends on the content of each file. `FALLOW_CACHE_DIR` sets the cache directory that the cache checks read.

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"doctor"` |
| `schema_version` | The version of this output format. |
| `version` | The fallow version. |
| `root` | The project root. |
| `status` | `pass`, `warn` or `fail`. |
| `summary` | The number of checks for each status: `pass`, `warn`, `fail`, `skipped`. |
| `checks` | One object for each check: `id`, `category`, `status`, `required`, `message`, and `remediation` when a fix exists. |

A `remediation` has `command`, `cwd` (always the project root) and `mutating` (`true` when the command writes files). An install command uses the package manager of the project. The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | Each required check passed. Warnings do not change the code. |
| `2` | A required check failed, or the input is invalid, for example `--production` or `--format sarif`. |

The command never exits with code 1, because it reports no findings. See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Check the project
fallow doctor

# Check the project in a CI step, and read the status
fallow doctor --format json --quiet | jq -r '.status'

# Check a project with another config file
fallow doctor --config configs/fallow.json
```
