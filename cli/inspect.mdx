Return the evidence of each analysis for one file or one exported symbol in one bundle.

For a walk from a finding to its cause, read [Trace a finding](/guides/trace-a-finding).

## Synopsis

{/* generated:start cli-synopsis inspect */}

```bash
fallow inspect [OPTIONS]
```

{/* generated:end */}

## Options

{/* generated:start cli-options inspect */}

| Option | Description |
|:--|:--|
| `--file <PATH>` | File to inspect |
| `--symbol <FILE:EXPORT>` | Exported symbol to inspect, formatted as FILE:EXPORT |
| `--symbol-chain` | OPT-IN: also attach the best-effort symbol-level call chain (`fallow trace`) as the `symbol_chain` evidence section. Only meaningful for a `--symbol` target. |
| `--churn` | OPT-IN: attach target-level git churn evidence from the health hotspot subsystem. Default off to avoid git-history latency |
| `--cloud` | OPT-IN: attach Fallow Cloud production evidence for a `--file` target as the `cloud` evidence section: calls, errors, CPU and never-run branches per function. The API key is $FALLOW_API_KEY, else the key that `fallow cloud login` stored. |
| `--repo <OWNER/REPO>` | Fallow Cloud repository for `--cloud`. Precedence: this flag > $FALLOW_REPO > the `origin` git remote |

{/* generated:end */}

Give `--file` or `--symbol`, not both. For a `--symbol` target, the dead-code, duplication, complexity and security evidence covers the whole file. `--cloud` sends one request to Fallow Cloud, with a limit of 2 seconds.

## Output

```bash
fallow inspect --file src/services/orders.ts
```

```text
Inspect target

  target: {"type":"file","file":"src/services/orders.ts"}
  identity: {"file":"src/services/orders.ts","is_reachable":true,"is_entry_point":false,"export_count":3,"import_count":1,"imported_by_count":3}

Evidence
  trace_file: ok [file] (exports: 3)
  dead_code: ok [file]
  duplication: ok [project filtered to file] (matches: 0)
  complexity: ok [project filtered to file] (matches: 0)
  security: ok [file]
  impact_closure: ok [project filtered to file]
```

Each evidence line gives the section, its status and its scope in brackets. The status is `ok`, `partial`, `unavailable` or `error`. A section with `error` adds an entry to `warnings`, and the other sections stay usable. `impact_closure` lists the files that a change to the target can affect.

### Compact output {#compact-output}

`--format compact` prints one line for each item and stays under 1 KB, for an editor hook that adds the text to the context of an agent:

```text
fallow src/services/orders.ts
finding unused-export src/services/orders.ts:18 `cancelOrder` is never imported
```

| Compact line | Content |
|:--|:--|
| `fallow <path>` | The header. |
| `finding <issue type> <path:line> <text>` | One static finding. |
| `prod <name:line> <text>` | One function with production data from `--cloud`, or a local function without it. |
| `cloud <status>: <text>` | The status of the `cloud` section when it is not `ok`. |
| `truncated <n> more` | The number of lines that the 1 KB limit left out. |

### JSON output {#json-output}

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"inspect_target"` |
| `target` | The target: `type` (`file` or `symbol`), `file`, and `export_name` for a symbol target. |
| `identity` | `file`, `is_reachable`, `is_entry_point`, `export_count`, `import_count`, `imported_by_count`. |
| `evidence` | One section for each analysis, each with `status`, `scope` and `data`. Opt-in sections: `symbol_chain`, `churn`, `cloud`. A symbol target with [type-aware analysis](/analysis/type-aware) adds `semantic_trace`, `api_surface`, `symbol_impact` and `targeted_tests`. |
| `warnings` | Messages about sections that failed. |

### Production data {#production-data}

With `--cloud`, fallow adds the production data of each function in the file from [runtime coverage](/analysis/runtime-coverage). The `cloud` section has its own `status`: `ok`, `no_key` (no key, or Fallow Cloud refused it), `plan_required`, `unavailable` (no answer in time, or an unknown repository) or `untracked` (no production data for the file). A status other than `ok` does not fail the run. A `null` count in this section means "not measured". The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The bundle is complete. A section with an `error` status does not change the code. |
| `2` | Invalid input, for example no target, two targets, or a file that is not in the project. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Get the evidence for one file as JSON
fallow inspect --file src/api.ts --format json --quiet

# Add the call chain of one exported symbol
fallow inspect --symbol src/api.ts:fetchUser --symbol-chain --format json --quiet

# Add the production data of the file for an editor hook
fallow inspect --file src/api.ts --cloud --format compact
```
