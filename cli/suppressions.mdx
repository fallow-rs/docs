List each active suppression comment in the project, with its line, issue type, scope and reason. The command reports no findings of its own.

For when and how to suppress a finding, read [Suppress a finding](/guides/suppress).

## Synopsis

{/* generated:start cli-synopsis suppressions */}

```bash
fallow suppressions [OPTIONS]
```

{/* generated:end */}

## Options

{/* generated:start cli-options suppressions */}

| Option | Description |
|:--|:--|
| `--file <PATH>` | Only list suppressions in the specified files. Accepts multiple values |

The [global options](/cli/global-flags) are in these groups: [Project](/cli/global-flags#options-project), [Output](/cli/global-flags#options-output), [Scope](/cli/global-flags#options-scope), [Baselines](/cli/global-flags#options-baselines), [Gates](/cli/global-flags#options-gates), [Duplication](/cli/global-flags#options-duplication), [Type-aware](/cli/global-flags#options-type-aware), [Performance](/cli/global-flags#options-performance).

{/* generated:end */}

The global options `--workspace`, `--changed-workspaces` and `--changed-since` limit the list. When fallow cannot resolve the ref of `--changed-since`, the list covers the whole project, and the JSON field `request_outcomes` says so.

## Output

```bash
fallow suppressions
```

```text
● Suppression inventory (1)
  src/reports/export.ts
    :3 code-duplication (range to :21) reason: kept on purpose

● Totals by kind
  code-duplication: 1

✓ 1 suppression in 1 file, 0 without reasons, 0 stale (0.06s)
```

Each comment gives its line, its issue type and its reason. A comment for a range shows `(range to :<line>)`, and a comment for the whole file shows `(file-wide)`. A comment without an issue type shows `blanket`. A range comment without a valid end shows `(range marker, no effect)`. The last line counts the comments without a reason, and the stale comments: the [`stale-suppression`](/rules/stale-suppression) findings of this run.

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"suppression-inventory"` |
| `schema_version` | The version of this output format. |
| `summary` | `total`, `files`, `without_reason`, `stale`, and `by_kind` with a `count` for each issue type. |
| `files` | One object for each file: `path`, and `suppressions` with `line`, `kind`, `level`, `origin`, `reason`, `reason_present`. |

`level` is `line`, `file` or `range`. A range has `end_line`, or a `problem` field when the comment has no effect. A blanket comment has `kind: null`. The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The list completed. The command never fails on a suppression. |
| `2` | Invalid input. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# List each suppression in the project
fallow suppressions

# List the suppressions in two files
fallow suppressions --file src/a.ts --file src/b.ts

# List the suppressions in the files that changed since main
fallow suppressions --changed-since main

# Count the suppressions without a reason
fallow suppressions --format json --quiet | jq '.summary.without_reason'
```
