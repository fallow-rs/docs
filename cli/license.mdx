Use `fallow license` to manage the local license that turns on the paid runtime-coverage features.

```bash
fallow license status
```

Fallow verifies the license offline, against an Ed25519 public key in the binary. Only the trial and refresh flows send network requests to `api.fallow.cloud`.

## Subcommands

### `activate`

Activate a local JWT or start a 30-day email-gated trial.

```bash
fallow license activate --trial --email you@company.com
fallow license activate eyJhbGciOiJFZERTQSIsInR5cCI6IkpXVCJ9...
fallow license activate --from-file ./license.jwt
cat ./license.jwt | fallow license activate --stdin
```

Fallow reads the JWT from the first source that is present:

1. positional JWT argument
2. `--from-file <path>`
3. `--stdin`

Fallow normalizes whitespace before verification, so a copied multiline token still works.

#### Flags

| Flag | Description |
|:-----|:------------|
| `--trial` | Start a 30-day email-gated trial, and do not read a local JWT. Requires `--email`. Rate-limited to **5 requests per hour per IP**. In CI or behind a shared NAT, start the trial on a developer machine and set `FALLOW_LICENSE` on the runner. |
| `--email <ADDR>` | Email address for the trial flow. On success, fallow also prints the `trialEndsAt` ISO timestamp from the server, so you do not need to decode the JWT. |
| `--from-file <PATH>` | Read a JWT from a file. |
| `--stdin` | Read a JWT from standard input. |

### `status`

Print the current license status, tier, seats, enabled features, and expiry state.

```bash
fallow license status
```

Example output:

```text
license: VALID, tier=trial seats=1 features=runtime_coverage days_until_expiry=29
  → runtime_coverage: ENABLED
```

If the token is expired but still in the grace window, fallow says so and tells you to refresh it. If no token is present, the command suggests a trial.

`api.fallow.cloud` can set a `refresh_after` claim in the JWT, at `iat + 15 days`. When that time has passed, `status` adds a one-line refresh hint. The hint is not an error. It comes while the license is still valid, so you can refresh early.

### `refresh`

Fetch a fresh JWT for the currently active license.

```bash
fallow license refresh
```

Use `refresh` to renew a token before it reaches the hard-fail window.

### `deactivate`

Remove the local license file.

```bash
fallow license deactivate
```

## Storage and precedence

By default, fallow stores the local token at `~/.fallow/license.jwt`. On Unix, fallow writes the file with mode `0600` (only the owner can read and write). Other users on the same host thus cannot read the bearer token. On Windows, the ACL of the parent directory controls access.

Fallow looks for the license in this order:

1. `FALLOW_LICENSE`
2. `FALLOW_LICENSE_PATH`
3. `~/.fallow/license.jwt`

On a shared CI runner where you do not want to write to a home directory, use `FALLOW_LICENSE`.

## Exit behavior

Common outcomes:

| Situation | Result |
|:----------|:-------|
| Valid license | exit code `0` |
| No license or hard-fail expired license | non-zero status |
| Network failure during `--trial` or `refresh` | exit code `7` |
| Malformed or truncated JWT | non-zero status with a verification error |

### Actionable error messages

When the backend returns a structured error envelope, fallow shows a specific hint for each known `code` value. It does not print the raw HTTP body:

| Operation + code | Message |
|:-----------------|:--------|
| `refresh` + `token_stale` | `your stored license is too stale to refresh. Reactivate with: fallow license activate --trial --email <addr>` (fires when the stored JWT is more than 45 days past its `exp`) |
| `refresh` + `invalid_token` | `your stored license token is missing required claims. Reactivate with: fallow license activate --trial --email <addr>` |
| `refresh` or `trial` + `unauthorized` | `authentication failed. Reactivate with: fallow license activate --trial --email <addr>` |
| `trial` + `rate_limit_exceeded` | `trial creation is rate-limited to 5 per hour per IP. Wait an hour or retry from a different network (in CI, start the trial locally and set FALLOW_LICENSE on the runner).` |

For an unknown code, fallow prints the `message` field from the backend. If that field is missing, fallow prints the raw body.

## Clock skew

License verification rejects a JWT when its `iat` (issued-at) claim is more than 24 hours in the future, relative to the local system clock. The same check finds skew in both directions:

- a JWT signed with a clock that is ahead
- a local machine with a clock that is behind

On rejection, fallow prints a `license appears to be issued <duration> in the future` error and exits non-zero. Paid features thus fail closed. Fallow does not accept a license that the local clock cannot validate.

Common causes that are not user errors:

- CI containers booted without NTP.
- Machines with a dead BIOS battery.
- A laptop clock that drifts after a long sleep.

For an environment with predictable drift, first make sure that the system clock is correct. Then set `FALLOW_LICENSE_SKEW_TOLERANCE_SECONDS=<seconds>` to change the default 24h window. Fallow parses this value leniently. An unset, empty, unparsable, or negative value falls back to the default, so a typo in a runner env block cannot cause a license verification failure by itself.
