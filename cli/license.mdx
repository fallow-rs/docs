Activate, show, refresh and remove the local license for continuous [runtime coverage](/analysis/runtime-coverage). Static analysis and one local capture of runtime coverage need no license.

For what runtime coverage adds, read [Runtime coverage](/analysis/runtime-coverage).

Fallow reads the token from the first source that is present: the `JWT` argument, `--from-file`, then `--stdin`. Fallow removes whitespace before it checks the token. The trial sends one request to `api.fallow.cloud`, and the server allows 5 trials for each IP address in one hour. In CI, start the trial on your machine and set `FALLOW_LICENSE` on the runner.

## Options

Fallow checks a token offline with a public key in the binary. Only `activate --trial` and `refresh` use the network. Fallow takes the license from the first source that is present:

1. `FALLOW_LICENSE`
2. `FALLOW_LICENSE_PATH`
3. `~/.fallow/license.jwt`, written with mode 0600 on Unix

Fallow refuses a token that was issued more than 24 hours in the future of the local clock. `FALLOW_LICENSE_SKEW_TOLERANCE_SECONDS` changes that window.

## Option details

### License file {#storage}

On Unix, only the owner can read and write `~/.fallow/license.jwt` (mode 0600), so other users of the host cannot read the token. On Windows, the access rules of the parent folder apply. On a shared CI runner where you do not want to write to a home folder, use `FALLOW_LICENSE`.

### Clock skew {#clock-skew}

Fallow refuses a token when its `iat` (issued-at) claim is more than 24 hours after the local clock. The same check finds a token signed with a clock that is ahead, and a machine with a clock that is behind. Fallow then prints `license appears to be issued <duration> in the future` and does not run the licensed feature.

Usual causes are a CI container that started without NTP, a machine with a dead BIOS battery, and a laptop clock that drifts after a long sleep. Correct the system clock first. For a known drift, set `FALLOW_LICENSE_SKEW_TOLERANCE_SECONDS=<seconds>`. An unset, empty, invalid or negative value gives the default of 24 hours, so a typo in the variable cannot make the check fail.

### Error messages of the license server {#server-errors}

When the license server returns a known error code, fallow prints a hint, not the raw HTTP body:

| Command and code | Message |
|:--|:--|
| `refresh`, `token_stale` | ``your stored license is too stale to refresh: set FALLOW_API_KEY to a full-access key and run `fallow license refresh` again (generate one at https://fallow.cloud/settings#api-keys)`` |
| `refresh`, `invalid_token` | `your stored license token is missing required claims. Reactivate with: fallow license activate --trial --email <addr>` |
| `refresh` or `activate --trial`, `unauthorized` | `authentication failed. Reactivate with: fallow license activate --trial --email <addr>` |
| `activate --trial`, `rate_limit_exceeded` | `trial creation is rate-limited to 5 per hour per IP. Wait an hour or retry from a different network (in CI, start the trial locally and set FALLOW_LICENSE on the runner).` |

For an unknown code, fallow prints the `message` field of the response, or the raw body when that field is absent.

## Output

```bash
fallow license status
```

```text
license: NOT FOUND. Start a 30-day trial: fallow license activate --trial --email you@company.com
  → runtime_coverage: disabled (upgrade or refresh)
```

The first line gives the state of the license, and for a valid license its tier, seats, features and days until expiry. Each next line gives one feature and its state. When the token can be refreshed, `status` adds a hint.

With `--format json`, `status` prints `kind: "license-status"` with these fields:

| Field | Content |
|:--|:--|
| `schema_version` | The version of this output format. |
| `state` | The state of the license, for example `missing`. |
| `tier`, `seats`, `features` | The content of the license. |
| `days_until_expiry`, `days_since_expiry` | The time to or since the expiry date. |
| `refresh_suggested` | `true` when fallow can refresh the token. |
| `runtime_coverage_enabled` | `true` when the license allows continuous runtime coverage. |
| `license_path` | The path of the license file. |
| `message` | One sentence about the state. |

After the expiry date, runtime coverage runs normally for 7 days. From day 8 to day 30, the output of runtime coverage has the `license-expired-grace` mark. From day 31, fallow stops runtime coverage with exit code 3.

## Exit codes {#exit-behavior}

| Code | Meaning |
|:--|:--|
| `0` | The command completed. `status` with a valid license, or a license less than 31 days after expiry. |
| `2` | Invalid input, for example `--trial` without `--email`. |
| `3` | `status` without a license, or more than 30 days after expiry. `activate` with a token that is not valid. |
| `7` | The trial or the refresh failed: no network, a rate limit, or a refusal of the server. |

Commands with `--runtime-coverage` also check the license. Without a license, one local capture runs. With a license that is not valid, expired for more than 30 days, or without the `runtime_coverage` feature, the run stops with code 3. See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Start a 30-day trial
fallow license activate --trial --email you@example.com

# Store a license token from a file
fallow license activate --from-file ./license.jwt

# Show the state of the license
fallow license status

# Get a new token before the license expires
fallow license refresh

# Remove the license and go back to one local capture
fallow license deactivate
```
