When a result looks wrong, first check what fallow found in your project. `fallow list` shows the files, entry points, plugins, and boundary zones that fallow uses. Use it to debug the configuration, or to confirm that fallow sees the correct project setup.

```bash
fallow list
```

## Options

| Flag | Description |
|:-----|:------------|
| `--files` | Show all discovered files |
| `--entry-points` | Show entry point files |
| `--plugins` | Show active plugins |
| `--boundaries` | Show architecture boundary zones, rules, and per-zone file counts |
| `--workspaces` | Show monorepo workspaces and workspace-discovery diagnostics, for example a malformed `package.json`, an unreachable glob match, or a missing tsconfig reference. The `fallow workspaces` alias does the same. |
| `-f, --format <FORMAT>` | Output format: `human` (default), `json` |

## Examples

<CodeGroup>
```bash Inspect plugins
# Show active plugins
fallow list --plugins

# JSON output for scripting
fallow list --plugins --format json
```

```bash Inspect files
# Show all discovered files
fallow list --files

# Show entry points
fallow list --entry-points
```

```bash Inspect boundaries
# Show boundary zones and rules (requires boundaries config)
fallow list --boundaries

# JSON output with zone file counts
fallow list --boundaries --format json
```

```bash Inspect workspaces
# Show monorepo workspaces and any discovery diagnostics
fallow list --workspaces

# Same, via the dedicated alias
fallow workspaces

# JSON output for scripting (workspace_diagnostics[] is also on
# `fallow dead-code / dupes / health --format json`)
fallow list --workspaces --format json
```
</CodeGroup>

### Workspace diagnostics

Fallow reports workspace-discovery problems as `workspace_diagnostics[]` entries. The `kind` field tells you the type of problem:

| `kind` | When |
|:-------|:-----|
| `malformed-package-json` | A declared workspace's `package.json` failed to parse. Includes the parse error. |
| `glob-matched-no-package-json` | A workspace glob matched a directory that has no `package.json` (and is not in the conventional skip list or your `ignorePatterns`). Includes the matching pattern. |
| `malformed-tsconfig` | `tsconfig.json` exists but failed to parse as JSONC. Includes the parse error. |
| `tsconfig-reference-dir-missing` | `tsconfig.json` references a `references[].path` that does not exist. |
| `undeclared-workspace` | A directory contains `package.json` but is not declared as a workspace. |
| `excluded-by-default-ignore` | A built-in discovery ignore pattern (`**/dist/**`, `**/build/**`, `**/coverage/**` or one of the minified-bundle globs) removed at least one candidate source file. Fallow reports one entry per pattern, never per file. The entry has the `pattern`, an exact `file_count`, and a `directory_count` of the distinct locations where the pattern matched. `path` is the project-relative matched directory that lost the most files. It is anchored at the deepest matching segment, so `fallow --root <path>` recovers the files. Fallow never reports `**/node_modules/**`. Source discovery emits this entry, so it appears in `dead-code`, `check`, `audit` and `health` JSON. `--explain-skipped` prints the same counts on stderr. A run that found no source files prints one warning without the flag. |
| `bun-lockb-override-resolution-skipped` | The root `package.json` declares overrides and has the legacy binary `bun.lockb` next to it. Fallow found no parseable text lockfile (`bun.lock`, `pnpm-lock.yaml`, `package-lock.json`, `npm-shrinkwrap.json`) to use instead. As a result, fallow skips the `unused-dependency-overrides` check, and the check reports nothing. A `yarn.lock` or an unparseable `bun.lock` next to the `bun.lockb` does not prevent the skip. To fix it, run `bun install --save-text-lockfile` (bun 1.2 or newer) to write a text `bun.lock`. If the repository no longer uses bun, delete the stale `bun.lockb`. The override analysis emits this entry, not workspace discovery. It appears in `dead-code`, `check`, and `health` JSON and as one stderr warning. |

A malformed ROOT `package.json` is a hard config-load error, and fallow exits 2. For all other problems, fallow prints a warning and continues, so the analysis still runs on the remaining workspaces.

The JSON output of `fallow dead-code`, `fallow dupes`, and `fallow health` also contains these workspace-discovery diagnostics (omitted when empty). A CI job can fail on discovery problems without a separate command. The same JSON output can also include source-discovery skip diagnostics:

- `skipped-large-file` and `skipped-minified-file`, each with `size_bytes`
- `excluded-by-default-ignore`, for files that a built-in ignore pattern removed

## Example output

```bash title="$ fallow list --boundaries"
Boundaries: 6 zones, 6 rules, 1 logical group

Zones:
  app                  3 files  src/app/**
  features/auth        4 files  src/features/auth/**
  features/billing     5 files  src/features/billing/**
  features             3 files  src/features/**
  shared               8 files  src/components/**, src/hooks/**, src/lib/**, ...
  server               4 files  src/server/**

Rules:
  features/auth        → shared, server
  features/billing     → shared, server
  app                  → features/auth, features/billing, features, shared, server
  features             → shared, server, features/auth, features/billing
  server               → shared
  shared               (isolated, no imports allowed)

Logical groups:
  features             12 files autoDiscover: src/features
    children: features/auth, features/billing
```

The `Logical groups:` section appears when the config (or a preset) uses
`autoDiscover` to split a parent zone into one zone per child directory.
Each entry shows the parent name from your config, the exact `autoDiscover`
paths as written, the discovered children, and the total file count.

In the human output, misconfigured entries (`invalid path`, `empty`) come first
in the section. When the parent has both `patterns` and `autoDiscover` (for
example, the Bulletproof preset), the file count shows as
`N files (X children + Y fallback)`.

The `--format json` output has the same data in a parallel
`boundaries.logical_groups[]` array. Tools that write the config back can use
these extra fields:

| Field | Meaning |
|:------|:--------|
| `auto_discover` | The user strings, verbatim. |
| `source_zone_index` | The position in the `zones[]` array before expansion. |
| `status` | `ok`, `empty`, or `invalid_path`. |
| `authored_rule` | The rule on the parent, before expansion. |
| `fallback_zone` | A back-reference when the parent kept its own `patterns` and stayed in `zones[]`. |
| `merged_from` | The parent zone indices when the config declares the same parent name twice. |
| `original_zone_root` | A copy of the `root` subtree scope of the parent. |
| `child_source_indices` | Parallel to `children`. It links each child to one `auto_discover` entry. |

[`docs/output-schema.json`](https://github.com/fallow-rs/fallow/blob/main/docs/output-schema.json)
documents the full shape under `ListBoundariesOutput`.
