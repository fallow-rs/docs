`fallow audit` runs a [changed-code check](/concepts/changed-code): the analyses on the files that a change touches, with one verdict.

For the concepts and the workflow, read [Changed code](/analysis/changed-code).

## Synopsis

{/* generated:start cli-synopsis audit */}

```bash
fallow audit [OPTIONS] [PATH]
```

{/* generated:end */}

`fallow review` is an alias of `fallow audit --brief`. It prints the [review brief](#review-brief-and-decision-surface).

`fallow audit` also accepts the [global options](/cli/global-flags), with these exceptions:

- `--baseline` and `--save-baseline` exit with code 2. Use `--dead-code-baseline`, `--health-baseline` and `--dupes-baseline`, or the `audit.deadCodeBaseline`, `audit.healthBaseline` and `audit.dupesBaseline` config keys.
- `--fail-on-issues` has no effect. The verdict sets the exit code.
- `--fail-on-stale-baseline` never runs in an audit, because the audit cannot judge a whole-project baseline.
- The `badge` format exits with code 2.

### Base ref {#base-ref}

Fallow takes the first base that it finds:

1. `--base` or `--changed-since`
2. the `FALLOW_AUDIT_BASE` environment variable
3. the merge-base with the upstream of the branch, else with `origin/HEAD`, `origin/main` or `origin/master`
4. the local `main` or `master` branch, when the repository has no `origin` remote

A base that git cannot resolve exits with code 2. `--staged` compares the staged files with `HEAD` and reads each file from the index. It cannot go together with `--base`.

### Gate {#gate}

| `--gate` value | Effect |
|:--|:--|
| `new-only` | The default. Fallow also analyzes the base, and only the findings that the change introduces count for the verdict. Each finding has `introduced: true` or `false`. |
| `all` | Each finding in the changed files counts. Fallow does not analyze the base, so the run is faster. |

The [`audit.gate`](/reference/config-rules#audit-gate) config key sets the default.

### Worsened complexity findings {#worsened-complexity-findings}

Under `new-only`, a complexity finding that the base already has is **worsened** when its cyclomatic complexity, its cognitive complexity or its CRAP score grew, or when the function grew by 5 lines or more. `--worsened`, or the [`audit.worsened`](/reference/config-rules#audit-worsened) config key, sets the effect:

| Value | Effect |
|:--|:--|
| `warn` | The default. The verdict is at least `warn`. The exit code stays `0`. |
| `error` | A worsened finding counts as an introduced finding. |
| `off` | Only the growth of a metric that the finding already exceeds counts as worsened. |

`--worsened` has no effect with `--gate all`.

### Estimated CRAP {#estimated-crap-new-only}

Without coverage data, fallow estimates the CRAP score. Under `new-only`, a finding that exceeds only the CRAP threshold with an estimated score has `effective_severity: "warn"` and does not fail the audit. `--coverage` gives a measured score, which can fail the audit.

### Clone groups {#introduced-clone-group}

The `introduced-clone-group` key in [`rules`](/configuration/rules) sets the effect of a clone group on the verdict: `warn` (the default), `error` or `off`. Under `new-only`, only a clone group that the change introduces counts.

### Quiet report {#quiet-audit-report}

With `--quiet`, the `human`, `compact` and `markdown` reports show only the introduced findings, the worsened findings, the diff-risk findings and the analysis errors. When nothing is left, they print `No introduced or worsened findings.`. The verdict, the exit code and the other formats use the complete result.

- The first line gives the number of changed files and the base.
- Each analysis has a section with the findings in the changed files, in the format of its own command.
- The `Diff risk` section lists the [diff-risk findings](#diff-risk-rules).
- The last line gives the verdict (`✓` pass, `⚠` warn, `✗` fail) and the counts.

### Verdicts {#verdict}

| Verdict | Exit code | When |
|:--|:--|:--|
| `pass` | `0` | No finding counts for the gate. |
| `warn` | `0` | Each finding that counts has `warn` severity. |
| `fail` | `1` | A finding that counts has `error` severity. |

The [parse error gate](/cli/global-flags#parse-error-gate) and `--fail-on-baseline-growth` can also exit with code 1. They are not part of `verdict`: read `gate_outcomes`.

### JSON output {#json-output}

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"audit"`. The review brief gives `"audit-brief"`. |
| `schema_version`, `version`, `elapsed_ms` | The version of this output format, the fallow version and the run time. |
| `verdict` | `pass`, `warn` or `fail`. Use this field, or the exit code, to gate CI. |
| `changed_files_count`, `base_ref`, `head_sha` | The changed files, the base and the commit of the run. |
| `summary` | The counts of all findings in the changed files, at each severity: `dead_code_issues`, `dead_code_has_errors`, `complexity_findings`, `max_cyclomatic`, `duplication_clone_groups`. `dead_code_skipped`, `complexity_skipped` and `duplication_skipped` are `true` when `--only` or `--skip` left out an analysis. |
| `attribution` | `gate`, `worsened`, and the counts `<analysis>_introduced` and `<analysis>_inherited` for `dead_code`, `complexity`, `duplication` and `styling`. Also `complexity_worsened`, `duplication_demoted` and `diff_risk_introduced`. Under `gate: all`, the introduced and inherited counts are `0`. |
| `gate_outcomes` | The `audit-verdict` gate, and each other gate of the run. |
| `dead_code`, `duplication`, `complexity` | The results of [`fallow dead-code`](/cli/dead-code#output), [`fallow dupes`](/cli/dupes#output) and [`fallow health`](/cli/health#output) for the changed files. Each finding has `introduced`. A complexity finding has `attribution` (`introduced`, `worsened` or `inherited`) and `worsened_metrics`. |
| `diff_risk` | The diff-risk findings: `rule`, `kind`, `path`, `line`, `message`, `evidence`, `severity`, `introduced`, `related`, `actions`. Absent when the change has none. |

The `summary` and `attribution` counts do not use the severity. Gate on `verdict`. The [JSON output reference](/reference/json-output) has each field.

## Diff-risk rules {#diff-risk-rules}

A diff-risk rule reports a fact about the change itself. Fallow compares the base text and the head text of each changed file, so each finding is introduced. Only `fallow audit` and the MCP `audit` tool run these rules. A finding has only suppression actions. Set the severity of each rule in [`rules`](/configuration/rules).

### weakened-tests {#weakened-tests}

[`weakened-tests`](/rules/weakened-tests), default `warn`: the change makes the tests weaker. The `kind` field is `skip-only`, `removed-tests`, `assertion-drop`, `coverage-threshold`, `rule-severity` or `ignore-pattern`.

### added-suppression {#added-suppression}

[`added-suppression`](/rules/added-suppression), default `warn`: the change adds a lint, type-check, coverage or fallow suppression comment.

### test-only-branch {#test-only-branch}

[`test-only-branch`](/rules/test-only-branch), default `warn`: the change adds a check for the test environment in source code.

### diverged-clone-sibling {#diverged-clone-sibling}

[`diverged-clone-sibling`](/rules/diverged-clone-sibling), default `off`: the change edits one instance of a clone group, and the other instances stay the same. `related` lists the other instances.

### added-dependency {#added-dependency}

[`added-dependency`](/rules/added-dependency), default `off`: the change adds a dependency to a `package.json`. A `package.json` cannot hold a comment, so use an `overrides` entry to turn the rule off for a path.

## Review brief {#review-brief-and-decision-surface}

`--brief`, or `fallow review`, prints the review brief: the same analysis, sorted by where a reviewer must look. The brief always exits with code 0. It has the `kind` `"audit-brief"`, and these fields next to the audit fields:

| Field | Content |
|:--|:--|
| `decisions` | The structural decisions of the change, at most `--max-decisions`. [`fallow decision-surface`](/cli/decision-surface) describes each field. |
| `focus` | The changed units, each with a `score` (a sum of named components and a `total`) and a `reason`. An absent component is zero. |
| `triage` | The size class of the change. |
| `deltas` | What the change adds, for example `dependency_added` and `dependency_major_bumped`. |
| `weakening` | The guardrails that the change makes weaker: `kind` (`test-weakened`, `threshold-lowered`, `suppression-added`, `security-check-removed`), `file` and `evidence`. |
| `impact_closure` | The files outside the diff that the change reaches: `affected_count`, a sample, `affected_by_dir`, `coordination_gap`, `search_gap` and `co_change_gap`. |
| `partition` | `independent_slices` when the change splits into two or more parts that do not import each other. |
| `test_reach` | For each changed value export, how tests reach it: `direct`, `transitive`, `mocked-only`, `none`, `none-file` or `framework`. The set is open. |
| `ownership`, `routing` | The `CODEOWNERS` groups that the change reaches. Present only with a `CODEOWNERS` file. |
| `graph_facts` | The facts from the module graph that the brief uses. |

The focus `score` components are `fan_io`, `risk_zone`, `change_shape`, `churn`, `worsened`, `test_reach`, `mutation` (with `--mutation-report`), `runtime` (with `--runtime-coverage`) and `security_taint`.

### Walkthrough contract {#json-envelope}

`--walkthrough-guide --format json` prints a guide for a reviewing agent, with the `kind` `"review-walkthrough-guide"`. It has `digest`, `direction`, `change_anchors`, `graph_snapshot_hash`, `agent_schema` and `injection_note`. The agent returns a JSON file with the echoed `graph_snapshot_hash` and a `judgments` array. Each judgment cites a `signal_id` or a `change_anchor` from the guide, and has `framing`, an optional `concern` and an optional `action` (`block`, `address`, `consider` or `fyi`).

`--walkthrough-file <PATH>` checks the judgments against the current module graph:

| Outcome | Condition |
|:--|:--|
| `accepted` | The `signal_id` or the `change_anchor` is one that fallow gave, and the graph did not change. `anchor_kind` is `signal` or `change`. |
| `rejected`, `unanchored-signal-id` | Fallow did not give the `signal_id`. |
| `rejected`, `unknown-change-anchor` | Fallow did not give the `change_anchor`. |
| `rejected`, `invalid-action` | The `action` is not in the list. `invalid_value` holds the value. |
| `rejected`, `stale-snapshot` | The `graph_snapshot_hash` does not match the current graph. Get a new guide. |

Keep the guide and the judgment file outside the project. A new file in the project changes the graph hash.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The verdict is `pass` or `warn`. The review brief always exits with `0`. |
| `1` | The verdict is `fail`, or another gate of the run failed. |
| `2` | Invalid input, for example a base ref that git cannot resolve, or `--baseline`. |
| `3` to `6` | With `--runtime-coverage`: the license or the runtime coverage step failed. |

[Exit codes](/reference/exit-codes) has the meaning of each code.

## Examples

```bash
# Check the current branch against its merge-base
fallow audit

# Check the change against main, as JSON for CI
fallow audit --base main --format json --quiet

# Check only the staged files before a commit
fallow audit --staged

# Fail also on the findings that the change did not introduce
fallow audit --gate all

# Check only duplication and health
fallow audit --skip dead-code

# Hide the findings in saved baselines
fallow audit --dead-code-baseline fallow-baselines/dead-code.json --health-baseline fallow-baselines/health.json

# Show the review brief
fallow review --base main
```
