Render a saved `--format json` result in another format, without a new analysis. One analysis can then feed each CI output.

For the CI setup, read [CI](/integrations/ci).

## Synopsis

{/* generated:start cli-synopsis report */}

```bash
fallow report [OPTIONS] --from <PATH>
```

{/* generated:end */}

## Options

{/* generated:start cli-options report */}

| Option | Description |
|:--|:--|
| `--from <PATH>` | Path to a fallow JSON results file produced by `--format json` (dead-code, architecture, dupes, health, audit, security, or bare combined) |
| `--mutation-report <PATH>` | A saved `fallow mutation --format json` report, or the JSON error envelope of a failed run, to render with the results. Applies to the pr-comment, review, github-summary, github-annotations and codeclimate formats only. |
| `--mutation-not-run <REASON>` | Why mutation testing did not run in this job, so the render states it. Applies to the same formats as `--mutation-report`. Values: `event-refused`, `fork-refused`, `no-change-scope`, `interrupted`. |

The [global options](/cli/global-flags) are in these groups: [Project](/cli/global-flags#options-project), [Output](/cli/global-flags#options-output), [Scope](/cli/global-flags#options-scope), [Baselines](/cli/global-flags#options-baselines), [Gates](/cli/global-flags#options-gates), [Duplication](/cli/global-flags#options-duplication), [Type-aware](/cli/global-flags#options-type-aware), [Performance](/cli/global-flags#options-performance).

{/* generated:end */}

`--format` takes `github-annotations`, `github-summary`, `codeclimate`, `sarif`, `markdown`, `pr-comment-github`, `pr-comment-gitlab`, `review-github` or `review-gitlab`. Fallow reads the `kind` of the saved file, so the file can come from `dead-code`, `architecture`, `dupes`, `health`, `audit`, `security` or a bare `fallow` run.

Each finding keeps the severity that the analysis gave it. The comment and review formats keep the verdict, the gate results and the [request outcomes](/cli/global-flags#request-outcomes) of the saved run. They use the diff that you give `fallow report`, not the diff of the analysis.

## Output

```bash
fallow dead-code --format json > results.json
fallow report --from results.json --format github-annotations
```

```text
::notice::Fallow: Gates: failed error-severity-findings (6 at or above error).
::error file=package.json,line=14,title=Unused dependency::Package 'left-pad' is listed in dependencies but never imported by this package.%0A%0ARun: npm uninstall left-pad
::error file=src/lib/format.ts,line=3,col=14,title=Unused export::Exported value 'formatPercent' is never imported by other modules.%0A%0ARemove the export keyword or the declaration. If the export is public API, add its file to the entry configuration.
```

The output is the same as the output of the analysis with that `--format`. The [global options](/cli/global-flags) describe each format.

### Mutation results {#mutation-results}

`--mutation-report` adds the result of a [`fallow mutation`](/cli/mutation) run to the comment, review, `github-summary`, `github-annotations` and `codeclimate` formats. Each survived mutant on a changed line becomes a [`mutation-survived`](/rules/mutation-survived) finding. The comment and the summaries get a "Mutation testing" section with the counts and the score. A `--min-score` result becomes the `mutation-min-score` gate. The paths of the mutation report are relative to the root of the mutation run, so use the same `--root` for both commands. `--mutation-not-run` renders why the job did not run mutation testing.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | Fallow rendered the file, also when it holds findings or a failed gate. The analysis run sets the gate. |
| `2` | Invalid input, for example an unsupported `--format`, or `--mutation-report` with a format that does not support it. A saved file of a failed run exits with the saved code, and at least 2. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Analyze once and save the result
fallow --format json > results.json

# Write annotations to the GitHub job log
fallow report --from results.json --format github-annotations

# Write the pull request comment
fallow report --from results.json --format pr-comment-github > comment.md

# Write SARIF for code scanning
fallow report --from results.json --format sarif > results.sarif

# Add the mutation results to the comment
fallow report --from results.json --mutation-report mutation.json --format pr-comment-github
```
