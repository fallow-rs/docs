Install the fallow setup for each coding agent in the project in one step: the `AGENTS.md` task map, the skills, the MCP server entry and the commit gate.

For the setup of an agent, read [Coding agents](/integrations/agents).

### install {#install}

Write the files that each detected agent reads.

{/* generated:start cli-synopsis agent install */}

```bash
fallow agent install [OPTIONS]
```

{/* generated:end */}

{/* generated:start cli-options agent install */}

| Option | Description |
|:--|:--|
| `--harness <HARNESS>` | Harness to wire; repeatable. Defaults to `auto`. Values: `auto`, `claude`, `codex`, `cursor`. |
| `--user` | Write user-scoped files (skill and MCP config under $HOME) instead of project files. The `AGENTS.md` guide is project-only and is skipped under this flag |
| `--without <WITHOUT>` | Skip a step; repeatable. Values: `guide`, `skill`, `mcp`, `hooks`. |
| `--dry-run` | Print the plan without touching the filesystem |
| `--force` | Replace skills, hook scripts, or config files fallow did not write |
| `--approve` | Pre-approve the project-scoped MCP server for yourself by listing it in `.claude/settings.local.json` (Claude Code asks otherwise) |
| `--gitignore-claude` | Append `.claude/` to the project's `.gitignore` |

{/* generated:end */}

`--harness` takes `auto`, `claude`, `codex` or `cursor`. `--without` takes `guide`, `skill`, `mcp` or `hooks`. With `auto`, fallow selects each agent that has a signal:

| Agent | Project signal | Home signal | Session variable |
|:--|:--|:--|:--|
| Claude Code | `.claude/`, `CLAUDE.md`, `.mcp.json` | `~/.claude/` | `CLAUDECODE` |
| Codex | `.codex/` | `~/.codex/` | `CODEX_THREAD_ID` |
| Cursor | `.cursor/` | `~/.cursor/` | `CURSOR_AGENT` |

Without a signal, fallow writes only `AGENTS.md` and `.agents/skills/`. Each step writes these files:

| Step | Claude Code | Codex | Cursor |
|:--|:--|:--|:--|
| `guide` | `AGENTS.md`, and an `@AGENTS.md` import in `CLAUDE.md` | `AGENTS.md` | `AGENTS.md` |
| `skill` | `.claude/skills/fallow/`, `.claude/skills/fallow-setup/` | `.agents/skills/fallow/`, `.agents/skills/fallow-setup/` | `.agents/skills/fallow/`, `.agents/skills/fallow-setup/` |
| `mcp` | `mcpServers.fallow` in `.mcp.json` | `[mcp_servers.fallow]` in `.codex/config.toml` | `mcpServers.fallow` in `.cursor/mcp.json` |
| `hooks` | `.claude/settings.json` and `.claude/hooks/fallow-gate.sh` | `.codex/hooks.json`, `.codex/hooks/fallow-gate.sh`, and a block in `AGENTS.md` | none |

Fallow marks each file and block that it writes. A second run writes the same bytes. Fallow does not change a file that it did not write, except with `--force`. The `mcp` step writes an entry only when the server command can start. The root is the Git root of the current directory, except with `--root`.

### uninstall {#uninstall}

## Output

```bash
fallow agent install --dry-run
```

```text
fallow agent install (dry run)
  harnesses: claude (detected)

Shared with your team (commit these):
  AGENTS.md                                 would write    guide             scaffold with the fallow task map
  CLAUDE.md                                 would write    guide (claude)    create with an @AGENTS.md import
  .claude/skills/fallow                     would write    skill (claude)    embedded copy, 9 files
  .claude/skills/fallow-setup               would write    skill (claude)    embedded copy, 5 files
  .claude/settings.json                     would write    hooks (claude)    PreToolUse gate handler
  .claude/hooks/fallow-gate.sh              would write    hooks (claude)    gate script

Next:
  fallow agent install --harness claude
    This was a dry run. The command writes the steps marked "would write".
```

Each row gives a path, its status, the step and the agent, and a note. Fallow puts the files to commit under "Shared with your team" and the files for you only under "Local to you". The `Next:` list starts with the command that applies the plan.

With `--format json`, `install` and `uninstall` print `kind: "agent-install"` or `"agent-uninstall"` with these top-level fields:

| Field | Content |
|:--|:--|
| `schema_version`, `fallow_version` | The version of this output format, and of fallow. |
| `root`, `mode`, `dry_run` | The root, `install` or `uninstall`, and `true` for a dry run. |
| `harnesses`, `detected`, `evidence` | The selected agents, `true` when detection selected them, and the signals of each agent. |
| `steps` | One object for each file: `harness`, `step`, `scope`, `path`, `status`, and `reason` for a skipped or refused step. |
| `next_actions` | Commands to run next. `mutating: true` marks a command that writes agent config. After a dry run, `agent-install-apply` comes first. |

`status` is `written`, `removed`, `unchanged`, `skipped`, `refused` or `failed`. `fallow agent status --format json` prints `kind: "agent-status"` with `surfaces` (`step`, `path`, `state`, `detail`) and `next_actions`. The [JSON output reference](/reference/json-output) has each field.

### Gate readiness {#gate-readiness}

A `stale` gate has one of these entries in `next_actions`:

| Action id | Meaning |
|:--|:--|
| `gate-json-reader` | Fallow found no fallow build or `jq` that the gate can use to read JSON. The gate then exits 0 and audits nothing. |
| `gate-reader-unverified` | A launcher exists, but fallow did not run it to check it. |
| `gate-script-refresh` | The gate script differs from the current version. Run `fallow agent install` to write it again. |
| `gate-requires-jq` | An older gate needs `jq`. |
| `gate-path-version` | The gate runs the `fallow` on `PATH`, and that is another fallow version. |

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | Each step completed or had nothing to do. |
| `2` | Invalid input, or a step is `refused` or `failed`. The other steps still run. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Show the plan, and write nothing
fallow agent install --dry-run

# Install the setup for each detected agent
fallow agent install

# Install the setup for Codex only, without the MCP entry
fallow agent install --harness codex --without mcp

# Show the state of each agent file as JSON
fallow agent status --format json

# Show what an uninstall removes
fallow agent uninstall --dry-run
```
