Print the resolved configuration as JSON, and the path of the [config file](/configuration/overview) that fallow loaded.

For how fallow finds and merges config files, read [Configuration overview](/configuration/overview).

## Synopsis

{/* generated:start cli-synopsis config */}

```bash
fallow config [OPTIONS]
```

{/* generated:end */}

## Options

{/* generated:start cli-options config */}

### Output {#options-output}

| Option | Description |
|:--|:--|
| `--path` | Print only the config file path (one line, no JSON) |
| `--resolved` | Print each decision of a run and its cause as JSON: for each analysis whether it runs and its production mode, and the run settings, each with the flag, environment variable, config key or default that gave it. Environment variables show by name only |

### Run {#options-run}

| Option | Description |
|:--|:--|
| `--for <COMMAND>` | The command whose rules `--resolved` applies. Without it, the rules of the bare `fallow` run apply. Values: `combined`, `audit`, `dead-code`, `dupes`, `health`. |
| `--only <ONLY>` | With `--resolved`: run only these analyses, as `--only` of the bare run or of `fallow audit` does. Values: `dead-code` (alias `check`), `dupes`, `health`, `architecture`. |
| `--skip <SKIP>` | With `--resolved`: skip these analyses, as `--skip` of the bare run or of `fallow audit` does. Values: `dead-code` (alias `check`), `dupes`, `health`, `architecture`. |
| `--production-dead-code` | With `--resolved`: run dead-code analysis in production mode |
| `--production-health` | With `--resolved`: run health analysis in production mode |
| `--production-dupes` | With `--resolved`: run duplication analysis in production mode |

The [global options](/cli/global-flags) are in these groups: [Project](/cli/global-flags#options-project), [Output](/cli/global-flags#options-output), [Scope](/cli/global-flags#options-scope), [Baselines](/cli/global-flags#options-baselines), [Gates](/cli/global-flags#options-gates), [Duplication](/cli/global-flags#options-duplication), [Type-aware](/cli/global-flags#options-type-aware), [Performance](/cli/global-flags#options-performance).

Fallow looks for `.fallowrc.json`, `.fallowrc.jsonc`, `fallow.toml` and `.fallow.toml`, in that order, from the project root up to the workspace root. The first match wins, and fallow resolves `extends`. With the global option `--config`, fallow loads that file and does not search. The output is JSON for each `--format`. Add `--pretty` to indent it.

## Output

```bash
fallow config | jq '.boundaries.zones[0]'
```

```text
{
  "name": "services",
  "patterns": [
    "src/services/**"
  ]
}
```

The JSON holds each config key with its resolved value, also the defaults. Fallow prints `loaded config: <absolute path>` on stderr, so stdout holds only the JSON. Without a config file, the stderr line is `no config file found, using defaults`. With `--path`, the output is one line with the absolute path of the config file.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | Fallow printed the config, or the defaults when the project has no config file. |
| `2` | A config file does not parse, or the file that `--config` names does not exist. |
| `3` | With `--path`: the project has no config file. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Print the resolved config
fallow config --pretty

# Show which config file applies in a workspace package
cd packages/app && fallow config --path

# Print the duplication settings that apply
fallow config | jq '.duplicates'

# Print the config of another file
fallow --config ./configs/fallow.json config
```
