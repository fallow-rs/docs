`fallow dupes` finds copy-pasted code blocks across your whole codebase. Each clone group shows you code that you can extract into one shared function. You can also fail CI when duplication is more than a threshold. Fallow uses suffix-array analysis to find the clones.

```bash
fallow dupes
```

## Options

### Detection

| Flag | Description |
|:-----|:------------|
| `--mode <MODE>` | Detection mode: `strict`, `mild` (default), `weak`, `semantic` |
| `--near` | Include function-scoped near-miss clones with small structural edits. Uses semantic normalization. Reports groups with at least 80% all-pairs similarity. |
| `--min-tokens <N>` | Minimum tokens per clone (default: 50) |
| `--min-lines <N>` | Minimum lines per clone (default: 5) |
| `--min-occurrences <N>` | Minimum number of occurrences for fallow to report a clone group (default: 2, must be ≥ 2). Raise it to skip clones that occur only twice and find the widespread copy-paste that is worth a refactor. |
| `--skip-local` | Report only cross-directory duplicates |
| `--cross-language` | Remove TS types so that TS code can match JS code |
| `--ignore-imports` | Exclude module wiring from clone detection (default). Fallow removes ES imports, re-export declarations, and top-level static `require()` binding declarations from the token stream. It still counts runtime code, local exports, side-effect `require()` calls, nested `require()` calls, dynamic require arguments, and mixed declarations. |
| `--no-ignore-imports` | Count module wiring as clone candidates (opt out of the default exclusion). Conflicts with `--ignore-imports`. |

### Output

| Flag | Description |
|:-----|:------------|
| `-f, --format <FORMAT>` | Output format: `human` (default), `json`, `sarif`, `compact`, `markdown`, `codeclimate`, `gitlab-codequality`, `pr-comment-github`, `pr-comment-gitlab`, `review-github`, `review-gitlab` |
| `--top <N>` | Show only the N highest-ranked clone groups (see [Ranking and JSON fields](#ranking-and-json-fields)). Fallow rebuilds `clone_families[]` from the groups it shows, so the families shrink too. The `stats` counters still describe the whole scoped corpus. `clone_groups_shown`, `clone_groups_omitted`, `clone_families_shown`, and `clone_families_omitted` report the split. With `--group-by`, fallow refuses the run with exit code `2`. |
| `--quiet` | Suppress progress output |
| `--threshold <N>` | Fail if duplication is more than N% |
| `--group-by <MODE>` | Split the report into one section per group. `MODE`: `owner` (CODEOWNERS), `directory` (first path component), `package` (workspace), or `section` (GitLab `[Section]` headers). Fallow assigns each clone group to its largest owner (most instances, alphabetical tiebreak). A group with 2 instances in `src` and 1 in `lib` appears under `src`. JSON adds `grouped_by` and a `groups` array. Each group has dedup-aware `stats`, its `clone_groups` (each with `primary_owner` and a per-instance `owner`), and `clone_families`. SARIF results have `properties.group`, and CodeClimate issues have a top-level `group` field. Compact and markdown print ungrouped output with a note on stderr. You cannot combine it with `--top`: fallow computes the stats of each group over all its clone groups, and a global top-N cut would make the stats describe groups that the output does not list. |
| `--explain` | Add metric explanations. In human format, prints a `Description:` line under each section header. In JSON format, adds a `_meta` object with metric descriptions and docs links. |
| `--explain-skipped` | In human and markdown output, show a per-pattern count of the files that the default duplicates ignores skipped. Machine formats do not show this note. |
| `--summary` | Print a one-line summary of the duplication counts at the end of the run. In JSON format, adds a `summary` counts object. |
| `--no-fragments` | Omit the verbatim source text from `clone_groups[].instances[].fragment` in `--format json`. On a codebase with much duplication, this text is most of the payload. Each instance still has `file`, `start_line`, `end_line`, `start_col`, and `end_col`, which point to the same code. Nothing else changes, because fallow computes fingerprints, suggested names, refactoring suggestions, and `actions[]` before serialization. |

### Incremental

| Flag | Description |
|:-----|:------------|
| `--changed-since <REF>` | Report only duplication in files changed since a git ref |
| `--baseline <PATH>` | Compare against a previously saved baseline file |
| `--save-baseline <PATH>` | Save the current duplication as a baseline file. If the destination has a baseline of another `kind`, fallow refuses the save with exit 2. A destination with no `kind` gets one on the next save. |
| `--fail-on-stale-baseline` | Exit 1 when the loaded baseline has any entry that matched no current clone group; see [global flags](/cli/global-flags) |

When a quarter or more of the saved entries match no current clone group, the run prints a warning on stderr with the command to save the baseline again. A run narrowed by `--changed-since` or `--production` prints no warning, because it cannot judge a whole-project baseline. `--workspace`, `--changed-workspaces`, `--diff-file` and a positional path narrow only the rendered report. The comparison, and a new save, still cover the whole project.

When the run loaded a baseline, the JSON output of an analysis run has a `baseline_staleness` object. It contains:

- the counts
- `current_findings`
- `change_scoped`
- the advisory result as `warning`
- `gate_trips`, which applies the rule of `--fail-on-stale-baseline`, so a CI integration reads one boolean and does not need to know the rule

`fallow report --from` renders a saved envelope again, and it includes the object only when that envelope already had it. Read `change_scoped` before you divide the counts: a narrowed run can report `matched_entries: 0` on a healthy baseline.

`scope_reasons` names what narrowed the run, so you do not have to guess which input caused it. It is present and not empty exactly when `change_scoped` is true. `dupes` compares before the report filters run, so it reports only the inputs that narrow the analysis: `changed-files` for a resolved changed-file set, and `production`. Each command reports what it can see, so the names differ per command. Expect new names in the set.

A run can load a baseline with entries and use only `--changed-since`. Such a run also adds a `recheck-baseline` entry to `next_steps[]` with the unscoped command. That command reads the baseline again and reports. It never saves the baseline again. A run in production mode adds no entry. Production mode can come from the config and the environment as well as from a flag, so the command in the entry would be just as narrow.

Each command writes its own baseline format, and a saved baseline names that format. Every file that `--save-baseline` writes has a top-level `kind` of `dead-code`, `dupes` or `health`. A baseline from an earlier release has no `kind` and still loads. For such a file, its keys decide the format.

`fallow dupes --baseline` loads a baseline of another kind as zero clone groups, so no entry stays unmatched. Such a run prints a warning on stderr, with or without `--quiet`, that names both kinds and the path. It reports `baseline_staleness.unrecognised_format: true` and suppresses nothing. The field is present only when it is true. An absent field means false. Read this field and not `baseline_entries == 0`, because a baseline from a project with no duplication is correctly empty. The baseline gate trips on such a file, so `--fail-on-stale-baseline` exits 1. A run with no gate turned on keeps its exit code.

#### Token cache

On large projects, `fallow dupes` caches tokenized source, so later runs do not tokenize unchanged files again. The cache is on for projects with at least `duplicates.minCorpusSizeForTokenCache` source files (default `5000`). It is stored per project under `<root>/.fallow/cache/dupes-tokens-vN/`. On the first save, the cache writes a `.gitignore` file with `*` next to it, so `git status` does not show its contents.

- To disable the cache for one run, pass `--no-cache`.
- To keep the cache off on larger projects, set a higher `minCorpusSizeForTokenCache`.

Below the threshold, the cache stays off: on small projects, loading and saving the cache costs more time than it saves.

With `--changed-since`, on a project with at least `duplicates.minCorpusSizeForShingleFilter` files (default `1024`), fallow also drops some unchanged files before it builds the suffix array. It drops each unchanged file whose k-token shingles do not overlap any changed file. You set both options in the `[duplicates]` section of `.fallowrc.json`, `.fallowrc.jsonc`, `fallow.toml`, or `.fallow.toml`.

#### Default generated-output ignores

By default, `fallow dupes` skips common framework output: `.next`, `.nuxt`, `.svelte-kit`, `.turbo`, `.parcel-cache`, `.vite`, `.cache`, `out`, and `storybook-static`. Fallow adds these defaults to `duplicates.ignore`. They do not replace your configured ignores.

By default, fallow also skips test and mock files: `*.test.*`, `*.spec.*`, `__tests__/`, and `__mocks__/` paths. Test setup is often repetitive on purpose, and it causes much noise on the first run of a hand-coded project. These patterns are part of the same `ignoreDefaults` set as the generated-output ignores.

```jsonc
{
  "duplicates": {
    "ignoreDefaults": true,
    "ignore": ["**/__generated__/**"]
  }
}
```

To opt out and use only your `duplicates.ignore` list, set `ignoreDefaults` to `false`.

#### Reviewed clone groups

To accept one clone group and keep all other duplication findings, add the group to `duplicates.ignoredClones`:

```jsonc
{
  "duplicates": {
    "ignoredClones": ["dup:6f12ab34:2"]
  }
}
```

The key is `<fingerprint>:<instance_count>`. Copy the fingerprint from the human listing or from `clone_groups[].fingerprint` in JSON. When the tokens change or a new occurrence appears, fallow reports the group again. An edit that changes only the formatting keeps the same fingerprint.

Collision handles use `dup:<16hex>-rN`. Ordinary short and widened handles do not change. Older `dup:<16hex>-N` handles no longer select or suppress a group.

- To replace a saved key, run `fallow dupes` again and review the reported group. Do not insert `r` into the old handle.
- Upgrade all runners before you add `-rN` keys to a shared `ignoredClones` configuration.

For the baseline behavior, see [migrating collision handles](/analysis/duplication#migrating-collision-handles).

### Monorepo scoping

Both flags keep only the clone groups with at least one instance under a selected workspace root. Fallow still builds the full cross-workspace index. It then computes the reported groups and the `duplication_percentage` stat again from the scoped part.

| Flag | Description |
|:-----|:------------|
| `-w, --workspace <PATTERNS>` | Scope output to one or more workspaces. Accepts exact package names, globs (`apps/*`, `@scope/*`) matched against the package name and the workspace path, and `!`-prefixed negation. Pass comma-separated values or repeat the flag. |
| `--changed-workspaces <REF>` | Monorepo CI scoping from git: scope to the workspaces that contain a file changed since `REF` (for example, `origin/main`). Cannot be combined with `--workspace`. A missing ref is a hard error (exit 2). Fallow does not fall back to the full scope. |

### Debugging

| Flag | Description |
|:-----|:------------|
| `--trace <FILE:LINE \| dup:<fp>>` | Show clone details. `FILE:LINE` shows all clones at a source location. `dup:<id>` shows one clone group by the stable fingerprint from the listing (and from `clone_groups[].fingerprint` in JSON). Fingerprints are usually `dup:<8hex>`, and become longer only on rare report collisions. The trace shows the fingerprint of each group, an extract-function suggestion with estimated savings, and a best-effort proposed name. |
| `--performance` | Show the time of each pipeline stage |

## Detection modes

<Accordion title="Detection mode details">
  Each mode normalizes more syntax than the previous one before it compares code. You find more clones, with less precision.

  | Mode | What it normalizes | Best for |
  |:-----|:-------------------|:---------|
  | **strict** | Nothing: exact token match | Finding verbatim copies |
  | **mild** | Currently equivalent to strict (AST tokenization inherently strips whitespace) | General-purpose detection (default) |
  | **weak** | + string literal values | Catching copies with different messages |
  | **semantic** | + variable names and numeric values | Finding structural clones after renaming |

  From `strict` to `semantic`, you find more clones and also more possible false positives. Start with `mild`, and increase the sensitivity when you need to.
</Accordion>

## Ranking and JSON fields

The default report and `--top` rank clone groups by duplicated token count times occurrence count, with a spread boost. `spread` is the maximum directory-tree distance between instances. In a same-file group, each 250 lines between instances count as one spread step. The boost is at most 15%.

Each JSON `clone_groups[]` entry has these fields:

- `spread`: maximum directory or same-file line distance
- `similarity`: lowest all-pairs similarity for near-miss groups, omitted for exact groups

### Shown versus measured

`stats` always describes the corpus that the run measured. A presentation cap such as `--top` shortens the arrays and does not change `stats`. Four counters on the envelope report the split:

| Field | Meaning |
|:------|:--------|
| `clone_groups_shown` | Length of `clone_groups[]`. |
| `clone_groups_omitted` | Groups a presentation cap withheld. `0` on an untruncated run. |
| `clone_families_shown` | Length of `clone_families[]`. |
| `clone_families_omitted` | Families a presentation cap withheld. `0` on an untruncated run. |

`clone_groups_shown + clone_groups_omitted` always equals `stats.clone_groups`. In the same way, the family counters add up to `stats.clone_families`. Read `clone_groups_shown` for the number of groups in the array. Read `stats.clone_groups` for the number of groups in the project.

Scope filters work differently from presentation caps. `--changed-since`, `--workspace`, and a duplication baseline narrow the corpus itself. Fallow computes `stats` again for the narrowed corpus, and reports nothing as omitted.

The human output gives the same information in words. A capped run ends the listing with the counts that it withheld:

```text
  ... and 63 more clone groups
  ... and 52 more clone families withheld by the same display limit
```

With `--summary`, the counts block shows the corpus totals next to the shown counts. This makes it clear that the numbers cover two scopes:

```text
       2  Clone families
       2  Clone groups
   2,605  Duplicated lines
    9.5%  Duplication rate
  ... and 63 more clone groups and 52 more clone families withheld by a display limit
  Corpus totals: 65 clone groups, 54 clone families; duplicated lines and rate cover all of it
```

The `stats` object can also include these fields. Fallow omits them when they are zero.

- `clone_groups_ignored`, when `duplicates.ignoredClones` hides groups
- `near_candidates_skipped`, when bounded-work limits skip near-miss comparisons

## Examples

<CodeGroup>
```bash Default analysis
# Mild mode (default)
fallow dupes
```

```bash Filtering
# Show only the 10 largest clone groups
fallow dupes --top 10

# Top 5 semantic clones, cross-directory only
fallow dupes --top 5 --mode semantic --skip-local
```

```bash Advanced detection
# Catch renamed-variable clones
fallow dupes --mode semantic

# Include function-scoped clones with small structural edits
fallow dupes --near

# Only cross-directory duplicates
fallow dupes --skip-local

# TS to JS comparison
fallow dupes --cross-language

# Count sorted import blocks as clones (opt out of the default exclusion)
fallow dupes --no-ignore-imports
```

```bash CI integration
# Only check duplication in changed files
fallow dupes --changed-since main

# Fail CI if duplication exceeds 5%
fallow dupes --threshold 5

# SARIF output for GitHub
fallow dupes --format sarif > dupes.sarif
```

```bash Debugging
# Trace clones at a specific line
fallow dupes --trace src/utils.ts:42

# Deep-dive a clone group by its dup:<id> fingerprint (from the listing or JSON)
fallow dupes --trace dup:7f3a2c1e

# Performance breakdown
fallow dupes --performance
```
</CodeGroup>

## JSON output

### `mirrored_directories`

When fallow detects two directories that are mostly duplicates (for example, a `deno/` mirror of `src/`), the JSON output includes a `mirrored_directories` array:

```json
{
  "mirrored_directories": [
    {
      "dir_a": "deno/lib",
      "dir_b": "src",
      "shared_files": ["client.ts", "handlers.ts", "types.ts", "utils.ts"],
      "total_lines": 6347
    }
  ]
}
```

Each entry names the two directories, the shared filenames, and the total duplicated lines in those files.
