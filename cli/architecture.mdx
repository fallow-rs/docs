`fallow architecture` reports import cycles, boundary violations and rule-pack policy violations.

For the concepts and the workflow, read [Architecture](/analysis/architecture).

## Synopsis

```bash
fallow architecture [OPTIONS] [PATH]
```

## Options

{/* generated:start cli-options architecture */}

| Argument | Description |
|:--|:--|
| `[PATH]` | Scope reported findings to this file or directory (default: whole project). The full project graph is still built; only reported items are narrowed |

| Option | Description |
|:--|:--|
| `--shared-state` | Inventory direct imported writes and custom global access sites |
| `--cycles` | Only report import cycles: circular dependencies, re-export cycles and package cycles |
| `--boundaries` | Only report boundary violations, boundary coverage and forbidden calls |
| `--policy` | Only report rule-pack policy violations |
| `--file <PATH>` | Only report issues in the specified file(s). Accepts multiple values. |
| `--finding-id <ID>` | Only report the findings with these `finding_id` values. Repeat the flag or pass a comma-separated list |

- Without `--cycles`, `--boundaries` or `--policy`, the command reports all three groups. You can give more than one.
- `--cycles` reports [circular dependencies](/rules/circular-dependency), [re-export cycles](/rules/re-export-cycle) and [package cycles](/rules/package-cycle). `--boundaries` reports [boundary violations](/rules/boundary-violation), [boundary coverage](/rules/boundary-coverage) and [forbidden calls](/rules/boundary-call-violation). `--policy` reports [policy violations](/rules/policy-violation).
- `fallow dead-code` with `--circular-deps`, `--re-export-cycles`, `--package-cycles`, `--boundary-violations` or `--policy-violations` reports the same findings, with the same finding ids.

### Shared-state inventory {#shared-state-inventory}

`--shared-state` adds a list of the places where code writes to an imported value, and of the custom properties of `window`, `globalThis`, `self` or `global` that more than one file reads or writes. Alone, it selects only the inventory. With `--cycles`, `--boundaries` or `--policy`, the run also reports those findings.

- The inventory is not a finding. It does not change the totals, the health score, a baseline or the exit code.
- Only the `human`, `json` and `markdown` formats show it. Another format, `--sarif-file`, `--group-by` or `--finding-id` together with `--shared-state` exits with code 2.
- The inventory uses static property keys only. It leaves out aliases, dynamic keys, `Object.assign` and destructuring targets.
- The `shared-state` suppression token and the [`sharedStateAllowlist`](/reference/config-dead-code#sharedstateallowlist) config key remove a site from the inventory.

## Output

```text
  3 entry points detected (2 package.json, 1 plugin)

── Architecture ─────────────────────────────────────

● Circular dependencies (1)
  src/services/catalog.ts
    → orders.ts → catalog.ts

  Import cycles that can cause initialization failures and prevent tree-shaking
  https://fallow.tools/docs/explanations/dead-code/#circular-dependencies

● Boundary violations (1)
  src/lib/format.ts:1 → src/services/catalog.ts (lib → services)
  Imports that cross defined architecture zone boundaries
  https://fallow.tools/docs/explanations/dead-code/#boundary-violations

✗ 1 circular dependency · 1 boundary violation (0.16s)
```

- A cycle shows its first file, then the files of the loop.
- A boundary violation shows the importing file and line, the imported file, and the two zones.
- The last line counts the findings of each issue type.

With `--format json`, the output has the shape of the [`fallow dead-code` output](/cli/dead-code#output), with these differences:

| Field | Content |
|:--|:--|
| `kind` | `"architecture"`. A `--group-by` run gives `"architecture-grouped"`. |
| `schema_version` | The version of the architecture output format, separate from the version of `dead-code`. |
| `circular_dependencies`, `re_export_cycles`, `package_cycles` | The cycle findings. |
| `boundary_violations`, `boundary_coverage_violations`, `boundary_call_violations` | The boundary findings. |
| `policy_violations` | The rule-pack findings. |
| `shared_state` | The inventory: `version`, `complete`, `truncated`, `imported_writes` and `globals`. Present only with `--shared-state`. |

The other issue arrays of `dead-code` are present and empty. The [JSON output reference](/reference/json-output) has each field.

A `fallow architecture` baseline has the `dead-code` format and `"kind": "dead-code"`. Because the run reports only some issue types, `--fail-on-stale-baseline` does not gate this command: the `stale-baseline` gate has the status `skipped`.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | No finding at `error` severity, and no other gate failed. |
| `1` | A finding has a rule at `error`. By default, circular dependencies, boundary violations, boundary coverage and forbidden calls are at `error`. Re-export cycles, package cycles and policy violations are at `warn`. |
| `2` | Invalid input, for example `--shared-state` with `--format sarif`. |

[Exit codes](/reference/exit-codes) has the codes that all commands share.

## Examples

```bash
# Report cycles, boundaries and policy rules
fallow architecture

# Report only the import cycles in files that changed since main
fallow architecture --cycles --changed-since main --format json --quiet

# Report only the boundary findings of one workspace
fallow architecture --boundaries --workspace web

# List the writes to imported values and to shared globals
fallow architecture --shared-state --format json

# Render a saved result as a GitHub job summary
fallow architecture --format json -o results.json
fallow report --from results.json --format github-summary
```
