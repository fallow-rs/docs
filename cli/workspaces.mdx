Show the [workspaces](/concepts/workspaces) that fallow finds in a monorepo, and the problems of the workspace setup. The command gives the same result as `fallow list --workspaces`.

For the setup of a monorepo, read [Monorepos](/guides/monorepo).

## Synopsis

{/* generated:start cli-synopsis workspaces */}

```bash
fallow workspaces [OPTIONS]
```

{/* generated:end */}

## Output

```bash
fallow workspaces
```

```text
Discovered 2 workspaces
  @acme/api -> packages/api (internal dep)
  @acme/web -> packages/web
1 workspace discovery diagnostic:
  - Dropped workspace 'packages/broken': package.json is not valid JSON (Failed to parse packages/broken/package.json: EOF while parsing a value at line 2 column 0). Fix the JSON syntax or remove 'packages/broken' from the workspaces pattern.
```

Each line gives the package name and its directory. `internal dep` marks a package that another workspace lists as a dependency. Each diagnostic gives a problem and its fix.

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"list-workspaces"` |
| `workspace_count` | The number of workspaces. |
| `workspaces` | One object for each workspace: `name`, `path`, `is_internal_dependency`. |
| `workspace_diagnostics` | One object for each problem: `kind`, `path`, `message`, `degrades_analysis`, and fields of the kind. [Workspace diagnostics](/cli/list#workspace-diagnostics) lists each kind. |

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The list completed, also with diagnostics. |
| `2` | The root `package.json` does not parse, or other invalid input. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Show the workspaces and the problems of the setup
fallow workspaces

# Get the workspaces as JSON
fallow workspaces --format json --quiet

# Analyze only one workspace
fallow dead-code --workspace @acme/api
```
