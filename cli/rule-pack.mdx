Create, list and test rule packs. A rule pack is a JSON or JSONC file with project policy rules, for example a banned import or a banned call. The `rulePacks` config key names the packs.

For policy rules and their findings, read [Architecture](/analysis/architecture).

### init {#init}

Create a pack file from a template, and add its path to `rulePacks` in the [config file](/configuration/overview).

{/* generated:start cli-synopsis rule-pack init */}

```bash
fallow rule-pack init [OPTIONS] [NAME]
```

{/* generated:end */}

{/* generated:start cli-options rule-pack init */}

| Argument | Description |
|:--|:--|
| `[NAME]` | Pack name (default: the template name, or "team-policy") |

| Option | Default | Description |
|:--|:--|:--|
| `--template <TEMPLATE>` | `starter` | Template: starter, ai-safe-repo, side-effect-free-domain, clean-architecture, next-app-router |
| `--dir <DIR>` | `rule-packs` | Directory for the pack file, relative to the project root |
| `--no-config` |  | Only write the pack file; do not modify the config |

{/* generated:end */}

The command writes `<DIR>/<NAME>.jsonc`, and stops with code 2 when the file exists. Without a config file, or when fallow cannot change the file safely, it prints the `rulePacks` line to add.

| Template | Rules |
|:--|:--|
| `starter` | A `banned-import` and a `banned-call` rule to edit. |
| `ai-safe-repo` | No dynamic code execution, no process or shell calls, no raw HTML. |
| `side-effect-free-domain` | No I/O effects in domain code and shared utilities. |
| `clean-architecture` | The domain layer does not import I/O adapters or frameworks. |
| `next-app-router` | No Pages Router APIs in Next.js App Router code. |

A `PACK` path works also when the config does not name the file. When the severity of `policy-violation` is `off`, the test uses `warn`, and the JSON field `forced_severity` is `true`.

## Output

```bash
fallow rule-pack test
```

```text
error  ai-safe-repo/no-dynamic-code  1 finding
  src/utils/summary.ts:24:37  matched "eval"
error  ai-safe-repo/no-shell  1 finding
  src/utils/summary.ts:24:37  matched "process: eval"
no findings:
  error  ai-safe-repo/no-raw-html  banned-call
```

Each rule with matches gives its severity, its id as `<pack>/<rule>`, and the number of matches. An indented line gives the file, the line, the column and the matched token of each match. `no findings:` lists the rules without a match.

```bash
fallow rule-pack list
```

```text
ai-safe-repo (rule-packs/ai-safe-repo.jsonc): 3 rules
  Guardrails for repositories where AI agents write code: no dynamic code execution, no shelling out, no raw HTML sinks.
  - no-dynamic-code [error] banned-call: eval, Function
    Dynamic code execution is banned in this repository.
```

With `--format json`, `list` prints `kind: "rule-pack-list"` with `packs`. Each rule has `id`, `kind`, `severity`, `patterns`, `files`, `exclude` and `message`, and `allowNames` for a `banned-import` rule that has it. `test` prints `kind: "rule-pack-test"` with `packs`, `rules` (the number of matches of each rule), `findings` and `forced_severity`. The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The command completed. `test` also exits with `0` when it finds matches. |
| `2` | Invalid input, for example `test` without a configured pack, a pack that does not parse, or a pack file that `init` would overwrite. |

To fail a CI run on a policy violation, run [`fallow architecture`](/cli/architecture). See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Create rule-packs/team-policy.jsonc from the starter template
fallow rule-pack init

# Create a pack from a template, and do not change the config file
fallow rule-pack init --template ai-safe-repo --no-config

# Test one pack file against the project
fallow rule-pack test rule-packs/team-policy.jsonc

# List the configured packs as JSON
fallow rule-pack list --format json
```
