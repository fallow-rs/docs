The `fallow` program runs each analysis as a command. Without a command, it runs the main analyses together.

For a first run, read the [Quickstart](/quickstart).

## Synopsis

{/* generated:start cli-synopsis fallow */}

```bash
fallow [OPTIONS] [PATH] [COMMAND]
```

## The bare run {#bare-run}

`fallow` without a command runs [dead code](/cli/dead-code), [architecture](/cli/architecture), [duplication](/cli/dupes) and [health](/cli/health) on the project. The human output shows one section for each analysis, then one line that names each analysis that failed. `--only` and `--skip` select the analyses.

These options apply only to the bare run:

{/* generated:start cli-options fallow */}

| Argument | Description |
|:--|:--|
| `[PATH]` | Scope reported findings to this file or directory (default: whole project). The full project graph is still built; only reported items are narrowed |

| Option | Description |
|:--|:--|
| `-v, --version` (alias `-V`) | Print version. Accepts `-v`, `-V`, and `--version`; TS/JS tooling (node, npm, pnpm, yarn, bun, tsc) uses `-v`, while `-V` matches knip/oxlint/biome |
| `--production-dead-code` | Run dead-code analysis in production mode when using bare combined mode |
| `--production-health` | Run health analysis in production mode when using bare combined mode |
| `--production-dupes` | Run duplication analysis in production mode when using bare combined mode |
| `--only <ONLY>` | Run only specific analyses when no subcommand is given. Values: `dead-code` (alias `check`), `dupes`, `health`, `architecture`. |
| `--skip <SKIP>` | Skip specific analyses when no subcommand is given. Values: `dead-code` (alias `check`), `dupes`, `health`, `architecture`. |
| `--score` | Compute health score in combined mode |
| `--trend` | Compare current health metrics against the most recent saved snapshot |
| `--trend-from <PATH>` | Compare current health metrics against this snapshot file in combined mode. Implies --trend and --score |
| `--save-snapshot <PATH>` | Save a vital signs snapshot for trend tracking in combined mode. Provide a path or omit for the default `.fallow/snapshots/` location. |
| `--coverage <PATH>` | Path to Istanbul or raw V8 coverage data for measured CRAP scores in combined mode. Also settable via `FALLOW_COVERAGE` or `health.coverage` |
| `--coverage-root <PATH>` | Absolute prefix to strip from Istanbul file paths in combined mode. Also settable via `FALLOW_COVERAGE_ROOT` or `health.coverageRoot` |
| `--dupes-baseline <PATH>` | Compare duplication clone groups against a saved baseline in combined mode (produced by `fallow dupes --save-baseline`) |
| `--health-baseline <PATH>` | Compare health findings against a saved baseline in combined mode (produced by `fallow health --save-baseline`) |

{/* generated:end */}

The bare run also accepts the `--dupes-*` options of the [global options](/cli/global-flags). With `--format json`, the output has the `kind` `"combined"` and one section for each analysis: `check`, `dupes` and `health`. The [JSON output reference](/reference/json-output) has each field.

## Output formats {#output-formats}

`--format` selects the output. Not every command accepts every format.

| Format | Use |
|:--|:--|
| `human` | The default. A report for the terminal. |
| `json` | The full result for scripts and agents. Add `--pretty` to indent it. |
| `sarif` | SARIF 2.1.0, for GitHub code scanning and other SARIF readers. |
| `compact` | One line for each finding, for `grep` and editors. |
| `markdown` (alias `md`) | A Markdown report. |
| `codeclimate` (alias `gitlab-codequality`, `gitlab-code-quality`) | A Code Climate report, for GitLab Code Quality. |
| `pr-comment-github`, `pr-comment-gitlab` | The body of one pull request or merge request comment. |
| `review-github`, `review-gitlab` | A JSON document with inline review comments on the changed lines. |
| `github-annotations` | GitHub workflow-command annotations. They show on pull requests from a fork without a write token. |
| `github-summary` | Markdown for the GitHub Actions job summary (`>> "$GITHUB_STEP_SUMMARY"`). |
| `badge` | An SVG badge with the health score. `fallow health` only. |

[CI integration](/integrations/ci) shows these formats in a pipeline.

## Exit codes

`0` means that no gate failed. `1` means that a [gate](/concepts/findings) failed, for example a finding at `error` severity. `2` means invalid input or an execution error. [Exit codes](/reference/exit-codes) lists each code, also the codes of one command.

## Scripts and agents {#scripts-and-agents}

- Use `--format json` and parse the JSON. Do not parse the human output.
- Use `--quiet` to hide the progress output on stderr.
- The bare run in `json`, `sarif`, `codeclimate`, the GitHub formats and the comment and review formats exits with code 0 on findings. Read `gate_outcomes`, or pass `--fail-on-issues` to exit with code 1.
- With `--format json`, an error prints `{"error": true, "message": "...", "exit_code": 2}` on stdout.
- Run `fallow fix --dry-run --format json --quiet` before a change to files. [Agents](/integrations/agents) has the full rules.
