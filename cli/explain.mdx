Get a short rule guide for one issue type before you decide to fix, suppress, or configure a finding. `fallow explain` does not run analysis. Agents and CI bots use it to read the rule before they act.

```bash
fallow explain unused-export
fallow explain fallow/code-duplication --format json --quiet
```

## Arguments

| Argument | Description |
|:---------|:------------|
| `<issue-type>` | Issue type token or rule id, for example `unused-export`, `fallow/unused-dependency`, `high-complexity`, or `code-duplication`. Fallow also accepts common plural aliases such as `unused-exports`. |

## Output

| Format | Description |
|:-------|:------------|
| `human` | Rule id, summary, rationale, example, fix guidance, and docs URL. |
| `json` | An object with the same fields. Use this format from agents. |

```json title="$ fallow explain unused-export --format json --quiet"
{
  "id": "fallow/unused-export",
  "name": "Unused Exports",
  "summary": "Export is never imported",
  "rationale": "Named exports that are never imported by any other module in the project. Includes both direct exports and re-exports through barrel files. The export may still be used locally within the same file.",
  "example": "export const formatPrice = ... exists in src/money.ts, but no module imports formatPrice.",
  "how_to_fix": "Remove the export or make it file-local. If it is public API, import it from an entry point or add an intentional suppression with context.",
  "docs": "https://docs.fallow.tools/explanations/dead-code#unused-exports"
}
```

## MCP tool

The `fallow_explain` MCP tool runs `fallow explain <issue-type> --format json --quiet`:

```json title="Example request"
{
  "tool": "fallow_explain",
  "arguments": {
    "issue_type": "unused-export"
  }
}
```

An agent can call it to read the rule before it applies a fix or a suppression.
