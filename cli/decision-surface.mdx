List the few structural decisions of a change as questions, each with the person to ask and the cost of the choice.

For the review of changed code, read [Changed-code analysis](/analysis/changed-code).

## Synopsis

{/* generated:start cli-synopsis decision-surface */}

```bash
fallow decision-surface [OPTIONS]
```

{/* generated:end */}

## Options

{/* generated:start cli-options decision-surface */}

| Option | Default | Description |
|:--|:--|:--|
| `--max-decisions <N>` | `4` | Cap on the number of surfaced decisions (the working-memory limit). Default 4; clamped to the range 3 to 5 |

The [global options](/cli/global-flags) are in these groups: [Project](/cli/global-flags#options-project), [Output](/cli/global-flags#options-output), [Scope](/cli/global-flags#options-scope), [Baselines](/cli/global-flags#options-baselines), [Gates](/cli/global-flags#options-gates), [Duplication](/cli/global-flags#options-duplication), [Type-aware](/cli/global-flags#options-type-aware), [Performance](/cli/global-flags#options-performance).

{/* generated:end */}

Fallow clamps `--max-decisions` to the range 3 to 5. Set the comparison point with the global option `--base` or `--changed-since`, as for [`fallow audit`](/cli/audit). Without it, fallow uses the merge base with the default branch. The human output goes to stderr, so `--quiet` hides it. Use `--quiet` only with `--format json`.

## Output

```bash
fallow decision-surface --base main
```

```text
Decisions to make (1):
  1. [dependency] `package.json` adds 1 third-party dependency (`uuid`),
       imported by 1 in-repo module. What does each replace, and who owns the
       new surface?
     trade-off: Takes on 1 new maintenance and supply-chain surface; 1 in-repo
       module outside this diff already imports the added packages.
```

Each decision has a category in brackets, a question, the structural cost after `trade-off:`, and, when the history names them, the owners to ask after `ask:`. `bus-factor 1` means that one person owns the file. A change without decisions prints `Decisions: none (no consequential structural decision in this change)`.

The categories are `coupling-boundary` (a new import across zones), `public-api-contract` (a new or changed public export) and `dependency` (a new package, or a new major version of a package). Fallow ranks the decisions by the number of modules outside the change that they affect.

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"decision-surface"` |
| `schema_version` | The version of this output format. |
| `version` | The fallow version. |
| `command` | `"decision-surface"` |
| `decisions` | One object for each decision, ranked. |
| `signal_count` | The number of decisions that fallow found, also the ones above the cap. |
| `truncated` | Present when the cap left decisions out. |

Each decision has these fields:

| Field | Content |
|:--|:--|
| `signal_id` | A stable id of the decision, for example `sig:efab2fe6cef7b663`. The same tree gives the same id. |
| `signal_key` | The value that `signal_id` is a hash of, for example `package.json::uuid`. |
| `previous_signal_id` | The id before a rename of the anchor file. Present only after a rename. |
| `category` | `coupling-boundary`, `public-api-contract` or `dependency`. |
| `question` | The decision as a question. |
| `anchor_file`, `anchor_line` | The file and the line of the decision. Line `0` is the start of the file. |
| `tradeoff` | The cost of the choice, as a fact. |
| `expert` | The owners to ask. Empty when fallow has no ownership data for the file. |
| `bus_factor_one` | `true` when one person owns the file. |
| `internal_consumer_count` | The number of modules outside the change that depend on the anchor. A higher number makes the choice harder to undo. |
| `blast`, `consequence` | The rank inputs. Fallow sorts on `consequence`, highest first. |
| `actions` | `ask-expert` when `expert` is not empty. `suppress` with the comment to add, except for `dependency`. |

To hide a `coupling-boundary` or `public-api-contract` decision, add `// fallow-ignore-next-line decision-surface <category>` above its anchor. See [Suppression](/configuration/suppression). The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The analysis completed. Decisions never set a gate. |
| `2` | Invalid input, for example a base ref that does not exist, or `--baseline`. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# List the decisions of the current branch against main
fallow decision-surface --base main

# Show five decisions
fallow decision-surface --base main --max-decisions 5

# Get the decisions as JSON for an agent
fallow decision-surface --base main --format json --quiet

# List the decisions for one workspace package
fallow decision-surface --base main --workspace @app/api
```
