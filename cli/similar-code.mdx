`fallow similar-code` finds pairs of functions that may do the same job, also when their code is different.

For the concepts and the workflow, read [Similar code](/analysis/similar-code).

## Synopsis

{/* generated:start cli-synopsis similar-code */}

```bash
fallow similar-code [OPTIONS] [PATH] [COMMAND]
```

{/* generated:end */}

The command is opt-in. Bare `fallow`, `fallow audit`, `fallow dupes` and the CI formats do not run it. It needs the `fallow-similar-code` program next to the `fallow` executable and a model that `setup` downloads.

## Subcommands

{/* generated:start cli-subcommands similar-code */}

| Subcommand | Description |
|:--|:--|
| [`status`](#status) | Show exact companion and pinned-model readiness without reading project source |
| [`setup`](#setup) | Download and verify the pinned local model after explicit confirmation |
| [`inspect`](#inspect) | Reproduce and inspect one unverified candidate with bounded source evidence |
| [`review`](#review) | Join candidate JSON with a separate human or agent verdict document |
| [`cache`](#cache) | Manage the user-local, project-namespaced vector cache. |

{/* generated:end */}

Without a subcommand, `fallow similar-code` compares the functions of the project and prints the candidates.

## Options

These options apply to the run without a subcommand.

{/* generated:start cli-options similar-code */}

| Argument | Description |
|:--|:--|
| `[PATH]` | Scope reported findings to this file or directory (default: whole project). The full project graph is still built; only reported items are narrowed |

| Option | Description |
|:--|:--|
| `--threshold <0..1>` | Minimum cosine similarity retained as an unverified candidate |
| `--min-lines <N>` | Minimum source lines per extracted function |
| `--top <N>` | Cap displayed candidates after bounded full-corpus comparison |
| `--file <PATH>` | Report pairs touching one of these project-relative files |

{/* generated:end */}

`--threshold` and `--min-lines` take their default from the [`similarCode` config](/reference/config-duplication#similarcode). The command accepts the `human` and `json` formats, and these [global options](/cli/global-flags): `--root`, `--config`, `--allow-remote-extends`, `--format`, `--pretty`, `--quiet`, `--no-cache`, `--threads`, `--changed-since`, `--diff-file`, `--diff-stdin`, `--workspace`, `--changed-workspaces`, `--max-file-size`, `--explain` and `--output-file`. A scope option compares only the pairs in which at least one function is fully in scope.

## Output

The human output starts with the line `Similar-code candidates (unverified)`. Each candidate then has these lines:

- the candidate id, the cosine similarity and its band
- the file, the line and the name of each of the two functions
- an `Inspect:` line with the `fallow similar-code inspect` command for the candidate

The output ends with a `Completion:` line (`Complete` or `Partial`) and a `Cache:` line with the cache hits and misses.

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"similar-code"`. The subcommands give `"similar-code-status"`, `"similar-code-inspect"`, `"similar-code-review"` and `"similar-code-cache-clear"`. |
| `schema_version`, `version`, `elapsed_ms` | The version of this output format, the fallow version and the run time. |
| `generation` | The provider, the model and the parameters of the run. |
| `candidates` | The unverified candidates, in a fixed order. |
| `completion` | Whether the run compared every function, and the cache statistics. Read it before you conclude that no candidate exists. |
| `diagnostics` | Notes about the run, in a fixed order. |

The `status` output has `model_ready`, `integrity_verified`, `model_id`, `model_revision`, `license`, `download_bytes`, `cache_dir`, and `problem` when the model is not ready. The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The command ran. Candidates do not change the exit code. |
| `2` | Invalid input, for example `cache clear` without `--yes`, an invalid verdict document, or a candidate without a verdict under `--require-verdict-for-each-candidate`. |
| `3` | The `fallow-similar-code` program is missing, or the model is not ready. Run `fallow similar-code setup --local`. |

[Exit codes](/reference/exit-codes) has the codes that all commands share.

## Examples

```bash
# Check that the program and the model are ready
fallow similar-code status

# Download and verify the model
fallow similar-code setup --local

# Save the candidates of the project
fallow similar-code --format json --quiet > similar-code.json

# Show the code and the evidence of one candidate
fallow similar-code inspect <CANDIDATE_ID> --candidates similar-code.json

# Join the candidates with your verdicts
fallow similar-code review --candidates similar-code.json --verdicts verdicts.json
```
