For the GitLab setup and the template variables, read [GitLab CI](/integrations/ci-gitlab).

### gitlab {#gitlab}

Print the GitLab CI template, or write it and its helper scripts with `--vendor`.

{/* generated:start cli-synopsis ci-template gitlab */}

```bash
fallow ci-template gitlab [OPTIONS]
```

{/* generated:end */}

{/* generated:start cli-options ci-template gitlab */}

| Option | Description |
|:--|:--|
| `--vendor <DIR>` | Write the template and its helper scripts under DIR/ci/ instead of printing the template. Passing --vendor without a DIR writes into the current directory. |
| `--force` | Overwrite existing files that differ from the bundled template |

The [global options](/cli/global-flags) are in these groups: [Project](/cli/global-flags#options-project), [Output](/cli/global-flags#options-output), [Scope](/cli/global-flags#options-scope), [Baselines](/cli/global-flags#options-baselines), [Gates](/cli/global-flags#options-gates), [Duplication](/cli/global-flags#options-duplication), [Type-aware](/cli/global-flags#options-type-aware), [Performance](/cli/global-flags#options-performance).

{/* generated:end */}

Without a `DIR`, `--vendor` writes below the current directory. The vendored template runs the local scripts, so a pipeline downloads no script for comments and reviews. A file with the same content as the bundled file is not a conflict. A file with other content stops the command with code 2, except with `--force`. Run the command again after an update of fallow.

## Options

`fallow ci-template` has no options of its own. The section of each subcommand under [Subcommands](#subcommands) lists its options.

## Output

```bash
fallow ci-template gitlab --vendor
```

```text
Vendored GitLab CI integration to . (6 files)
```

The command writes these files:

- `ci/gitlab-ci.yml`
- `ci/scripts/comment.sh`
- `ci/scripts/review.sh`
- `ci/scripts/gitlab_common.sh`
- `ci/scripts/mutation.sh`
- `ci/scripts/mutation_common.sh`

Include the vendored template in `.gitlab-ci.yml`:

```yaml
# .gitlab-ci.yml
include:
  - local: 'ci/gitlab-ci.yml'

fallow:
  extends: .fallow
```

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | Fallow printed or wrote the template. |
| `2` | A file exists with other content and `--force` is not set, or the input is invalid. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Print the template
fallow ci-template gitlab > fallow-gitlab-ci.yml

# Write the template and its scripts below ci/
fallow ci-template gitlab --vendor

# Write the files below another directory
fallow ci-template gitlab --vendor build

# Replace the vendored files after an update of fallow
fallow ci-template gitlab --vendor --force
```
