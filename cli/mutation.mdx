`fallow mutation` makes small changes to the code (mutants), runs the project tests against each mutant, and reports the mutants that no test detects.

For the concepts and the workflow, read [Mutation testing](/analysis/mutation).

## Synopsis

{/* generated:start cli-synopsis mutation */}

```bash
fallow mutation [OPTIONS] [PATH]... [COMMAND]
```

{/* generated:end */}

The command is opt-in. Bare `fallow`, `fallow audit` and `fallow health` do not run it. Only a run without `--plan`, and `inspect --replay`, run project code.

## Options

{/* generated:start cli-options mutation */}

| Argument | Description |
|:--|:--|
| `[PATH...]` | Mutate only these files or directories instead of the changed code |

### Scope {#options-scope}

| Option | Description |
|:--|:--|
| `--all` | Mutate every source file instead of the changed code |
| `--max-mutants <N>` | Run at most N covered mutants, in rank order. Uncovered mutants do not count. |
| `--mutants-per-line <N>` | Keep at most N mutants on each source line. The plan keeps the most productive mutants of the line (relational, condition, arithmetic and logical operators first). |
| `--function-scope` | Widen each changed line to the whole function that holds it, so that a changed parameter or signature selects the mutants of the function. Only the changed-code scope uses it (default: the `mutation.functionScope` key, else the changed lines only) |
| `--allow-side-effects` | Keep mutants in functions that reach a file system, process, network or database sink. A mutant can then remove a guard of a real side effect. |
| `--operators <NAMES>` | The operators to use, comma-separated. Default: the default set. |

### Run {#options-run}

| Option | Description |
|:--|:--|
| `--plan` | Build the plan only: select, map and rank mutants. Runs no code |
| `--time-budget <DURATION>` | Stop starting mutants after this time, for example `90s`, `10m` or `1h`. The others are `pending` |
| `--concurrency <N>` | The number of mutation runner processes (default: half the logical cores) |
| `--runtime <PATH>` | The JavaScript runtime: a name on PATH such as `node`, or a file path (default from PATH: `node` for node:test, `bun` for bun test, and `node`, then `bun`, for Vitest) |
| `--allow-dirty` | Run in a dirty git worktree. The run still reports the paths that it changed |
| `--setup-timeout <DURATION>` | Wait this long for each runner process to start, finish its dry run or reload, for example `5m` on a slow or busy host (default: `2m`) |
| `--runner-config <PATH>` | The config file of the test runner, for example `vitest.integration.config.mjs` (default: the `mutation.runnerConfig` key, else the runner's own discovery). The file must be inside the project root. |
| `--runner-project <NAME>` | Use only this Vitest project, as the Vitest `--project` flag does. Repeat the flag for more projects. |

### Detection {#options-detection}

| Option | Description |
|:--|:--|
| `--record-args <MODE>` | Record the arguments of the changed exported functions in a record pass (off by default). `shapes` keeps their types, `values` keeps the values for `fallow mutation inspect --replay`. |
| `--verdicts <PATH>` | A verdict document that marks mutants as equivalent. Equivalent mutants leave the score |
| `--typecheck` | Type-check each survived mutant through the type-aware companion. A survivor that does not type-check becomes `compile_error` and leaves the score. |
| `--kill-matrix` | Collect all killing tests and report redundant-test candidates for individual review. Run every covering test without stopping at a failure |
| `--kill-matrix-for <TARGET>` | Check whether this test is redundant: a test file (each test in it) or a test id (`file::name`). Repeat the flag for more targets. |
| `--kill-matrix-full` | With `--kill-matrix-for`: also run the other covering tests of a mutant that no target kills, and retry each survivor. Each mutant then gets a normal status, and the run has a score. |

### Gates {#options-gates}

| Option | Description |
|:--|:--|
| `--min-score <0-100>` | Exit with code 1 when the mutation score is below this percentage |

### Reruns {#options-reruns}

| Option | Description |
|:--|:--|
| `--resume` | Continue an interrupted or partial run: reuse the killed and confirmed survived mutants in its journal and run only the others. A journal of other inputs exits 2 |
| `--recheck` | Rerun the open tasks of a saved report (its `survived` and `no_coverage` mutants) against the current tests. The worktree may change test files only. |
| `--report <PATH>` | The saved report of `--recheck` (default: the report of the last run). A recheck without `--mutant` replaces this file and the report of the last run |
| `--mutant <ID>` | Recheck only these mutant ids of the report, comma-separated or repeated (default: each open task). The saved report then stays as it is, so `fallow mutation tasks` keeps the other open tasks |
| `--compare <PATH>` | Compare this run with a saved complete report: list each mutant that the report detects (`killed` or `timeout`) and this run does not (`survived` or `no_coverage`), with its earlier killing tests. A report or a run that is not complete exits 2 |

`fallow mutation` also accepts these [global options](/cli/global-flags): `--root`, `--config`, `--format` (`human` and `json`), `--quiet`, `--no-cache`, `--changed-since`, `--diff-file`, `--diff-stdin` and `--output-file`. `--workspace` and `--changed-workspaces` exit with code 2: pass a package directory as a path.

## Option details {#option-details}

### Changed-code scope {#scope}

Without `--all` or a path, the run mutates the lines that changed since the base ref. Fallow finds the base in the same way as [`fallow audit`](/cli/audit#base-ref). The changed-code scope, `--all` and a path cannot go together.

### Function scope {#function-scope}

`--function-scope`, or `mutation.functionScope: true`, widens each changed line to the function that holds it. A changed parameter or signature line then selects the mutants of the function. `--all`, a path and `--recheck` do not accept it.

### Runners {#runners}

| Runner | `mutation.runner` value | Supported versions |
|:--|:--|:--|
| Vitest | `vitest` | 4.1.0 and later, before 6.0.0, in Node mode |
| `node:test` | `node-test` | Node.js 22.18.0 and later, before 27.0.0 |
| `bun test` | `bun-test` | Bun 1.4.0 and later, before 2.0.0 |

The default value `auto` selects the runner from the project. An unsupported version stops the run before the first mutant. `--plan` shows the runner and its version.

### Runner config {#runner-config}

`--runner-config <PATH>`, or `mutation.runnerConfig`, selects the config file of the test runner, for example `vitest.integration.config.mjs`. The file must be inside the project root. Only Vitest accepts it.

### Runner projects {#runner-projects}

`--runner-project <NAME>`, or `mutation.runnerProjects`, uses only the named Vitest projects, as the Vitest `--project` option does. Only Vitest accepts it.

### Operators {#operators}

Without `--operators`, the run uses the default set. A list replaces the default set.

| Set | Operators |
|:--|:--|
| Default | `arithmetic-operator`, `relational-operator`, `logical-operator`, `negate-condition`, `unary-operator`, `update-operator`, `removed-call`, `return-value`, `boolean-literal`, `string-literal`, `optional-chaining`, `regex-literal`, `removed-chain-link` |
| Opt-in | `block-statement`, `array-literal`, `object-literal`, `method-expression`, `switch-case`, `call-expression`, `throw-statement`, `regex-constructor`, `regex-assertion`, `nullish-fallback` |

### Mutants per line {#mutants-per-line}

`--mutants-per-line <N>`, or `mutation.mutantsPerLine`, keeps at most `N` mutants on each line. Relational, condition, arithmetic and logical operators come first. A mutant that the limit leaves out is `pending` with `pending_reason: "sampled-out"`.

### Type check of survivors {#type-check-of-survivors}

`--typecheck`, or `mutation.typecheck: true`, type-checks each survivor with the program of [type-aware analysis](/cli/type-aware). A survivor that adds a type error to its file becomes `compile_error` and leaves the score. Without the program, the run exits with code 2 before the tests start.

### Result cache {#result-cache}

A run stores the result of each `killed` mutant and of each `survived` mutant that a second run confirmed, in `.fallow/mutation/results.json`. A later run reuses a result when the mutant, its source file, its tests, the runner config and the versions are the same. The key does not cover files that the tests read or import dynamically. `--no-cache` runs each mutant again.

### Safety rules {#safety-rules}

- A run refuses a git worktree with uncommitted changes, and exits with code 2. `--allow-dirty` turns off this check. After the run, the report lists each path that the tests changed.
- Fallow does not write to project files. The changed copies live in the fallow cache directory.
- A mutant in a function that calls a file system, process, network or database API is `pruned` with the reason `side-effect-sink`. `--allow-side-effects` keeps these mutants.
- Do not redirect the report with `>`: the shell creates the file first, and the worktree check refuses the run. Use `-o .fallow/mutation.json`.

### Verdict document {#verdicts-for-equivalent-mutants}

`--verdicts <PATH>` reads a document that marks mutants as equivalent: no test can detect them.

```json
// verdicts.json
{
  "schema_version": "1",
  "verdicts": [
    { "review_key": "92b796688261e748", "verdict": "equivalent", "note": "percent is never negative here" }
  ]
}
```

The `review_key` is the `mutant_id`. A `survived`, `no_coverage` or `flaky` mutant becomes `equivalent` and leaves the score. A verdict for a `killed`, `timeout` or `compile_error` mutant is `contradicted`. An invalid document exits with code 2 before a test runs.

## Output

```text
Mutation testing (ran the project tests)
Scope: all source files
Score 58.3%  killed 7  survived 5  timeout 0  complete
Coverage 92.3%  no coverage 1

● Survived (5)
  src/pricing.js
    #1 2:7  applyDiscount  negate-condition  if (percent <= 0) { -> if (false) {
      id 92b796688261e748
      covered by 1 test: test/pricing.test.js::applies a discount
    #3 2:15  applyDiscount  relational-operator  if (percent <= 0) { -> if (percent < 0) {
      id d73be05a845d2f5c
      covered by 1 test: test/pricing.test.js::applies a discount

● No coverage (1): no test reaches these mutants
  src/pricing.js  1 mutant  test reach: 1 direct

Next
  Inspect a survivor (runs no code): fallow mutation inspect 92b796688261e748
```

- `Score` is the share of the tested mutants that a test detects. `Coverage` is the share of the planned mutants that a test reaches. The last word of the `Score` line is the completion: `complete` or `partial`.
- Each survivor gives its line and column, its function, its operator, the line before and after the change, its id and its covering tests.
- `No coverage` counts the mutants that no test reaches, with the reason from the module graph.

Each run saves its report to `.fallow/mutation/last-report.json`. `inspect`, `tasks`, `export` and `--recheck` read this file by default.

### Statuses {#statuses}

| Status | Meaning | In the score |
|:--|:--|:--|
| `killed` | A covering test failed. | yes |
| `timeout` | The run passed its time limit, also in a second run. It counts as detected. | yes |
| `survived` | Each covering test passed, also in a second run. | yes |
| `no_coverage` | No test reaches the mutant. | no |
| `runtime_error` | The runner failed for a reason outside the tests. | no |
| `flaky` | The second run gave another result. | no |
| `compile_error` | The mutant survived, but adds a type error. Only `--typecheck` sets it. | no |
| `not_killed_by_target` | No target test of `--kill-matrix-for` kills the mutant. | no |
| `pending` | The mutant did not run: a limit or the time budget ended first. | no |
| `equivalent` | A verdict marks the mutant as equivalent. | no |
| `pruned` | A static rule removed the mutant, with a reason such as `side-effect-sink` or `dead-code`. | no |

The score is `(killed + timeout) / (killed + timeout + survived)`. A run without a tested mutant has no score.

### JSON output {#json-output}

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"mutation"`. `--plan` gives `"mutation-plan"`, `inspect` gives `"mutation-inspect"`, and `tasks` gives `"mutation-tasks"`. |
| `schema_version`, `version`, `elapsed_ms` | The version of this output format, the fallow version and the run time. |
| `completion` | `complete` or `partial`, with the reasons. |
| `scope`, `runner` | The selected code, and the runner with its version. |
| `summary` | `counts` for each status, `score` and `coverage` as fractions from 0 to 1, and `sampled_out`. |
| `mutants` | One object for each mutant: `mutant_id`, `file`, `line`, `column`, `operator`, `function`, `change` (`from` and `to`), `status`, `covering_tests`, `killing_tests`, `retried`. Each mutant also has `rank`, `span`, `function_line`, `duration_ms` and `cached`. A `no_coverage` mutant has `test_reach`. |
| `functions` | The counts and the score of each function. |
| `kill_matrix` | The evidence of `--kill-matrix`: `status`, `reasons`, `tests`, `candidates`. Without the option, `status` is `unavailable`. |
| `cache` | `hits` and `stored` of the result cache. |
| `worktree` | The paths that the tests changed. |
| `errors`, `baseline_failures` | The errors of the run, and the tests that fail without a mutant. |
| `typecheck`, `resume`, `recheck`, `verdicts` | The result of `--typecheck`, `--resume`, `--recheck` and `--verdicts`. |
| `timings` | The time of each step. |
| `files` | Each mutated file with its SHA-256 digest at plan time. `inspect` compares the digest with the current file. |
| `skipped_files`, `unloaded_paths`, `unmatched_paths`, `no_test_files` | The selected files without mutants, the files that the runner never loaded, the path arguments that select no file, and `true` when the project has no test files. |

`--min-score` uses a percentage. `summary.score` is a fraction. The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The plan, the run or the subcommand completed. Survivors do not change the exit code. |
| `1` | `--min-score` or `mutation.minScore` is set, and the score is lower. |
| `2` | Invalid input or an execution error, for example a dirty worktree without `--allow-dirty`, an unsupported runner version, an invalid verdict document, or a `--resume` journal of other inputs. |

[Exit codes](/reference/exit-codes) has the meaning of each code.

## Examples

```bash
# Show the plan of the changed code, and run nothing
fallow mutation --plan

# Mutate the code that changed since main
fallow mutation --changed-since main

# Mutate one directory, and stop after 10 minutes
fallow mutation src/billing --time-budget 10m

# Fail when the score is lower than 80 percent
fallow mutation --all --min-score 80

# List the open tasks, write tests, then run the open tasks again
fallow mutation tasks
fallow mutation --recheck

# Find the tests that kill no mutant that other tests do not kill
fallow mutation --all --kill-matrix --format json --quiet
```
