Propose a [config file](/configuration/overview) for the project, with the reason for each setting. The command writes nothing.

For a first setup of fallow in a project, read [Adopt fallow](/guides/adopt).

## Synopsis

{/* generated:start cli-synopsis recommend */}

```bash
fallow recommend [OPTIONS]
```

{/* generated:end */}

## Options

This command has no options of its own. It reads the config file that `--config` names, or the config file that it finds, and takes it into account.

## Output

```bash
fallow recommend
```

```text
Detected frameworks: none detected

Proposed config (a safe starting point):
{
  "$schema": "https://raw.githubusercontent.com/fallow-rs/fallow/main/schema.json",
  "entry": [
    "src/index.{ts,tsx,js,jsx}",
    "src/main.{ts,tsx,js,jsx}"
  ]
}

Ask the user these 2 taste question(s):
  - Should the cleanup rules that default to warn (unused dev/optional dependencies, component-level dead code, styling drift) fail CI, or stay advisory?
  - Enable the opt-in private-type-leak check, which flags exported signatures that reference a same-file private type (a break for consumers)?

Zero config is a valid stop: fallow's defaults are strong, so writing no config is fully supported.
```

The output gives the detected frameworks, the proposed config, and the questions that only the user can answer. Each setting is one decision in one of three tiers:

| Tier | Meaning |
|:--|:--|
| `auto` | Fallow decided it from the detected project, for example the entry patterns. |
| `default` | A default that you can change, or an optional feature. It changes the proposed config only when the config holds its setting. |
| `taste` | A choice for the user. It has an open question with options. |

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"recommendation"` |
| `schema_version` | The version of this output format. |
| `detected` | The project shape: `is_monorepo`, `workspace_tool`, `workspace_patterns`, `has_typescript`, `test_framework`, `test_framework_ambiguous`, `ui_framework`, `frameworks_present`, `heterogeneous_frameworks`, `has_storybook`, `package_manager`. |
| `proposed_config` | The config that the `auto` decisions give. |
| `decisions` | One object for each decision: `setting`, `value`, `rationale`, `kind` (the tier), and `question` for a `taste` decision. |
| `note` | How to use the result. |
| `config_schema_command` | The command that prints each valid config key. |

A `question` has a `header`, the `question` text and `options`, each with a `label` and a `description`. `package_manager` comes only from the `packageManager` field of `package.json`. The [JSON output reference](/reference/json-output) has each field.

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | Fallow printed the proposal. |
| `2` | Invalid input, for example a config file that does not parse. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Show the proposal
fallow recommend

# Get the proposal and each decision as JSON
fallow recommend --format json --quiet

# List only the questions for the user
fallow recommend --format json --quiet | jq '.decisions[] | select(.kind == "taste") | .question'
```
