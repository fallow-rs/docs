Get a config proposal for your project, with the reasons for each setting, before anything is written. `fallow recommend` examines the frameworks, workspace layout, and tooling of the project. It writes nothing, and it reports:

- what it **detected**
- a safe **proposed config**
- the **decisions** behind that proposal

A person or an agent can thus review the reasons, and does not have to trust a generated file.

<Info>
  Zero config is a valid end state. The fallow defaults are strong, and fallow fully supports a project with no config. `recommend` is for projects that want a config, and for agents that must write the config with the user and not guess.
</Info>

```bash
fallow recommend
fallow recommend --format json
```

[`fallow init`](/cli/init) writes a config file. `recommend` is read-only. An agent uses it in these steps:

1. Run `recommend --format json`.
2. Apply the `auto` decisions.
3. Tell the user about the `default` decisions.
4. Ask the user about the `taste` decisions.
5. Write the result, or run `init`.

When fallow detects TypeScript, the default decisions point to optional type-aware analysis. They do not add it to `proposed_config`.

## Decision tiers

Each proposed setting has a tier and a rationale:

| Tier | Meaning |
|:-----|:--------|
| `auto` | Comes from detection, for example a detected framework, workspace layout, or test runner. Safe to apply as it is. |
| `default` | A default that fallow tells you about and that you can override, or an optional capability. It changes `proposed_config` only when the proposed config contains its setting. |
| `taste` | A subjective choice. Fallow shows it as an open `question` for the user, and does not decide it silently. |

## Options

`fallow recommend` has no flags of its own. If you pass an existing config with
`--config`, the command reads it and takes it into account. [Global flags](/cli/global-flags) such as `--root`,
`--format`, `--quiet`, `--no-cache`, and `--threads` apply.

## JSON output

```json
{
  "kind": "recommendation",
  "schema_version": "1",
  "detected": {
    "has_typescript": true,
    "is_monorepo": false,
    "package_manager": "npm",
    "ui_framework": null,
    "test_framework": "vitest"
  },
  "proposed_config": {
    "$schema": "https://raw.githubusercontent.com/fallow-rs/fallow/main/schema.json",
    "entry": ["src/index.{ts,tsx,js,jsx}", "src/main.{ts,tsx,js,jsx}"]
  },
  "decisions": [
    {
      "setting": "entry",
      "value": ["src/index.{ts,tsx,js,jsx}", "src/main.{ts,tsx,js,jsx}"],
      "rationale": "Assumes the src/index or src/main entry convention. Adjust for framework-routed apps or DI-wired entry points (fallow also auto-honors package.json exports/main/module for libraries).",
      "kind": "auto",
      "question": null
    },
    {
      "setting": "typeAware.enabled",
      "value": null,
      "rationale": "Detected TypeScript. Run fallow dead-code --type-aware or set typeAware.enabled to true when cleanup depends on exact TypeScript identity. This starts a slower semantic pass and does not replace tsc or Oxlint. Guide: https://docs.fallow.tools/analysis/type-aware",
      "kind": "default",
      "question": null
    }
  ],
  "note": "proposed_config is the safe, detection-derived baseline; resolve every taste decision with the user before finalizing. For the full set of valid config keys and their shapes, run `fallow config-schema`. Zero config is a valid stop.",
  "config_schema_command": "fallow config-schema"
}
```

The `detected` block also reports the monorepo workspace patterns, the workspace tool, Storybook presence, and if frameworks are in workspace packages and not in the root.
