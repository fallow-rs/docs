Show if each external [plugin](/concepts/plugins) is active, and what each `manifestEntries` rule matched and added as entry points. The command runs no full analysis and writes nothing.

For how to write a plugin, read [Custom plugins](/guides/custom-plugins).

## Synopsis

{/* generated:start cli-synopsis plugin-check */}

```bash
fallow plugin-check [OPTIONS]
```

{/* generated:end */}

## Options

This command has no options of its own. Fallow reads the plugins of the `plugins` config key, of `.fallow/plugins/`, and the `fallow-plugin-*` files in the project root. The command refuses `--ci`, `--fail-on-issues`, `--sarif-file` and `--output-file`.

## Output

```bash
fallow plugin-check
```

```text
plugin 'acme': INACTIVE (no enabler present; requires one of these dependencies: @acme/core)
plugin 'jobs': rule 'svc/**/service.json' matched 1 manifest(s), seeded 2 entry pattern(s), 0 warning(s)

0 warnings.
```

An inactive plugin shows the condition that is not met. An active plugin shows one line for each `manifestEntries` rule: the number of manifests that the rule matched, the number of entry patterns that it added, and the number of warnings.

With `--format json`, the output has these top-level fields:

| Field | Content |
|:--|:--|
| `kind` | `"plugin-check"` |
| `schema_version` | The version of this output format. |
| `note` | How to read `path_exists`. |
| `plugins` | One object for each plugin: `name`, `active`, and `activation_requirement` for an inactive plugin, or `manifest_rules` for an active plugin. |

Each item of `manifest_rules` has `manifests` (the glob), `manifests_matched`, `matched` and `warnings`. Each item of `matched` has the manifest `path`, `when_passed`, and `seeded` with a `path` and `path_exists` for each entry. `path_exists: false` means that the entry is broken. `path_exists: true` does not prove that fallow reaches the entry, because discovery still skips gitignored files. The output is sorted, so the same project gives the same bytes. The [JSON output reference](/reference/json-output) has each field.

Each warning has a `kind`:

| `kind` | Cause |
|:--|:--|
| `manifests-matched-none` | The `manifests` glob matched no file. |
| `when-excluded-all` | The `when` condition excluded each matched manifest. |
| `field-path-unresolved` | A `${field}` path resolved in no manifest. |
| `entries-empty` | The rule has no `entries`. |
| `manifest-parse-failed` | Fallow cannot read or parse a matched manifest. |
| `field-values-limit-exceeded` | A field path gave more than 1,024 values in one manifest. |
| `entry-expansion-limit-exceeded` | An entry gave more than 4,096 paths for one manifest. |
| `entry-outside-root` | An entry resolved outside the project root. Fallow skipped it. |
| `seeded-paths-missing` | No added entry exists on disk. |

## Exit codes

| Code | Meaning |
|:--|:--|
| `0` | The check completed, also with warnings or inactive plugins. |
| `2` | Invalid input, for example `--fail-on-issues`. |

See [Exit codes](/reference/exit-codes).

## Examples

```bash
# Check the plugins of the project
fallow plugin-check

# Save the result as a snapshot to compare in CI
fallow plugin-check --format json --quiet > plugin-check.json

# Check the plugins of one workspace package
fallow plugin-check --root packages/app
```
