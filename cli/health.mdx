`fallow health` reports the functions above the complexity thresholds, the health of each file, the hotspots, the refactoring targets and the [health score](/analysis/health).

For the concepts and the workflow, read [Health](/analysis/health).

## Synopsis

{/* generated:start cli-synopsis health */}

```bash
fallow health [OPTIONS] [PATH]
```

## Option details {#option-details}

### Section selection {#section-selection}

Without a section option, the run shows the health score, the complexity findings, the file scores, the hotspots and the refactoring targets. A section option shows only its section: `--complexity`, `--file-scores`, `--hotspots`, `--targets`, `--score`, `--coverage-gaps`. You can give more than one. `--ownership` implies `--hotspots`, and `--effort` implies `--targets`.

- `--hotspots` and `--ownership` need git history, or a `--churn-file`. Outside a git repository, the section is empty and the run continues.
- `--score` alone does not read the git history, so the score has no hotspot penalty. Add `--hotspots` for the penalty.
- `--coverage-gaps` and `--type-coupling` are opt-in. `--type-coupling` needs `--type-aware`.
- Fallow takes the coverage path from `--coverage`, else from `FALLOW_COVERAGE`, else from `health.coverage`. When none is set, fallow reads `coverage/coverage-final.json` when it exists, else it estimates the CRAP score. `--coverage-root` follows the same order with `FALLOW_COVERAGE_ROOT` and `health.coverageRoot`, and must be an absolute path.
- `--coverage` reads an Istanbul coverage map (`coverage-final.json`), a directory that holds one, a raw V8 coverage directory, or one V8 coverage JSON file. It does not read LCOV: with `lcov.info`, the run stops with `failed to parse coverage data` and exits with code 2. Add the `json` reporter to the test runner, and pass `coverage-final.json`.

### Option values {#option-values}

| Option | Values |
|:--|:--|
| `--sort` | `cyclomatic` (default), `cognitive`, `lines`, `severity`. Equal findings sort by path, line, column and name. |
| `--min-severity`, `--effort` | `moderate`, `high`, `critical` for `--min-severity`. `low`, `medium`, `high` for `--effort`. |
| `--ownership-emails` | `handle` (default): the local part of the email. `anonymized`: an `xxh3:<16 hex>` name, which is not a cryptographic hash. `raw`: the full email. `hash` is an old name of `anonymized`. |
| `--since` | A duration (`6m`, `90d`, `1y`, `2w`) or a date (`2025-06-01`). The default is `6m`. |
| `--baseline-mode` | `count` (default): match per file and category. `identity`: match per file and function name, only with a baseline that you saved with `--baseline-mode identity`. |

### Scope of the score {#scoping}

`--workspace` and a path argument compute the score, the vital signs and the file scores again for the files in scope. `--group-by` adds a `groups` array: each group has its own `vital_signs`, `health_score`, `findings`, `file_scores`, `hotspots` and `targets`. The top-level fields stay project-wide. `--group` keeps only the groups that match.

### Baseline {#baseline}

`--save-baseline` saves the complexity findings with `"kind": "health"`. `--baseline` hides the findings in the file. A baseline applies only to complexity findings, not to file scores. The result of the comparison is in `summary.baseline_staleness`.

### Mutation report {#mutation-report}

`--mutation-report <FILE>` reads a saved [`fallow mutation`](/cli/mutation) JSON report, and shows the mutation score of each complexity finding below its CRAP score. The run starts no test. A function whose file changed since the mutation run shows `stale` and no score. The mutation score does not change the CRAP score, the health score or a gate. A plan document, a missing file or an invalid file exits with code 2.

### Degraded inputs {#degraded-inputs}

An input that fallow cannot read gives zeros, for example a project without git or an unreadable snapshot. To tell a measured zero from a missing measurement, read `workspace_diagnostics`: an entry with `degrades_analysis: true` marks a missing input. Select on that field, and not on a list of kinds.

### Health score {#health-score-formula}

The score starts at 100. Fallow subtracts each penalty in `health_score.penalties`, rounds to one decimal, and keeps the result between 0 and 100. A penalty of an analysis that did not run is `null` and subtracts nothing.

| Penalty | Formula | Maximum |
|:--|:--|:--|
| `dead_files` | `dead_file_pct` × 0.2 | 15 |
| `dead_exports` | `dead_export_pct` × 0.2 | 15 |
| `complexity` | `critical_complexity_pct` × 4 | 20 |
| `p90_complexity` | (`p90_cyclomatic` − 10), only when `critical_complexity_pct` is absent | 10 |
| `maintainability` | `maintainability_low_pct` × 1.5 | 15 |
| `hotspots` | `hotspot_count` ÷ (1 percent of the files, at least 1) × 10 | 10 |
| `unused_deps` | `unused_deps_per_k_files` × 0.5 | 25 |
| `circular_deps` | `circular_deps_per_k_files` × 0.5 | 25 |
| `unit_size` | `functions_over_60_loc_per_k` × 0.5 | 10 |
| `coupling` | `coupling_high_pct` × 0.5 | 5 |
| `duplication` | `duplication_pct` − 5 | 10 |
| `prop_drilling` | 1 for each prop-drilling chain, only with the `prop-drilling` rule | 5 |

The grade is `A` for a score of 85 or more, `B` for 70, `C` for 55, `D` for 40 and `F` below 40. `formula_version` is `3`.

### Maintainability index {#maintainability-index-formula}

`maintainability_index` of a file is:

```text
MI = 100 − complexity_density × 30 × min(lines ÷ 50, 1) − dead_code_ratio × 20 − min(ln(fan_out + 1) × 4, 15)
```

- `complexity_density` is the sum of the cyclomatic complexity of the file divided by its lines.
- `dead_code_ratio` is the share of the value exports that nothing uses. It is 1 for an unused file, and 0 for a file without value exports.
- Fallow keeps the result between 0 and 100.

### CRAP {#crap-formula}

```text
CRAP = CC² × (1 − coverage)³ + CC
```

`CC` is the cyclomatic complexity of the function. With a coverage file, `coverage` is the measured coverage of the function (`coverage_model` `istanbul`). Without one, fallow estimates it (`coverage_model` `static_estimated`): 85 percent for a function that a test imports, 40 percent for another function in a file that a test reaches, and 0 for a function that no test reaches.

### Refactoring targets {#refactoring-targets}

```text
priority = min(complexity_density, 1) × 30 + hotspot_score ÷ 100 × 25 + dead_code_ratio × 20 + min(fan_in ÷ fan_in_p95, 1) × 15 + min(fan_out ÷ fan_out_p95, 1) × 10
efficiency = priority ÷ effort
```

`effort` is 1 for `low`, 2 for `medium` and 3 for `high`. The targets are sorted by `efficiency`, highest first.

- `high` effort: 500 lines or more, a fan-in of `fan_in_p95` or more, or 15 functions or more with a complexity density above 0.5.
- `low` effort: fewer than 100 lines, 3 functions or fewer, and a fan-in below the 25th percentile (at least 2).
- `medium` effort: each other file.

`target_thresholds` holds the percentiles of the project: `fan_in_p95` (at least 5), `fan_in_p75` (at least 3), `fan_out_p95` (at least 8) and `fan_out_p90` (at least 5).

| `category` | `confidence` |
|:--|:--|
| `urgent_churn_complexity` | `low` |
| `break_circular_dependency` | `high` |
| `split_high_impact` | `medium` |
| `remove_dead_code` | `high` |
| `extract_complex_functions` | `high` |
| `extract_dependencies` | `medium` |
| `add_test_coverage` | `high` |
| `resolve_hidden_coupling` | `medium` |

### Hotspots {#hotspots}

The hotspot `score` is the weighted commits of the file divided by the largest weighted commits, times its complexity density divided by the largest complexity density, times 100. Each hotspot has `path`, `score` (0 to 100), `commits`, `weighted_commits` (with a half-life of 90 days), `lines_added`, `lines_deleted`, `complexity_density`, `fan_in`, `trend` (`Accelerating` when the newer half of the window has more than 1.5 times the commits of the older half, `Cooling` below 0.67 times, else `Stable`) and `is_test_path`. `hotspot_summary` has `since`, `min_commits`, `files_analyzed`, `files_excluded` and `shallow_clone`.

With `--ownership`, each hotspot also has these fields:

| Field | Content |
|:--|:--|
| `bus_factor` | The smallest number of authors that made half of the weighted commits. |
| `contributor_count` | The number of authors, without bots. |
| `top_contributor`, `recent_contributors` | The authors with the largest share: `identifier`, `format`, `share`, `stale_days`, `commits`. |
| `suggested_reviewers` | The recent contributors that committed in the last 90 days. |
| `declared_owner`, `unowned` | The owner in `CODEOWNERS`. `unowned` is `null` when the project has no `CODEOWNERS` file. |
| `ownership_state` | `active`, `unowned`, `declared_inactive` or `drifting`. |
| `drift`, `drift_reason` | `true` when the first author has less than 10 percent of the weighted commits of a file that is 30 days old or older. |

The `actions` of a hotspot can then have `low-bus-factor`, `unowned-hotspot` and `ownership-drift`. The [`health.ownership`](/reference/config-health#health-ownership) config key sets the bot patterns and the email mode.

### Snapshot file {#snapshots}

`--save-snapshot` writes `.fallow/snapshots/<timestamp>.json`, or the path that you give. `--trend` reads the newest file in that directory, and `--trend-from` reads one file. A snapshot has these fields:

| Field | Content |
|:--|:--|
| `snapshot_schema_version` | The version of this file format. |
| `version`, `timestamp`, `git_sha`, `git_branch`, `shallow_clone` | The fallow version, the time and the git state of the run. |
| `vital_signs`, `counts` | The [vital signs](#vital-signs) and the numbers behind them. |
| `score`, `grade`, `score_formula_version` | The health score. A trend compares scores only when the formula versions match. |
| `coverage_model` | The source of the CRAP coverage. |
| `groups` | The metrics of each group, when the run used `--group-by`. |
| `analysis_identity` | The mode of the analysis, for example `syntactic`, and its completeness. |

### Churn file {#importing-churn-from-a-non-git-vcs}

`--churn-file <PATH>` reads the change history from a JSON file, for a project without git. The file feeds `--hotspots`, `--ownership` and `--targets`. When the project also has git, the file wins.

```json
// churn.json
{
  "schema": "fallow-churn/v1",
  "events": [
    { "path": "src/foo.ts", "timestamp": 1717459200, "author": "dev@corp", "added": 10, "deleted": 5 }
  ]
}
```

| Field | Required | Content |
|:--|:--|:--|
| `path` | yes | The path from the repository root, with forward slashes. |
| `timestamp` | yes | The commit time in Unix seconds, UTC. A time more than one year in the future exits with code 2. |
| `author` | no | One stable identity for each person, for example the email. Fallow does not apply a mailmap. |
| `added`, `deleted` | yes | The changed lines. The hotspot score counts events, so the line counts are only for display. |

Give one event for each commit and file. Leave out merge commits and binary files. Give a renamed file under its new path only. Fallow ignores other fields.

## Exit codes

| Run | Exit code `0` when | Exit code `1` when |
|:--|:--|:--|
| `fallow health` | no finding has a `complexity-*` rule at `error` | a finding has a rule at `error`, which is the default |
| `--fail-on-issues` | the run has no finding | the run has a finding, also with a rule at `warn` |
| `--min-score N` | the score is `N` or higher | the score is lower than `N` |
| `--min-severity LEVEL` | no finding is at `LEVEL` or higher | a finding is at `LEVEL` or higher |
| `--report-only` | always | never |

With `--min-score` and `--min-severity` together, the run fails when one of them fails. With `--min-score` alone, the findings do not set the exit code. `--report-only` together with `--min-score` or `--min-severity` exits with code 2.

| Code | Meaning |
|:--|:--|
| `2` | Invalid input, for example an invalid `--mutation-report` file or `--trend-from` file. |
| `3` to `6` | With `--runtime-coverage`: the license is not valid, or the runtime coverage step failed. |

[Exit codes](/reference/exit-codes) has the meaning of each code.

## Examples

```bash
# Report the functions above the thresholds
fallow health

# Show only the 10 most complex functions, sorted by cognitive complexity
fallow health --complexity --top 10 --sort cognitive

# Use measured coverage for the CRAP scores
fallow health --coverage coverage/coverage-final.json

# Show the hotspots of the last 3 months, with their owners
fallow health --hotspots --ownership --since 3m

# Fail when the health score is lower than 70
fallow health --min-score 70

# Show the results without a failure
fallow health --report-only

# Save a snapshot, then compare a later run with it
fallow health --save-snapshot
fallow health --trend
```
